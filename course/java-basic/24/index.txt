<h3 id="项目坐标groupId-artifactId-version">项目坐标（groupId, artifactId, version）</h3>
<p>项目坐标是 Maven 仓库中唯一标识一个构件的三元组，类似于数据库中的复合主键。</p>
<table>
<thead>
<tr>
<th>元素</th>
<th>说明</th>
<th>示例</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>groupId</code></td>
<td>组织或公司的域名反写，用于分组</td>
<td><code>com.example</code>、<code>org.apache</code></td>
</tr>
<tr>
<td><code>artifactId</code></td>
<td>项目本身的唯一标识符</td>
<td><code>my-app</code>、<code>httpclient</code></td>
</tr>
<tr>
<td><code>version</code></td>
<td>项目的版本号</td>
<td><code>1.0-SNAPSHOT</code>、<code>4.5.13</code></td>
</tr>
</tbody>
</table>
<h3 id="packaging-类型">packaging 类型</h3>
<p><code>&lt;packaging&gt;</code> 定义项目的打包方式，常见值：</p>
<ul>
<li><code>jar</code>：默认，打包为 Java 归档文件</li>
<li><code>war</code>：打包为 Web 应用归档文件（用于部署到 Servlet 容器）</li>
<li><code>pom</code>：仅用于父模块（不包含代码，只做依赖管理和聚合）</li>
</ul>
<h3 id="parent-元素继承">parent 元素（继承）</h3>
<p><code>&lt;parent&gt;</code> 用于声明父 POM，子项目可以继承父项目的配置（如依赖版本、插件配置等），实现配置复用。</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;parent&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>org.springframework.boot<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-boot-starter-parent<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>2.7.0<span class="nt">&lt;/version&gt;</span>
<span class="w">    </span><span class="nt">&lt;relativePath/&gt;</span><span class="w"> </span><span class="cm">&lt;!-- 从本地仓库查找，若省略则从远程仓库查找 --&gt;</span>
<span class="nt">&lt;/parent&gt;</span>
</code></pre></div>

<h3 id="properties-元素属性">properties 元素（属性）</h3>
<p><code>&lt;properties&gt;</code> 用于定义可重用的变量，常用于统一版本号、指定编码等：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;properties&gt;</span>
<span class="w">    </span><span class="nt">&lt;java.version&gt;</span>11<span class="nt">&lt;/java.version&gt;</span>

<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;version&gt;</span>${jackson.version}<span class="nt">&lt;/version&gt;</span>
</code></pre></div>

<h2 id="依赖管理Dependency-Management">依赖管理（Dependency Management）</h2>
<h3 id="依赖声明结构">依赖声明结构</h3>
<p>一个完整的依赖声明由三要素组成（坐标）：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>org.apache.httpcomponents<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>httpclient<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>4.5.13<span class="nt">&lt;/version&gt;</span>


<span class="w">    </span><span class="nt">&lt;scope&gt;</span>compile<span class="nt">&lt;/scope&gt;</span><span class="w">   </span><span class="cm">&lt;!-- 可选，默认 compile --&gt;</span>

<span class="w">    </span><span class="nt">&lt;optional&gt;</span>false<span class="nt">&lt;/optional&gt;</span>

<span class="w">    </span><span class="nt">&lt;exclusions&gt;</span>
<span class="w">        </span><span class="cm">&lt;!-- 排除传递依赖 --&gt;</span>
<span class="w">    </span><span class="nt">&lt;/exclusions&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<h3 id="依赖范围scope">依赖范围（scope）</h3>
<p><code>&lt;scope&gt;</code> 控制依赖在哪些构建阶段中被包含，分为以下 5 种：</p>
<table>
<thead>
<tr>
<th>scope</th>
<th>编译时</th>
<th>测试时</th>
<th>运行时</th>
<th>打包时</th>
<th>示例</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>compile</code>（默认）</td>
<td>✅</td>
<td>✅</td>
<td>✅</td>
<td>✅</td>
<td>Apache HttpClient</td>
</tr>
<tr>
<td><code>provided</code></td>
<td>✅</td>
<td>✅</td>
<td>❌</td>
<td>❌</td>
<td>Servlet API（容器已提供）</td>
</tr>
<tr>
<td><code>runtime</code></td>
<td>❌</td>
<td>✅</td>
<td>✅</td>
<td>✅</td>
<td>JDBC 驱动</td>
</tr>
<tr>
<td><code>test</code></td>
<td>❌</td>
<td>✅</td>
<td>❌</td>
<td>❌</td>
<td>JUnit</td>
</tr>
<tr>
<td><code>system</code></td>
<td>✅</td>
<td>✅</td>
<td>❌</td>
<td>❌</td>
<td>本地 JAR（不推荐，需指定路径）</td>
</tr>
</tbody>

<p><strong>典型场景：</strong></p>
<ul>
<li><strong>test</strong>：仅测试阶段使用，不会被打入最终 JAR。</li>
<li><strong>provided</strong>：编译和测试时需要，但运行时由容器提供（如 Tomcat 的 <code>servlet-api</code>）。</li>
<li><strong>runtime</strong>：编译时不需要，运行时需要（如数据库驱动）。</li>
</ul>
<h3 id="传递性依赖Transitive-Dependency">传递性依赖（Transitive Dependency）</h3>
<p>Maven 会自动解析并引入依赖所依赖的其他 JAR 包（传递依赖），无需手动添加。</p>
<p><strong>示例：</strong> 我们在项目中声明了 <code>httpclient</code>，而 <code>httpclient</code> 本身依赖 <code>httpcore</code> 和 <code>commons-logging</code>。Maven 会自动下载并引入这两个传递依赖。</p>
<p><strong>传递依赖带来的好处：</strong> 大大减少了人工工作量，避免遗漏依赖。</p>
<p><strong>传递依赖带来的问题：</strong> 可能引入版本冲突（不同路径引入同一依赖的不同版本）。</p>
<h3 id="依赖冲突与版本仲裁">依赖冲突与版本仲裁</h3>
<p>当多个传递依赖路径引入了同一个依赖的不同版本时，Maven 会进行版本仲裁，规则如下：</p>
<ol>
<li><strong>最短路径优先</strong>：路径最短的依赖版本被选中。</li>
<li><strong>第一声明优先</strong>：若路径长度相同，则先声明的依赖版本被选中。</li>
</ol>
<p><strong>示例：</strong></p>
<ul>
<li>项目 A 直接依赖了 <code>jackson-databind:2.12.0</code></li>
<li>项目 A 又依赖了 B，而 B 依赖了 <code>jackson-databind:2.10.0</code></li>
<li>那么 2.12.0 会被选中（因为直接依赖路径最短）。</li>
</ul>
<h3 id="查看依赖树">查看依赖树</h3>
<p>使用 <code>mvn dependency:tree</code> 可以查看完整的依赖树，便于排查冲突：</p>
<div class="codehilite"><pre><span></span><code>mvn dependency:tree
</code></pre></div>

<div class="codehilite"><pre><span></span><code>[INFO] com.example:my-app:jar:1.0-SNAPSHOT

<p>如果不想引入某个传递依赖，可以使用 <code>&lt;exclusions&gt;</code> 排除：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>

<h3 id="dependencyManagement-统一管理版本">dependencyManagement 统一管理版本</h3>
<p>在父 POM 中使用 <code>&lt;dependencyManagement&gt;</code>，可以统一管理子模块的依赖版本，但不会实际引入依赖，子模块只需声明 <code>groupId</code> 和 <code>artifactId</code>，版本从父继承。</p>
<p><strong>父 POM：</strong></p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependencyManagement&gt;</span>

<span class="w">            </span><span class="nt">&lt;version&gt;</span>2.13.0<span class="nt">&lt;/version&gt;</span>
<span class="w">        </span><span class="nt">&lt;/dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;/dependencies&gt;</span>
<span class="nt">&lt;/dependencyManagement&gt;</span>
</code></pre></div>

<p><strong>子模块：</strong> 只需声明，无需指定版本：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.fasterxml.jackson.core<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>jackson-databind<span class="nt">&lt;/artifactId&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<h2 id="版本管理策略">版本管理策略</h2>
<h3 id="使用属性管理版本">使用属性管理版本</h3>
<p>将所有依赖版本集中定义在 <code>&lt;properties&gt;</code> 中，便于统一升级：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;properties&gt;</span>
<span class="w">    </span><span class="nt">&lt;jackson.version&gt;</span>2.13.0<span class="nt">&lt;/jackson.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;httpclient.version&gt;</span>4.5.13<span class="nt">&lt;/httpclient.version&gt;</span>
<span class="nt">&lt;/properties&gt;</span>
...
<span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.fasterxml.jackson.core<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>jackson-databind<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>${jackson.version}<span class="nt">&lt;/version&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<h3 id="SNAPSHOT-版本">SNAPSHOT 版本</h3>
<ul>
<li><strong>SNAPSHOT</strong> 表示“开发中的版本”，Maven 不会缓存 SNAPSHOT 版本，每次都会去仓库检查更新。</li>
<li><strong>RELEASE</strong> 表示“正式发布版本”，会被缓存，除非强制更新。</li>
<li><strong>版本号规范</strong>：一般使用 <code>x.y.z-SNAPSHOT</code>（如 <code>1.0.0-SNAPSHOT</code>），正式版去 <code>-SNAPSHOT</code>。</li>
</ul>
<h2 id="实践示例将上节课的手工项目转为-Maven-项目">实践示例：将上节课的手工项目转为 Maven 项目</h2>
<p>让我们将第 1 课中的 <code>GithubApiClient</code> 手工项目转换为 Maven 项目，只需在 <code>pom.xml</code> 中添加以下依赖：</p>
<div class="codehilite"><pre><span></span><code>&lt;dependencies&gt;
    &lt;!-- Apache HttpClient --&gt;
    &lt;dependency&gt;
        &lt;groupId&gt;org.apache.httpcomponents&lt;/groupId&gt;
        &lt;artifactId&gt;httpclient&lt;/artifactId&gt;
        &lt;version&gt;4.5.13&lt;/version&gt;
    &lt;/dependency&gt;

    &lt;!-- Jackson Databind（自动传递 jackson-core 和 annotations） --&gt;
    &lt;dependency&gt;
        &lt;groupId&gt;com.fasterxml.jackson.core&lt;/groupId&gt;
        &lt;artifactId&gt;jackson-databind&lt;/artifactId&gt;
        &lt;version&gt;2.13.0&lt;/version&gt;
    &lt;/dependency&gt;
&lt;/dependencies&gt;
</code></pre></div>

<p>执行 <code>mvn compile</code>，Maven 自动下载所有依赖（包括传递依赖），项目即可编译通过，无需手动下载任何 JAR 包。对比之前的手工过程，效率提升显著。</p>
