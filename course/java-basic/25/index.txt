</ul>

<h2 id="Maven-生命周期">Maven 生命周期</h2>
<h3 id="什么是生命周期">什么是生命周期</h3>
<p>Maven 的生命周期定义了项目构建的<strong>标准流程</strong>，它将整个构建过程划分为一系列<strong>阶段（Phase）</strong>。每个阶段按顺序执行，执行后面的阶段时，前面的所有阶段都会自动执行。</p>
<div class="codehilite"><pre><span></span><code>执行 mvn package 时：
validate → compile → test → package
（test 之前的阶段都会自动执行）
</code></pre></div>

<h3 id="三大生命周期">三大生命周期</h3>
<p>Maven定义了<strong>三套独立的生命周期</strong>，每套生命周期包含一组阶段：</p>
<table>
<thead>
<tr>
<th>生命周期</th>
<th>说明</th>
<th>核心用途</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>clean</strong></td>
<td>清理构建产物</td>
<td>删除target目录</td>
</tr>
<tr>
<td><strong>default</strong></td>
<td>构建项目（核心）</td>
<td>编译、测试、打包、部署</td>
</tr>
<tr>
<td><strong>site</strong></td>
<td>生成项目站点</td>
<td>生成文档和报告</td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]</p>
<p>这三套生命周期是相互独立的。执行 <code>mvn clean package</code> 时，会依次执行clean生命周期的阶段和default生命周期的阶段（从开始到package）。</p>
</blockquote>
<p>生命周期特点</p>
<ul>
<li><strong>顺序执行</strong>：阶段之间按固定顺序执行，前面的阶段完成后才执行后续阶段。</li>
<li><strong>前置条件</strong>：执行某个阶段时，所有前置阶段都会自动执行（如执行 <code>package</code> 会自动执行 <code>validate</code> → <code>compile</code> → <code>test</code> → <code>package</code>）。</li>
<li><strong>独立性</strong>：不同生命周期的阶段之间没有前置依赖关系。</li>
</ul>
<h3 id="clean-生命周期">clean 生命周期</h3>
<p>包含 3 个阶段：</p>
<table>
<thead>
<tr>

<th>说明</th>
</tr>
</thead>
<tbody>
<tr>

<td>清理前执行的操作（如备份）</td>
</tr>
<tr>
<td><code>clean</code></td>
<td>删除 <code>target/</code> 目录下的所有构建产物</td>
</tr>
<tr>
<td><code>post-clean</code></td>
<td>清理后执行的操作</td>
</tr>
</tbody>
</table>
<div class="codehilite"><pre><span></span><code>mvn clean
</code></pre></div>

<p><strong>常用场景：</strong></p>
<ul>
<li>重新构建前清理旧文件，确保全新构建</li>
<li>解决因缓存导致的构建问题</li>
</ul>
<blockquote>
<p>[!CAUTION]</p>
<p><code>mvn clean</code> 会删除 <code>target/</code> 目录下的所有文件，包括编译生成的 <code>.class</code> 文件和打包的 JAR/WAR 文件。</p>

<h4 id="validate验证">validate（验证）</h4>
<p>验证项目信息是否正确：POM文件语法正确、必要的配置完整等。</p>
<div class="codehilite"><pre><span></span><code>mvn validate
</code></pre></div>

<h4 id="compile编译">compile（编译）</h4>
<p>编译 <code>src/main/java</code> 下的Java源代码，将生成的 <code>.class</code> 文件输出到 <code>target/classes</code>。</p>
<div class="codehilite"><pre><span></span><code>mvn compile
</code></pre></div>

<p>执行后会生成：</p>
<div class="codehilite"><pre><span></span><code>target/
└── classes/
    └── com/example/
        └── App.class
</code></pre></div>

<h4 id="test测试">test（测试）</h4>
<p>执行 <code>src/test/java</code> 下的单元测试（使用JUnit等测试框架）。</p>
<div class="codehilite"><pre><span></span><code>mvn test
</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>测试失败会中断构建过程，阻止后续阶段执行。</p>
</blockquote>
<h4 id="package打包">package（打包）</h4>
<p>根据 <code>&lt;packaging&gt;</code> 类型生成对应的归档文件：</p>
<ul>
<li><code>jar</code> → <code>target/xxx-version.jar</code></li>
<li><code>war</code> → <code>target/xxx-version.war</code></li>
</ul>
<div class="codehilite"><pre><span></span><code>mvn package
</code></pre></div>

<h4 id="verify验证">verify（验证）</h4>
<p>验证打包后的文件是否符合质量要求（如集成测试、代码覆盖率检查）。</p>
<div class="codehilite"><pre><span></span><code>mvn verify
</code></pre></div>

<h4 id="install安装">install（安装）</h4>
<p>将打包后的 JAR/WAR 安装到本地Maven仓库（<code>~/.m2/repository</code>），供本机其他Maven项目使用。</p>
<div class="codehilite"><pre><span></span><code>mvn install
</code></pre></div>

<p>安装后在本地仓库的路径：</p>
<div class="codehilite"><pre><span></span><code>~/.m2/repository/com/example/my-app/1.0-SNAPSHOT/
├── my-app-1.0-SNAPSHOT.jar
├── my-app-1.0-SNAPSHOT.pom
└── ...
</code></pre></div>

<h4 id="deploy部署">deploy（部署）</h4>
<p>将打包后的文件部署到远程Maven仓库（如Nexus私服），供团队其他成员使用。</p>
<div class="codehilite"><pre><span></span><code>mvn deploy
</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>虽然阶段很多，但日常开发中最常用的是：<code>compile</code>、<code>test</code>、<code>package</code>、<code>install</code>、<code>deploy</code>。</p>
</blockquote>

<h2 id="Maven-插件体系">Maven 插件体系</h2>
<h3 id="插件与目标Plugin-Goal">插件与目标（Plugin &amp; Goal）</h3>
<ul>
<li><strong>插件（Plugin）</strong>：执行具体构建任务的工具包，例如 <code>maven-compiler-plugin</code>。</li>
<li><strong>目标（Goal）</strong>：插件中具体执行的操作单元，例如 <code>compile</code> 目标。</li>
</ul>
<p>调用格式：<code>mvn 插件前缀:目标</code>，如 <code>mvn compiler:compile</code>。
也可以直接绑定到生命周期阶段，通过 <code>mvn 阶段</code> 触发。</p>
<h3 id="插件分类">插件分类</h3>

<th>说明</th>
<th>示例</th>
</tr>
</thead>

<td>Maven 自带，默认绑定到生命周期阶段</td>
<td><code>compiler</code>、<code>surefire</code>、<code>jar</code>、<code>war</code>、<code>install</code>、<code>deploy</code></td>
</tr>
<tr>
<td><strong>标准插件</strong></td>
<td>Maven 官方维护，但不默认绑定</td>
<td><code>source</code>、<code>javadoc</code>、<code>dependency</code></td>
</tr>

</tr>
</tbody>
</table>

<h3 id="作业一命令执行顺序分析">作业一：命令执行顺序分析</h3>
<p>阅读以下场景，写出 Maven 实际会执行的阶段序列（包括 clean 和 default 生命周期）。</p>
<p><strong>场景1：</strong> <code>mvn test</code>
写出从 default 生命周期开始到 test 阶段结束，所有会被执行的阶段。</p>
<p><strong>场景2：</strong> <code>mvn clean package</code>
写出 clean 和 default 生命周期中所有会被执行的阶段（按实际执行顺序）。</p>
<p><strong>场景3：</strong> <code>mvn clean install -DskipTests</code>
写出实际执行的阶段，并说明 <code>-DskipTests</code> 对执行过程的影响。</p>
