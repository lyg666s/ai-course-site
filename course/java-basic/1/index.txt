<h4 id="知识体系的相通性触类旁通两个案例分析">知识体系的相通性（触类旁通）：两个案例分析</h4>
<h5 id="案例1响应式事件驱动">案例1：响应式/事件驱动</h5>
<ul>
<li>场景描述：</li>
</ul>
<p>你去网红奶茶店买奶茶。你点完单，店员给你一张小票（上面有取餐号），然后让你不用在柜台前死等，可以去旁边逛一逛。等到奶茶做好了，店员主动喊号，你听到号再去取。</p>
<div class="codehilite"><pre><span></span><code>前端（你的手机 / 网页）：
你在网页上点击“查询物流”按钮。前端不会让网页卡住干等，而是发起请求后，先让页面可以继续滚动。等后端把数据传回来了，前端触发一个回调事件，才去更新页面上的物流信息。

后端（Java 服务器）：
双十一大量下单，后端不会一个请求占用一个线程去死等数据库返回，而是把请求注册成一个“待办事件”。等数据库查完了，主动触发事件把结果扔回给前端。这个过程中，后端线程被释放出来去处理别的请求。
</code></pre></div>

<ul>
<li>两者的相通点：</li>
</ul>
<p>以前是“你主动去问”（轮询/同步阻塞），现在是“做好了通知你”（回调/事件驱动）。 前后端都在做同一件事：不浪费资源干等着，而是等事情做完了，通过“喊号”（事件）来通知对方。前端避免了页面卡死，后端避免了线程堆积。</p>
<h5 id="案例2代理拦截器">案例2：代理/拦截器</h5>
<ul>
<li>场景描述：</li>
</ul>
<p>你是公司老板（业务代码）。你不需要亲自订机票、筛选推销电话、安排会议室，这些事都由你的行政秘书（代理Proxy）在中间处理。所有找你的人（调用方）都先经过秘书，秘书觉得重要才转给你，你只管专心做核心决策，甚至不知道秘书帮你挡掉了多少杂事。</p>
<div class="codehilite"><pre><span></span><code>前端（Vue 的数据代理）：
你在代码里写 this.name = "小明"（你想改个数据）。但 Vue 在背后用“代理”拦截了这个赋值动作，它偷偷额外做了两件事：① 把页面上的文字自动更新成“小明”；② 把这次修改记录到日志里。而你作为开发者，根本不知道代理的存在，你以为只是在改变量。

后端（Spring 的 AOP 事务代理）：
你在 Java 里写 userService.saveUser()（你想保存一个用户）。但 Spring 在背后用“代理”拦截了这个方法调用，它偷偷额外做了两件事：① 在调用前开启数据库事务；② 在调用成功后提交事务（失败则回滚）。而你作为开发者，根本不知道代理的存在，你以为只是在调用一个普通保存方法。
</code></pre></div>

<ul>
<li>两者的相通点：</li>
</ul>
<p>核心逻辑不变（改数据 / 存用户），但前后端都在“核心操作”外面套了一个透明的“拦截层”。 这个拦截层可以在你不察觉的情况下，帮你把“附带工作”（更新界面、管理事务、打印日志、校验权限）给做了。这就像秘书帮你挡掉琐事，让你只专心干活。</p>
