从一个简单项目看传统依赖管理的痛点

假设我们使用 IntelliJ IDEA 创建一个简单的 Java 项目，需要实现一个功能：发送 HTTP 请求并解析返回的 JSON 数据。

我们不想自己写底层的网络和 JSON 解析代码，希望使用成熟的第三方库，比如：

  • Apache HttpClient：用于发送 HTTP 请求
  • Jackson：用于解析 JSON

项目结构如下：

simple-http-json-demo/
├── src/
│   └── com/demo/
│       └── GithubApiClient.java
├── lib/                         # 手动存放 JAR 包的目录
│   ├── httpclient-4.5.13.jar
│   ├── httpcore-4.4.13.jar
│   ├── commons-logging-1.2.jar
│   ├── jackson-databind-2.13.0.jar
│   ├── jackson-core-2.13.0.jar
│   └── jackson-annotations-2.13.0.jar
└── .idea/                       # IDEA 项目配置文件

在原生 Java 项目中（不使用任何构建工具），我们需要手动完成以下步骤：

  1. 下载 JAR 包：去 Apache 官网下载 httpclient-4.5.13.jar，去 Jackson 官网下载 jackson-databind-2.13.0.jar 以及它的所有依赖（如 jackson-core、jackson-annotations）。
依赖包名称 依赖包下载地址
httpclient-4.5.13.jar https://repo.maven.apache.org/maven2/org/apache/httpcomponents/httpclient/4.5.13/httpclient-4.5.13.jar
httpcore-4.4.13.jar https://repo.maven.apache.org/maven2/org/apache/httpcomponents/httpcore/4.4.13/httpcore-4.4.13.jar
commons-logging-1.2.jar https://repo.maven.apache.org/maven2/commons-logging/commons-logging/1.2/commons-logging-1.2.jar
jackson-databind-2.13.0.jar https://repo.maven.apache.org/maven2/com/fasterxml/jackson/core/jackson-databind/2.13.0/jackson-databind-2.13.0.jar
jackson-core-2.13.0.jar https://repo.maven.apache.org/maven2/com/fasterxml/jackson/core/jackson-core/2.13.0/jackson-core-2.13.0.jar
jackson-annotations-2.13.0.jar https://repo.maven.apache.org/maven2/com/fasterxml/jackson/core/jackson-annotations/2.13.0/jackson-annotations-2.13.0.jar

  1. 添加到项目：在 IDEA 中，将下载的 JAR 包复制到项目中的 lib/ 目录（手动创建），然后通过「Project Structure」→「Modules」→「Dependencies」逐个添加。

  2. 处理传递性依赖：httpclient 本身依赖于 httpcore、commons-logging 等。这些 JAR 也必须手动下载并添加，否则运行时抛出 ClassNotFoundException。

  3. 解决版本冲突：假如 jackson-databind 需要特定版本的 jackson-core，如果我们误下载了不兼容的版本，程序将出现难以调试的运行时错误。

  4. 团队协作：项目需要提交到 Git 仓库。lib/ 目录下的所有 JAR 包都必须提交，因为其他人没有这些文件。这会导致仓库体积迅速膨胀（几百 MB）。

  5. 更新版本：如果我们需要升级某个库的版本，必须重新下载新 JAR 替换旧 JAR，并手动删除旧版本，所有操作需要人工完成。

总结痛点：

痛点 说明
依赖管理混乱 第三方JAR包需要手动下载、复制到项目中，版本冲突难以排查
项目结构不统一 每个项目的目录结构各不相同，新人接手需要重新适应
构建流程繁琐 编译、测试、打包、部署需要手动执行或编写复杂的脚本
缺乏标准化 不同项目使用不同的构建方式，难以实现自动化

Maven是什么

Maven（全称Apache Maven）是一款基于项目对象模型（Project Object Model，POM） 的项目管理和构建工具，核心功能是管理Java项目的依赖、编译、测试、打包和部署等全流程。

Maven完全免费开源，跨平台支持Windows、macOS和Linux。

Maven vs Gradle vs Ant

对比维度 Maven Gradle Ant + Ivy
配置方式 XML（POM声明式） Groovy/Kotlin DSL（编程式） XML（命令式）
依赖管理 ✅ 内置 ✅ 内置 ✅（通过Ivy）
约定优于配置 ✅ 强制规范 ✅ 可选 ❌ 需手动配置
构建速度 中等 快（增量构建+缓存） 慢
学习曲线 平缓 陡峭 中等
适用场景 传统企业项目 多模块/Android项目 遗留系统

[!NOTE]

Maven和Gradle是目前Java项目最主流的两个构建工具。Maven胜在规范统一，所有项目都遵循标准的项目结构和生命周期，新手上手容易，老项目中也用得最广。Gradle胜在灵活和构建速度快。

核心概念：约定优于配置

Maven的核心设计理念是约定优于配置（Convention over Configuration）：项目遵循标准的目录结构和生命周期，开发者只需关注业务代码，而不需要为每个项目重复配置构建细节。

Windows环境变量配置

第一步：确认JDK已安装

打开命令行（Win+R → cmd），执行：

java -version
javac -version

如果报错，需要先安装JDK并配置JAVA_HOME环境变量。

第二步：新建MAVEN_HOME系统变量

右键「此电脑」→「属性」→「高级系统设置」→「环境变量」→ 在「系统变量」中点击「新建」：

变量名 变量值
MAVEN_HOME Maven解压路径（如 D:\apache-maven-3.9.16）

第三步：修改Path变量

在「系统变量」中找到Path变量，点击「编辑」→「新建」，添加：

%MAVEN_HOME%\bin

第四步：验证安装

打开新的命令行窗口（必须重启CMD），执行：

mvn -v

成功时应看到类似输出：

Apache Maven 3.9.9 (xxx)
Maven home: D:\apache-maven-3.9.9
Java version: 1.8.0_xxx, vendor: Oracle Corporation

[!CAUTION] 如果提示 'mvn' 不是内部或外部命令，检查：

  1. Path变量是否包含 %MAVEN_HOME%\bin
  2. 是否重启了CMD窗口
  3. 系统变量是否保存在「系统变量」而非「用户变量」

macOS / Linux 安装

macOS（Homebrew）：

brew install maven

macOS（SDKMAN）：

sdk install maven

Ubuntu/Debian（APT）：

sudo apt install maven

CentOS/RHEL（YUM）：

sudo yum install maven

手动安装（所有Unix系统）： 

# 下载并解压
wget https://dlcdn.apache.org/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz
tar -xzvf apache-maven-3.9.9-bin.tar.gz -C /opt/

# 验证
mvn -v

settings.xml配置

配置文件位置

settings.xml 是Maven的全局/用户配置文件，有两个位置：

位置 级别 说明
$MAVEN_HOME/conf/settings.xml 全局 影响所有用户，不推荐直接修改
~/.m2/settings.xml 用户 推荐修改此文件，不影响其他开发者

[!NOTE] 如果 ~/.m2/settings.xml 不存在，可以从 $MAVEN_HOME/conf/settings.xml 复制一份。

配置本地仓库（localRepository）

Maven会将下载的依赖JAR包存储在本地仓库中，避免重复下载。

默认位置：

  • Windows：C:\Users\用户名\.m2\repository
  • macOS/Linux：~/.m2/repository

修改路径（避免C盘空间不足）：

<localRepository>D:\maven_repo</localRepository>

配置国内镜像仓库（mirror）

默认Maven使用中央仓库（repo.maven.apache.org），国内访问速度慢。通过配置国内镜像可以将下载速度提升3-5倍。

阿里云镜像配置示例：

<mirrors>
    <mirror>
        <id>aliyunmaven</id>
        <name>阿里云公共仓库</name>
        <url>https://maven.aliyun.com/repository/public</url>
        <mirrorOf>central</mirrorOf>
    </mirror>
</mirrors>
标签 说明
<id> 镜像的唯一标识符
<name> 镜像的名称，便于识别
<url> 镜像仓库的URL地址
<mirrorOf> 该镜像替代的仓库ID，central表示替代中央仓库

[!NOTE] 配置镜像后，所有对中央仓库的请求会被转发至阿里云镜像地址。

第一个Maven项目

使用 archetype:generate 创建项目

Maven提供了archetype（项目模板）来快速创建项目。

交互式创建（推荐新手）： 

mvn archetype:generate

系统会交互式地询问：

  • 选择archetype（直接回车选择默认的 maven-archetype-quickstart）
  • 输入 groupId（如 com.example）
  • 输入 artifactId（如 my-first-maven-project）
  • 输入 version（默认 1.0-SNAPSHOT）
  • 输入 package（默认与groupId相同）

非交互式创建（一次性指定所有参数）： 

mvn archetype:generate -DgroupId=com.example -DartifactId=my-first-maven-project -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false

标准Maven项目目录结构

创建成功后，项目目录结构如下：

my-first-maven-project/
├── pom.xml                    # 项目对象模型配置文件
├── src/
│   ├── main/
│   │   └── java/              # 主代码目录
│   │       └── com/example/   # 包路径
│   │           └── App.java   # 主类
│   └── test/
│       └── java/              # 测试代码目录
│           └── com/example/
│               └── AppTest.java # 测试类
└── target/                    # 构建输出目录（自动生成）

pom.xml 初识

<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <!-- 项目坐标：唯一标识一个项目 -->
    <groupId>com.example</groupId>
    <artifactId>my-first-maven-project</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>jar</packaging>

    <name>my-first-maven-project</name>
    <url>http://maven.apache.org</url>

    <properties>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
        <maven.compiler.source>1.8</maven.compiler.source>
        <maven.compiler.target>1.8</maven.compiler.target>
    </properties>

    <dependencies>
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.11</version>
            <scope>test</scope>
        </dependency>
    </dependencies>
</project>

[!NOTE] 项目坐标（groupId、artifactId、version）是Maven识别项目的唯一标识，类似于数据库的主键。我们会在下一节中进行详细介绍。

Maven常用命令初体验

在项目根目录（即包含pom.xml的目录）下执行以下命令：

mvn clean

清理项目，删除target目录下的所有编译输出文件。

mvn clean

mvn compile

编译项目源码（src/main/java下的Java文件），生成class文件到target/classes目录。

mvn compile

mvn test

执行单元测试。会先编译main和test中的代码，然后执行src/test/java下的测试方法。

mvn test

mvn package

打包项目。根据pom.xml中的<packaging>类型生成对应的JAR或WAR文件到target目录。

mvn package

常用命令组合

实际开发中经常组合使用：

# 最常用：清理 → 编译 → 测试 → 打包
mvn clean package

# 清理 → 编译 → 测试（跳过打包）
mvn clean test
