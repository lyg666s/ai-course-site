<p>假设我们使用 IntelliJ IDEA 创建一个简单的 Java 项目，需要实现一个功能：<strong>发送 HTTP 请求并解析返回的 JSON 数据</strong>。</p>
<p>我们不想自己写底层的网络和 JSON 解析代码，希望使用成熟的第三方库，比如：</p>
<ul>
<li><strong>Apache HttpClient</strong>：用于发送 HTTP 请求</li>
<li><strong>Jackson</strong>：用于解析 JSON</li>
</ul>
<p>项目结构如下：</p>
<div class="codehilite"><pre><span></span><code>simple-http-json-demo/
├── src/
│   └── com/demo/
│       └── GithubApiClient.java
├── lib/                         # 手动存放 JAR 包的目录
│   ├── httpclient-4.5.13.jar
│   ├── httpcore-4.4.13.jar
│   ├── commons-logging-1.2.jar
│   ├── jackson-databind-2.13.0.jar
│   ├── jackson-core-2.13.0.jar
│   └── jackson-annotations-2.13.0.jar
└── .idea/                       # IDEA 项目配置文件
</code></pre></div>

<p>在原生 Java 项目中（不使用任何构建工具），我们需要手动完成以下步骤：</p>
<ol>
<li><strong>下载 JAR 包</strong>：去 Apache 官网下载 <code>httpclient-4.5.13.jar</code>，去 Jackson 官网下载 <code>jackson-databind-2.13.0.jar</code> 以及它的所有依赖（如 <code>jackson-core</code>、<code>jackson-annotations</code>）。</li>
</ol>

<thead>
<tr>
<th>依赖包名称</th>
<th>依赖包下载地址</th>
</tr>
</thead>

<tr>
<td>httpclient-4.5.13.jar</td>
<td>https://repo.maven.apache.org/maven2/org/apache/httpcomponents/httpclient/4.5.13/httpclient-4.5.13.jar</td>
</tr>
<tr>
<td>httpcore-4.4.13.jar</td>

</tr>

<td>jackson-databind-2.13.0.jar</td>

<ol start="2">
<li>
<p><strong>添加到项目</strong>：在 IDEA 中，将下载的 JAR 包复制到项目中的 <code>lib/</code> 目录（手动创建），然后通过「Project Structure」→「Modules」→「Dependencies」逐个添加。</p>
</li>
<li>
<p><strong>处理传递性依赖</strong>：<code>httpclient</code> 本身依赖于 <code>httpcore</code>、<code>commons-logging</code> 等。这些 JAR 也必须手动下载并添加，否则运行时抛出 <code>ClassNotFoundException</code>。</p>
</li>
<li>
<p><strong>解决版本冲突</strong>：假如 <code>jackson-databind</code> 需要特定版本的 <code>jackson-core</code>，如果我们误下载了不兼容的版本，程序将出现难以调试的运行时错误。</p>
</li>
<li>
<p><strong>团队协作</strong>：项目需要提交到 Git 仓库。<code>lib/</code> 目录下的所有 JAR 包都必须提交，因为其他人没有这些文件。这会导致仓库体积迅速膨胀（几百 MB）。</p>
</li>
<li>
<p><strong>更新版本</strong>：如果我们需要升级某个库的版本，必须重新下载新 JAR 替换旧 JAR，并手动删除旧版本，所有操作需要人工完成。</p>
</li>
</ol>

</tr>

<td>缺乏标准化</td>
<td>不同项目使用不同的构建方式，难以实现自动化</td>
</tr>

<h3 id="Maven是什么">Maven是什么</h3>
<p><strong>Maven</strong>（全称Apache Maven）是一款基于<strong>项目对象模型（Project Object Model，POM）</strong> 的项目管理和构建工具，核心功能是管理Java项目的依赖、编译、测试、打包和部署等全流程。</p>
<p>Maven完全免费开源，跨平台支持Windows、macOS和Linux。</p>
<h3 id="Maven-vs-Gradle-vs-Ant">Maven vs Gradle vs Ant</h3>
<table>
<thead>
<tr>
<th>对比维度</th>
<th>Maven</th>
<th>Gradle</th>
<th>Ant + Ivy</th>
</tr>
</thead>
<tbody>
<tr>
<td>配置方式</td>
<td>XML（POM声明式）</td>
<td>Groovy/Kotlin DSL（编程式）</td>
<td>XML（命令式）</td>
</tr>
<tr>
<td>依赖管理</td>
<td>✅ 内置</td>
<td>✅ 内置</td>
<td>✅（通过Ivy）</td>
</tr>
<tr>
<td>约定优于配置</td>
<td>✅ 强制规范</td>
<td>✅ 可选</td>
<td>❌ 需手动配置</td>
</tr>
<tr>
<td>构建速度</td>
<td>中等</td>
<td>快（增量构建+缓存）</td>
<td>慢</td>
</tr>
<tr>
<td>学习曲线</td>
<td>平缓</td>
<td>陡峭</td>
<td>中等</td>
</tr>
<tr>
<td>适用场景</td>
<td>传统企业项目</td>
<td>多模块/Android项目</td>
<td>遗留系统</td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]</p>
<p>Maven和Gradle是目前Java项目最主流的两个构建工具。Maven胜在<strong>规范统一</strong>，所有项目都遵循标准的项目结构和生命周期，新手上手容易，老项目中也用得最广。Gradle胜在<strong>灵活</strong>和<strong>构建速度快</strong>。</p>
</blockquote>
<h3 id="核心概念约定优于配置">核心概念：约定优于配置</h3>
<p>Maven的核心设计理念是<strong>约定优于配置</strong>（Convention over Configuration）：项目遵循标准的目录结构和生命周期，开发者只需关注业务代码，而不需要为每个项目重复配置构建细节。</p>

</code></pre></div>

<h2 id="第一个Maven项目">第一个Maven项目</h2>
<h3 id="使用-archetypegenerate-创建项目">使用 archetype:generate 创建项目</h3>
<p>Maven提供了<strong>archetype</strong>（项目模板）来快速创建项目。</p>
<p><strong>交互式创建（推荐新手）：</strong> </p>
<div class="codehilite"><pre><span></span><code>mvn archetype:generate
</code></pre></div>

<p>系统会交互式地询问：</p>
<ul>
<li>选择archetype（直接回车选择默认的 <code>maven-archetype-quickstart</code>）</li>
<li>输入 <code>groupId</code>（如 <code>com.example</code>）</li>
<li>输入 <code>artifactId</code>（如 <code>my-first-maven-project</code>）</li>
<li>输入 <code>version</code>（默认 <code>1.0-SNAPSHOT</code>）</li>
<li>输入 <code>package</code>（默认与groupId相同）</li>
</ul>
<p><strong>非交互式创建（一次性指定所有参数）：</strong> </p>
<div class="codehilite"><pre><span></span><code>mvn archetype:generate -DgroupId=com.example -DartifactId=my-first-maven-project -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false
</code></pre></div>

│   │   └── java/              # 主代码目录

</code></pre></div>

<h2 id="Maven常用命令初体验">Maven常用命令初体验</h2>
<p>在项目根目录（即包含<code>pom.xml</code>的目录）下执行以下命令：</p>
<h3 id="mvn-clean">mvn clean</h3>
<p>清理项目，删除<code>target</code>目录下的所有编译输出文件。</p>
<div class="codehilite"><pre><span></span><code>mvn clean
</code></pre></div>

<h3 id="mvn-compile">mvn compile</h3>
<p>编译项目源码（<code>src/main/java</code>下的Java文件），生成class文件到<code>target/classes</code>目录。</p>
<div class="codehilite"><pre><span></span><code>mvn compile
</code></pre></div>

<h3 id="mvn-test">mvn test</h3>
<p>执行单元测试。会先编译<code>main</code>和<code>test</code>中的代码，然后执行<code>src/test/java</code>下的测试方法。</p>
<div class="codehilite"><pre><span></span><code>mvn test
</code></pre></div>

<h3 id="mvn-package">mvn package</h3>
<p>打包项目。根据<code>pom.xml</code>中的<code>&lt;packaging&gt;</code>类型生成对应的JAR或WAR文件到<code>target</code>目录。</p>
<div class="codehilite"><pre><span></span><code>mvn package
</code></pre></div>

<h3 id="常用命令组合">常用命令组合</h3>
<p>实际开发中经常组合使用：</p>
<div class="codehilite"><pre><span></span><code># 最常用：清理 → 编译 → 测试 → 打包
mvn clean package

# 清理 → 编译 → 测试（跳过打包）
mvn clean test
</code></pre></div>
