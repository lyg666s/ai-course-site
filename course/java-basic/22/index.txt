<h2 id="CompletableFuture-异步编程的利器"><code>CompletableFuture</code> —— 异步编程的利器</h2>
<h3 id="为什么需要-CompletableFuture">为什么需要 <code>CompletableFuture</code></h3>
<p>回顾：<code>Future</code> 代表异步计算的结果，提供以下方法：</p>
<table>
<thead>
<tr>
<th>方法</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>boolean cancel(boolean mayInterruptIfRunning)</code></td>
<td>取消任务</td>
</tr>
<tr>
<td><code>boolean isCancelled()</code></td>
<td>是否已取消</td>
</tr>
<tr>
<td><code>boolean isDone()</code></td>
<td>是否已完成</td>
</tr>
<tr>
<td><code>V get()</code></td>
<td>获取结果（阻塞等待）</td>
</tr>
<tr>
<td><code>V get(long timeout, TimeUnit unit)</code></td>
<td>限时获取（超时抛异常）</td>
</tr>
</tbody>
</table>
<p>传统 <code>Future</code> 的局限性：</p>
<ul>
<li>只能通过阻塞（<code>get()</code>）或轮询（<code>isDone()</code>）获取结果</li>
<li>无法链式组合多个异步任务</li>
<li>无法处理异常链</li>
<li>无法手动完成（设定结果）</li>
</ul>
<p><code>CompletableFuture</code> 弥补了这些缺陷，提供了函数式异步编程能力。</p>

</tr>
<tr>
<td><code>runAsync(Runnable)</code></td>
<td>异步执行无返回值任务</td>
</tr>
<tr>

</tr>
</tbody>
</table>

<h3 id="链式组合">链式组合</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    A[创建异步任务] --&gt; B[thenApply 转换结果]
    B --&gt; C[thenAccept 消费结果]
    C --&gt; D[thenRun 执行动作]
</code></pre></div>

<table>
<thead>
<tr>
<th>方法</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>thenApply(Function)</code></td>
<td>对结果进行转换（有返回值）</td>
</tr>
<tr>
<td><code>thenAccept(Consumer)</code></td>
<td>消费结果（无返回值）</td>
</tr>
<tr>
<td><code>thenRun(Runnable)</code></td>
<td>执行动作（不依赖结果）</td>
</tr>
</tbody>
</table>

<h2 id="ThreadLocal-线程本地变量"><code>ThreadLocal</code> —— 线程本地变量</h2>

<h3 id="内存泄漏问题">内存泄漏问题</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    ThreadRef[线程引用] --&gt; Thread[Thread对象]
    Thread --&gt; TLM[ThreadLocalMap]
    TLM --&gt; Entry[Entry]
    Entry --&gt;|弱引用| TL[ThreadLocal对象]
    Entry --&gt;|强引用| Value[副本值]

    style Entry fill:#ffeb3b
</code></pre></div>

<p><strong>问题：</strong> 如果线程长期存活（如线程池中的线程），且 <code>ThreadLocal</code> 对象被 GC 回收，但键为 <code>null</code> 的 Entry 仍然存在，导致值无法回收，造成内存泄漏。</p>
<p><strong>解决方法：</strong> 使用 <code>try-finally</code> 确保 <code>remove()</code> 被调用。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="kd">public</span><span class="w"> </span><span class="kt">void</span><span class="w"> </span><span class="nf">doWork</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="n">SimpleDateFormat</span><span class="w"> </span><span class="n">sdf</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">dateFormat</span><span class="p">.</span><span class="na">get</span><span class="p">();</span>
<span class="w">    </span><span class="k">try</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="c1">// 使用 sdf</span>
<span class="w">    </span><span class="p">}</span><span class="w"> </span><span class="k">finally</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="n">dateFormat</span><span class="p">.</span><span class="na">remove</span><span class="p">();</span><span class="w"> </span><span class="c1">// 必须显式移除</span>
<span class="w">    </span><span class="p">}</span>
<span class="p">}</span>
</code></pre></div>

<blockquote>
<p>[!CAUTION]
在线程池中使用 <code>ThreadLocal</code> 务必调用 <code>remove()</code>，否则可能导致内存泄漏。</p>
</blockquote>
<h2 id="原子类">原子类</h2>
<h3 id="简介_1">简介</h3>
<p>在多线程环境下，对共享变量进行 <code>i++</code> 等操作并非原子性，通常需要 <code>synchronized</code> 或 <code>Lock</code> 来保证线程安全。<code>java.util.concurrent.atomic</code> 包提供了一系列原子类，利用 <strong>CAS（Compare-And-Swap）</strong> 机制，在无锁的情况下实现线程安全的原子操作，性能更高。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    subgraph 非原子操作
        Read[读取 i=0] --&gt; Calc[计算 i+1] --&gt; Write[写入 i=1]
        Read -.-&gt;|线程切换| Write2[写入错误值]
    end

    subgraph 原子类操作
        CAS[CAS 比较并交换] --&gt;|成功| Done[更新完成]
        CAS --&gt;|失败| Retry[重试/自旋]
    end

    style CAS fill:#4CAF50,color:#fff
</code></pre></div>
