<h2 id="生活中的状态类比">生活中的状态类比</h2>
<p>在正式学习线程状态之前，我们先通过生活中的例子来理解“状态”这个概念。</p>
<p>想象你是一个<strong>外卖骑手</strong>，你的状态会随着工作进展而变化：</p>
<table>
<thead>
<tr>
<th>状态</th>
<th>生活场景</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>新建</strong></td>
<td>你刚入职，还没开始接单</td>
</tr>
<tr>
<td><strong>就绪</strong></td>
<td>你打开接单软件，等待系统派单（随时准备接单）</td>
</tr>
<tr>
<td><strong>运行</strong></td>
<td>你正在送餐的路上（正在执行任务）</td>
</tr>
<tr>
<td><strong>阻塞</strong></td>
<td>你在等红绿灯（需要等待某个条件才能继续）</td>
</tr>
<tr>
<td><strong>等待</strong></td>
<td>你在等商家出餐（等待某个通知）</td>
</tr>
<tr>
<td><strong>计时等待</strong></td>
<td>你在等商家出餐，但只等10分钟</td>
</tr>
<tr>

<p>线程也有类似的状态变化，它会在不同的状态之间切换。理解这些状态，是掌握多线程编程的基础。</p>
<h2 id="线程的六种状态">线程的六种状态</h2>
<p>Java 中线程共有 <strong>6 种状态</strong>，定义在 <code>Thread.State</code> 枚举中：</p>
<table>
<thead>
<tr>
<th>状态</th>
<th>英文</th>
<th>说明</th>
<th>生活类比</th>
</tr>
</thead>
<tbody>
<tr>
<td>新建</td>
<td><code>NEW</code></td>
<td>线程被创建，但尚未启动</td>
<td>你刚入职，还没开始接单</td>
</tr>
<tr>
<td>就绪/运行</td>
<td><code>RUNNABLE</code></td>
<td>线程已就绪等待调度 或 正在执行</td>
<td>你打开软件准备接单 / 正在送餐</td>
</tr>
<tr>
<td>阻塞</td>
<td><code>BLOCKED</code></td>
<td>线程等待获取锁</td>
<td>你在等红绿灯</td>
</tr>
<tr>
<td>等待</td>
<td><code>WAITING</code></td>
<td>线程无限期等待另一个线程的通知</td>

</tr>

</tr>
<tr>

<td>你下班了</td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]
严格来说，Java 中 <code>RUNNABLE</code> 状态包含了操作系统的<strong>就绪</strong>和<strong>运行</strong>两个状态。这是 Java 对线程状态的一种简化。</p>
</blockquote>
<h3 id="NEW新建状态">NEW（新建状态）</h3>
<p>线程被创建但还没有调用 <code>start()</code> 方法。</p>

<h3 id="RUNNABLE就绪运行状态">RUNNABLE（就绪/运行状态）</h3>
<p>调用 <code>start()</code> 后，线程进入 <code>RUNNABLE</code> 状态。这个状态实际上包含两种情况：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>stateDiagram-v2
    state RUNNABLE {
        Ready --&gt; Running: 获得CPU时间片
        Running --&gt; Ready: 时间片用完/yield()
        note right of Ready
            就绪状态
            等待CPU调度
        end note
        note right of Running
            运行状态
            正在CPU上执行
        end note
    }
</code></pre></div>

<ul>
<li><strong>就绪状态</strong>：线程已准备好执行，等待操作系统调度分配 CPU。</li>
<li><strong>运行状态</strong>：线程正在 CPU 上执行。</li>
</ul>
<p>这两个状态在 Java 中统一表示为 <code>RUNNABLE</code>。</p>
<h3 id="BLOCKED阻塞状态">BLOCKED（阻塞状态）</h3>
<p>当线程尝试获取一个<strong>被其他线程占用的锁</strong>时，会进入 <code>BLOCKED</code> 状态。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant T1 as 线程A
    participant Lock as 锁对象
    participant T2 as 线程B

    T1-&gt;&gt;Lock: 获取锁 ✓
    Lock--&gt;&gt;T1: 持有锁
    activate T1
    T1-&gt;&gt;T1: 执行同步代码块...

    T2-&gt;&gt;Lock: 尝试获取锁 ✗
    Note over T2: 锁被A占用
    Lock--&gt;&gt;T2: 进入 BLOCKED 状态
    deactivate T1

    Note over Lock: 线程A释放锁
    T2-&gt;&gt;Lock: 获取锁 ✓
    Lock--&gt;&gt;T2: 获得锁，变为 RUNNABLE
</code></pre></div>

<h2 id="线程状态转换图">线程状态转换图</h2>
<p>理解了每个状态的含义后，我们来看看线程是如何在这些状态之间转换的：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>stateDiagram-v2
    [*] --&gt; NEW

    NEW --&gt; RUNNABLE: t.start()

    state RUNNABLE {
        [*] --&gt; Ready: 等待CPU调度
        Ready --&gt; Running: 获得时间片
        Running --&gt; Ready: 时间片用完 / yield()
    }

    RUNNABLE --&gt; BLOCKED: 等待锁
    BLOCKED --&gt; RUNNABLE: 获得锁

    RUNNABLE --&gt; WAITING: wait() / join() / park()
    WAITING --&gt; RUNNABLE: notify() / unpark()

    RUNNABLE --&gt; TIMED_WAITING: sleep(ms) / wait(ms)
    TIMED_WAITING --&gt; RUNNABLE: 超时或唤醒

    RUNNABLE --&gt; TERMINATED: run() 结束
    TERMINATED --&gt; [*]

    note left of NEW
        已创建
        未启动
    end note

    note left of RUNNABLE
        就绪 + 运行
        由OS调度
    end note

    note left of BLOCKED
        等待锁释放
        (同步阻塞)
    end note

    note left of WAITING
        无限等待
        需显式唤醒
    end note

    note left of TIMED_WAITING
        计时等待
        超时自动唤醒
    end note

    note left of TERMINATED
        已终止
        不可重启
    end note
</code></pre></div>

<h3 id="interrupt-中断线程"><code>interrupt()</code> —— 中断线程</h3>
<p><code>interrupt()</code> 用于向线程发送一个<strong>中断信号</strong>，通知线程应该停止正在做的事情。</p>
<p><strong>中断机制的核心是协作</strong>：中断只是给线程发送一个信号，线程需要<strong>主动检查</strong>自己是否被中断，然后决定如何响应。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph Sender["发送中断"]
        A["线程A"] --&gt;|"interrupt()"| B["中断信号"]
    end

    subgraph Receiver["接收中断"]
        B --&gt; C{"线程B检查"}
        C --&gt;|"isInterrupted()"| D["主动检查"]
        C --&gt;|"sleep/wait等"| E["抛出InterruptedException"]
        D --&gt; F["处理中断"]
        E --&gt; F
    end

    style Sender fill:#e3f2fd
    style Receiver fill:#fff3e0
</code></pre></div>

</tr>
<tr>
<td><code>t.isInterrupted()</code></td>

<h2 id="守护线程">守护线程</h2>
<h3 id="什么是守护线程">什么是守护线程</h3>
<p>Java 中的线程分为两类：</p>
<table>
<thead>
<tr>
<th>类型</th>
<th>说明</th>
<th>例子</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>用户线程</strong></td>
<td>普通线程，JVM 会等待所有用户线程结束才退出</td>
<td>main 线程、自定义线程</td>
</tr>
<tr>
<td><strong>守护线程</strong></td>
<td>后台线程，JVM 退出时<strong>不会等待</strong>守护线程结束</td>
<td>垃圾回收线程、监控线程</td>
</tr>
</tbody>
</table>

<h3 id="守护线程使用注意事项">守护线程使用注意事项</h3>
<blockquote>
<p>[!CAUTION]</p>
<ol>
<li><code>setDaemon(true)</code> 必须在 <code>start()</code> <strong>之前</strong>调用，否则抛出 <code>IllegalThreadStateException</code>。</li>
<li>守护线程不应该执行 IO 操作或访问资源，因为 JVM 退出时可能会突然中断。</li>
<li>守护线程不能持有“必须释放”的资源（如文件句柄、数据库连接）。</li>
<li>适合使用守护线程的场景：监控、日志记录、定时任务、缓存清理等。</li>
</ol>
</blockquote>

<h3 id="作业二线程状态观察编程题">作业二：线程状态观察编程题</h3>
<p><strong>题目描述</strong>
编写一个 Java 程序，模拟三个线程协同工作，重点观察线程在不同阶段的状态变化。</p>
<p><strong>程序功能</strong>：</p>
<ol>
<li><strong>线程 A（Worker）</strong>：执行一个耗时的计数任务，从 1 到 5，每隔 1 秒打印一个数字。打印完数字后，再额外休眠 2 秒，然后结束。</li>
<li><strong>线程 B（Waiter）</strong>：调用 <code>threadA.join()</code> 等待线程 A 完全结束，等待完成后打印 <code>"Waiter: A finished"</code>。</li>
<li><strong>线程 C（Monitor）</strong>：每隔 500 毫秒（0.5 秒）打印一次当前所有线程（A、B、C 以及主线程）的状态（使用 <code>getState()</code>）。当所有线程（A、B、主线程）都终止后，监控线程打印 <code>"Monitor: all done"</code> 并结束。</li>
<li><strong>主线程</strong>：依次启动 A、B、C，然后调用 <code>threadA.join()</code> 和 <code>threadB.join()</code> 等待它们结束，最后打印 <code>"Main: exit"</code>。</li>
</ol>
<p><strong>输出示例</strong>（状态输出顺序可能略有差异，但关键状态必须出现）：</p>
<div class="codehilite"><pre><span></span><code>A: 1
A: 2
Monitor: A=TIMED_WAITING, B=WAITING, C=RUNNABLE, MAIN=TIMED_WAITING
A: 3
Monitor: A=TIMED_WAITING, B=WAITING, C=RUNNABLE, MAIN=TIMED_WAITING
A: 4
A: 5
Waiter: A finished
Monitor: A=TERMINATED, B=RUNNABLE, C=RUNNABLE, MAIN=TIMED_WAITING
Monitor: A=TERMINATED, B=TERMINATED, C=RUNNABLE, MAIN=TIMED_WAITING
Main: exit
Monitor: all done
</code></pre></div>

<p>（实际输出中，Monitor 会多次打印，此处仅截取关键片段）</p>
