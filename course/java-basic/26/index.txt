<p>在正式学习之前，我们先通过生活中的例子理解“多模块”的概念。</p>
<p>想象一下你经营一家<strong>大型连锁餐厅集团</strong>：</p>
<table>
<thead>
<tr>
<th>生活场景</th>
<th>Maven多模块概念</th>
</tr>
</thead>
<tbody>
<tr>
<td>集团总部，统一品牌形象和运营标准</td>
<td><strong>父POM</strong>（统一管理）</td>
</tr>
<tr>
<td>菜单、食材标准、装修风格由总部统一制定</td>
<td><strong>dependencyManagement</strong>（统一版本）</td>
</tr>
<tr>
<td>各分店只需执行标准，不用自己研究配方</td>
<td><strong>继承</strong>（子模块继承父配置）</td>
</tr>
<tr>
<td>顾客点餐时，各分店各自出餐</td>
<td><strong>聚合</strong>（统一构建所有模块）</td>
</tr>
<tr>
<td>中央厨房供应半成品</td>
<td><strong>公共模块</strong>（被其他模块复用）</td>
</tr>
<tr>
<td>不同分店有各自的特色菜品</td>
<td><strong>模块独立扩展</strong></td>
</tr>
</tbody>
</table>
<p><strong>核心思想：</strong> 多模块项目管理就是将一个大项目拆分成多个相互协作的子模块，通过统一的父POM来管理公共配置，实现代码复用、职责分离和统一构建。</p>
<h2 id="为什么需要多模块项目">为什么需要多模块项目</h2>
<h3 id="单体项目的痛点">单体项目的痛点</h3>
<p>随着项目规模扩大，将所有代码放在一个模块中会面临诸多问题：</p>
<table>
<thead>
<tr>
<th>痛点</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td>代码臃肿</td>
<td>所有代码混在一起，难以维护和理解</td>
</tr>
<tr>
<td>编译缓慢</td>
<td>每次修改都需要重新编译整个项目</td>
</tr>
<tr>
<td>职责不清</td>
<td>业务逻辑、数据访问、工具类等没有清晰边界</td>
</tr>
<tr>
<td>复用困难</td>
<td>无法单独提取公共模块供其他项目使用</td>
</tr>
<tr>
<td>团队协作冲突</td>
<td>多人修改同一模块容易产生冲突</td>
</tr>
<tr>
<td>测试困难</td>
<td>修改一处可能影响整个项目，回归测试范围大</td>
</tr>
</tbody>
</table>
<h3 id="多模块项目的优势">多模块项目的优势</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph 单体项目
        A[所有代码混在一起]
        A --&gt; P1[编译慢]
        A --&gt; P2[维护难]
        A --&gt; P3[复用难]
    end

    subgraph 多模块项目
        B[按职责拆分]
        B --&gt; M1[common 公共模块]
        B --&gt; M2[api 接口模块]
        B --&gt; M3[service 业务模块]
        B --&gt; M4[web 展示模块]
        M1 --&gt; A1[独立编译]
        M2 --&gt; A1
        M3 --&gt; A1
        M4 --&gt; A1
    end
</code></pre></div>

<ul>
<li><strong>职责分离</strong>：每个模块专注于特定功能领域</li>
<li><strong>独立构建</strong>：修改某个模块只需重新构建该模块及其依赖</li>
<li><strong>代码复用</strong>：公共模块可被多个模块共享</li>
<li><strong>并行开发</strong>：不同团队可同时开发不同模块</li>
<li><strong>版本独立</strong>：每个模块可以有自己的版本演进</li>
<li><strong>易于测试</strong>：模块边界清晰，单元测试更精准</li>
</ul>
<h2 id="聚合Aggregation">聚合（Aggregation）</h2>
<h3 id="什么是聚合">什么是聚合</h3>
<p><strong>聚合</strong>是将多个子模块组织成一个整体，让父模块可以<strong>统一管理</strong>所有子模块的构建。聚合模块本身不包含业务代码，只是作为一个"容器"来组织子模块。</p>
<h3 id="聚合的配置">聚合的配置</h3>
<p>在父POM中使用 <code>&lt;modules&gt;</code> 元素声明子模块：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="cm">&lt;!-- 父POM：pom.xml --&gt;</span>
<span class="nt">&lt;project&gt;</span>
<span class="w">    </span><span class="nt">&lt;modelVersion&gt;</span>4.0.0<span class="nt">&lt;/modelVersion&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.example<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>parent-project<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>1.0-SNAPSHOT<span class="nt">&lt;/version&gt;</span>
<span class="w">    </span><span class="nt">&lt;packaging&gt;</span>pom<span class="nt">&lt;/packaging&gt;</span><span class="w">   </span><span class="cm">&lt;!-- 必须为 pom --&gt;</span>

<span class="w">    </span><span class="nt">&lt;modules&gt;</span>
<span class="w">        </span><span class="nt">&lt;module&gt;</span>common<span class="nt">&lt;/module&gt;</span>
<span class="w">        </span><span class="nt">&lt;module&gt;</span>api<span class="nt">&lt;/module&gt;</span>
<span class="w">        </span><span class="nt">&lt;module&gt;</span>service<span class="nt">&lt;/module&gt;</span>
<span class="w">        </span><span class="nt">&lt;module&gt;</span>web<span class="nt">&lt;/module&gt;</span>
<span class="w">    </span><span class="nt">&lt;/modules&gt;</span>
<span class="nt">&lt;/project&gt;</span>
</code></pre></div>

<blockquote>
<p>[!CAUTION]</p>
<p>聚合模块的 <code>&lt;packaging&gt;</code> 必须是 <code>pom</code>，否则无法声明子模块。</p>
</blockquote>
<div class="codehilite"><pre><span></span><code>parent-project/                    # 父项目目录
├── pom.xml                        # 父POM（packaging=pom）
├── common/
│   └── pom.xml                    # 公共模块
├── api/
│   └── pom.xml                    # API模块
├── service/
│   └── pom.xml                    # 业务模块
└── web/
    └── pom.xml                    # Web模块
</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>子模块目录名通常与 <code>&lt;module&gt;</code> 标签中的名称一致，约定优于配置。</p>
</blockquote>
<h3 id="聚合的构建行为">聚合的构建行为</h3>
<p>在父项目根目录执行 <code>mvn clean compile</code>：</p>
<ol>
<li>Maven读取父POM中的 <code>&lt;modules&gt;</code> 列表</li>
<li>按声明顺序依次进入每个子模块执行 <code>clean compile</code></li>
<li>所有子模块构建完成后，构建过程结束</li>
</ol>
<div class="codehilite"><pre><span></span><code># 在父项目根目录执行，会构建所有子模块
mvn clean install

# 只构建特定模块及其依赖
mvn clean install -pl common,service -am

# 只构建特定模块（不构建依赖模块）
mvn clean install -pl web
</code></pre></div>

<h2 id="继承Inheritance">继承（Inheritance）</h2>
<h3 id="什么是继承">什么是继承</h3>
<p><strong>继承</strong>是让子模块能够<strong>复用父POM中的配置</strong>，避免在每个子模块中重复定义相同的配置（如依赖版本、插件配置、属性等）。</p>
<h3 id="父POM配置">父POM配置</h3>
<p>父POM中定义公共配置，子模块可以继承：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="cm">&lt;!-- 父POM：pom.xml --&gt;</span>
<span class="nt">&lt;project&gt;</span>
<span class="w">    </span><span class="nt">&lt;modelVersion&gt;</span>4.0.0<span class="nt">&lt;/modelVersion&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.example<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>parent-project<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>1.0-SNAPSHOT<span class="nt">&lt;/version&gt;</span>
<span class="w">    </span><span class="nt">&lt;packaging&gt;</span>pom<span class="nt">&lt;/packaging&gt;</span>

<span class="w">    </span><span class="cm">&lt;!-- 公共属性 --&gt;</span>
<span class="w">    </span><span class="nt">&lt;properties&gt;</span>
<span class="w">        </span><span class="nt">&lt;project.build.sourceEncoding&gt;</span>UTF-8<span class="nt">&lt;/project.build.sourceEncoding&gt;</span>
<span class="w">        </span><span class="nt">&lt;maven.compiler.source&gt;</span>11<span class="nt">&lt;/maven.compiler.source&gt;</span>
<span class="w">        </span><span class="nt">&lt;maven.compiler.target&gt;</span>11<span class="nt">&lt;/maven.compiler.target&gt;</span>
<span class="w">        </span><span class="nt">&lt;jackson.version&gt;</span>2.13.0<span class="nt">&lt;/jackson.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;/properties&gt;</span>

<span class="w">    </span><span class="cm">&lt;!-- 统一依赖管理（子模块可继承） --&gt;</span>
<span class="w">    </span><span class="nt">&lt;dependencyManagement&gt;</span>
<span class="w">        </span><span class="nt">&lt;dependencies&gt;</span>
<span class="w">            </span><span class="nt">&lt;dependency&gt;</span>
<span class="w">                </span><span class="nt">&lt;groupId&gt;</span>com.fasterxml.jackson.core<span class="nt">&lt;/groupId&gt;</span>
<span class="w">                </span><span class="nt">&lt;artifactId&gt;</span>jackson-databind<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">                </span><span class="nt">&lt;version&gt;</span>${jackson.version}<span class="nt">&lt;/version&gt;</span>
<span class="w">            </span><span class="nt">&lt;/dependency&gt;</span>
<span class="w">            </span><span class="nt">&lt;dependency&gt;</span>
<span class="w">                </span><span class="nt">&lt;groupId&gt;</span>junit<span class="nt">&lt;/groupId&gt;</span>
<span class="w">                </span><span class="nt">&lt;artifactId&gt;</span>junit<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">                </span><span class="nt">&lt;version&gt;</span>4.13.2<span class="nt">&lt;/version&gt;</span>
<span class="w">                </span><span class="nt">&lt;scope&gt;</span>test<span class="nt">&lt;/scope&gt;</span>
<span class="w">            </span><span class="nt">&lt;/dependency&gt;</span>
<span class="w">        </span><span class="nt">&lt;/dependencies&gt;</span>
<span class="w">    </span><span class="nt">&lt;/dependencyManagement&gt;</span>

<span class="w">    </span><span class="cm">&lt;!-- 统一插件管理 --&gt;</span>
<span class="w">    </span><span class="nt">&lt;build&gt;</span>
<span class="w">        </span><span class="nt">&lt;pluginManagement&gt;</span>
<span class="w">            </span><span class="nt">&lt;plugins&gt;</span>
<span class="w">                </span><span class="nt">&lt;plugin&gt;</span>
<span class="w">                    </span><span class="nt">&lt;groupId&gt;</span>org.apache.maven.plugins<span class="nt">&lt;/groupId&gt;</span>
<span class="w">                    </span><span class="nt">&lt;artifactId&gt;</span>maven-compiler-plugin<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">                    </span><span class="nt">&lt;version&gt;</span>3.10.1<span class="nt">&lt;/version&gt;</span>
<span class="w">                    </span><span class="nt">&lt;configuration&gt;</span>
<span class="w">                        </span><span class="nt">&lt;source&gt;</span>${maven.compiler.source}<span class="nt">&lt;/source&gt;</span>
<span class="w">                        </span><span class="nt">&lt;target&gt;</span>${maven.compiler.target}<span class="nt">&lt;/target&gt;</span>
<span class="w">                    </span><span class="nt">&lt;/configuration&gt;</span>
<span class="w">                </span><span class="nt">&lt;/plugin&gt;</span>
<span class="w">            </span><span class="nt">&lt;/plugins&gt;</span>
<span class="w">        </span><span class="nt">&lt;/pluginManagement&gt;</span>
<span class="w">    </span><span class="nt">&lt;/build&gt;</span>
<span class="nt">&lt;/project&gt;</span>
</code></pre></div>

<h3 id="子模块继承父POM">子模块继承父POM</h3>
<p>子模块通过 <code>&lt;parent&gt;</code> 声明父POM：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="cm">&lt;!-- 子模块：common/pom.xml --&gt;</span>
<span class="nt">&lt;project&gt;</span>
<span class="w">    </span><span class="nt">&lt;modelVersion&gt;</span>4.0.0<span class="nt">&lt;/modelVersion&gt;</span>

<span class="w">    </span><span class="cm">&lt;!-- 声明父POM --&gt;</span>
<span class="w">    </span><span class="nt">&lt;parent&gt;</span>
<span class="w">        </span><span class="nt">&lt;groupId&gt;</span>com.example<span class="nt">&lt;/groupId&gt;</span>
<span class="w">        </span><span class="nt">&lt;artifactId&gt;</span>parent-project<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">        </span><span class="nt">&lt;version&gt;</span>1.0-SNAPSHOT<span class="nt">&lt;/version&gt;</span>
<span class="w">        </span><span class="nt">&lt;relativePath&gt;</span>../pom.xml<span class="nt">&lt;/relativePath&gt;</span>
<span class="w">    </span><span class="nt">&lt;/parent&gt;</span>

<span class="w">    </span><span class="cm">&lt;!-- 子模块只需要定义 artifactId，groupId 和 version 从父继承 --&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>common<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;packaging&gt;</span>jar<span class="nt">&lt;/packaging&gt;</span>

<span class="w">    </span><span class="nt">&lt;dependencies&gt;</span>
<span class="w">        </span><span class="cm">&lt;!-- 不需要指定版本，从父POM的 dependencyManagement 继承 --&gt;</span>
<span class="w">        </span><span class="nt">&lt;dependency&gt;</span>
<span class="w">            </span><span class="nt">&lt;groupId&gt;</span>com.fasterxml.jackson.core<span class="nt">&lt;/groupId&gt;</span>
<span class="w">            </span><span class="nt">&lt;artifactId&gt;</span>jackson-databind<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">        </span><span class="nt">&lt;/dependency&gt;</span>
<span class="w">        </span><span class="nt">&lt;dependency&gt;</span>
<span class="w">            </span><span class="nt">&lt;groupId&gt;</span>junit<span class="nt">&lt;/groupId&gt;</span>
<span class="w">            </span><span class="nt">&lt;artifactId&gt;</span>junit<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">            </span><span class="nt">&lt;scope&gt;</span>test<span class="nt">&lt;/scope&gt;</span>
<span class="w">        </span><span class="nt">&lt;/dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;/dependencies&gt;</span>
<span class="nt">&lt;/project&gt;</span>
</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>子模块的 <code>groupId</code> 和 <code>version</code> 可以省略（从父继承），但 <code>artifactId</code> 必须指定（用于唯一标识子模块）。</p>
</blockquote>
<h3 id="relativePath-说明">relativePath 说明</h3>
<p><code>&lt;relativePath&gt;</code> 告诉Maven父POM的位置：</p>
<table>
<thead>
<tr>
<th>配置</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>&lt;relativePath&gt;../pom.xml&lt;/relativePath&gt;</code></td>
<td>父POM在上级目录（推荐）</td>
</tr>
<tr>
<td><code>&lt;relativePath/&gt;</code></td>
<td>从本地/远程仓库查找</td>

<p>在多模块项目中，父POM就在父目录，设置 <code>../pom.xml</code> 即可。</p>
</blockquote>
<h2 id="聚合-vs-继承">聚合 vs 继承</h2>
<h3 id="对比总览">对比总览</h3>
<table>
<thead>
<tr>
<th>对比维度</th>
<th>聚合（Aggregation）</th>
<th>继承（Inheritance）</th>
</tr>
</thead>
<tbody>
<tr>
<td>目的</td>
<td>统一构建所有子模块</td>
<td>统一配置，避免重复</td>
</tr>
<tr>
<td>配置方式</td>
<td><code>&lt;modules&gt;</code></td>
<td><code>&lt;parent&gt;</code></td>
</tr>
<tr>
<td>子模块定位</td>
<td>物理位置（目录）</td>
<td>逻辑位置（坐标）</td>
</tr>
<tr>
<td>子模块获取父配置</td>
<td>❌</td>
<td>✅</td>
</tr>
<tr>
<td>父模块包含代码</td>
<td>❌（仅组织）</td>
<td>❌（仅配置）</td>
</tr>
<tr>
<td>packaging类型</td>
<td><code>pom</code></td>
<td><code>pom</code></td>
</tr>
<tr>
<td>使用场景</td>
<td>组织多模块项目</td>
<td>复用公共配置</td>
</tr>
</tbody>
</table>
<h3 id="核心区别">核心区别</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    subgraph 聚合
        P1[父POM&lt;br/&gt;modules] --&gt; M1[模块A]
        P1 --&gt; M2[模块B]
        P1 --&gt; M3[模块C]
        Note1["父POM &lt;br/&gt;知道所有子模块的位置"]
    end

    subgraph 继承
        P2[父POM&lt;br/&gt;dependencyManagement&lt;br/&gt;pluginManagement] -.-&gt; C1[模块A&lt;br/&gt;继承配置]
        P2 -.-&gt; C2[模块B&lt;br/&gt;继承配置]
        P2 -.-&gt; C3[模块C&lt;br/&gt;继承配置]
        Note2["子模块 &lt;br/&gt;通过parent引用父POM"]
    end
</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>在多模块项目中，<strong>聚合和继承通常同时使用</strong>——父POM既用 <code>&lt;modules&gt;</code> 聚合子模块，子模块也用 <code>&lt;parent&gt;</code> 继承父配置。这是最经典的多模块项目模式。</p>
</blockquote>
<h3 id="同时使用聚合与继承">同时使用聚合与继承</h3>
<p>大多数多模块项目都会同时使用聚合和继承：</p>
<div class="codehilite"><pre><span></span><code>parent-project/
├── pom.xml                    # 既有 &lt;modules&gt; 聚合，也有公共配置供继承
├── common/
│   └── pom.xml                # 继承父POM，可被其他模块依赖
├── api/
│   └── pom.xml                # 继承父POM
├── service/
│   └── pom.xml                # 继承父POM，依赖common
└── web/
    └── pom.xml                # 继承父POM，依赖service
</code></pre></div>

<h2 id="多模块项目结构最佳实践">多模块项目结构最佳实践</h2>
<h3 id="典型分层架构">典型分层架构</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph 多模块项目
        P[parent&lt;br/&gt;父POM]
        P --&gt; C[common&lt;br/&gt;公共模块&lt;br/&gt;工具类/常量]
        P --&gt; A[api&lt;br/&gt;接口定义模块]
        P --&gt; S[service&lt;br/&gt;业务逻辑模块]
        P --&gt; W[web&lt;br/&gt;Web展示模块]
        S --&gt; C
        S --&gt; A
        W --&gt; S
    end
</code></pre></div>

<h3 id="按功能拆分-vs-按层次拆分">按功能拆分 vs 按层次拆分</h3>
<table>
<thead>
<tr>
<th>拆分方式</th>
<th>说明</th>
<th>适用场景</th>
</tr>
</thead>
<tbody>
<tr>

<h2 id="版本管理最佳实践">版本管理最佳实践</h2>
<h3 id="使用-properties-统一版本">使用 properties 统一版本</h3>
<p>在父POM中使用 <code>&lt;properties&gt;</code> 集中管理依赖版本：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;properties&gt;</span>
<span class="w">    </span><span class="nt">&lt;java.version&gt;</span>11<span class="nt">&lt;/java.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;jackson.version&gt;</span>2.13.0<span class="nt">&lt;/jackson.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;junit.version&gt;</span>4.13.2<span class="nt">&lt;/junit.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;httpclient.version&gt;</span>4.5.13<span class="nt">&lt;/httpclient.version&gt;</span>
<span class="w">    </span><span class="nt">&lt;spring.version&gt;</span>5.3.10<span class="nt">&lt;/spring.version&gt;</span>
<span class="nt">&lt;/properties&gt;</span>
</code></pre></div>

<h3 id="dependencyManagement-的最佳实践">dependencyManagement 的最佳实践</h3>
<ul>
<li><strong>只在父POM中定义</strong>：所有依赖版本在父POM的 <code>&lt;dependencyManagement&gt;</code> 中统一管理。</li>
<li><strong>子模块只声明不写版本</strong>：子模块只需 <code>&lt;groupId&gt;</code> 和 <code>&lt;artifactId&gt;</code>，版本从父继承。</li>
<li><strong>添加注释</strong>：在 <code>&lt;dependencyManagement&gt;</code> 中为每个依赖添加注释说明用途。</li>
</ul>
<h2 id="常见问题与解决方案">常见问题与解决方案</h2>
<h3 id="问题1循环依赖">问题1：循环依赖</h3>
<p><strong>现象：</strong> 模块A依赖模块B，模块B依赖模块A。</p>
<p><strong>解决方案：</strong></p>
<ul>
<li>检查模块职责划分是否合理</li>
<li>将相互依赖的部分抽取到新的公共模块中</li>
</ul>
<h3 id="问题2版本不一致">问题2：版本不一致</h3>
<p><strong>现象：</strong> 不同子模块使用了同一依赖的不同版本，导致运行时冲突。</p>
<p><strong>解决方案：</strong></p>
<ul>
<li>在父POM的 <code>&lt;dependencyManagement&gt;</code> 中统一管理所有版本</li>
<li>子模块不指定版本，从父继承</li>
</ul>
<h3 id="问题3构建顺序错误">问题3：构建顺序错误</h3>
<p><strong>现象：</strong> 构建时出现"找不到依赖"的错误。</p>
<p><strong>解决方案：</strong></p>
<ul>
<li>确保模块间的依赖关系在POM中正确声明</li>
<li>执行 <code>mvn clean install</code> 让Maven自动按依赖顺序构建</li>
</ul>

<h3 id="作业二聚合与继承概念理解">作业二：聚合与继承概念理解</h3>
<p>判断以下说法是否正确，并说明理由。</p>
<ol>
<li>聚合模块的 <code>&lt;packaging&gt;</code> 必须是 <code>jar</code>。</li>
<li>继承可以让子模块复用父POM中定义的依赖版本。</li>
<li>子模块必须显式声明 <code>groupId</code>，不能从父POM继承。</li>
<li>聚合是将多个子模块组织在一起统一构建，子模块之间没有依赖关系也可以聚合。</li>
<li><code>relativePath</code> 用于告诉Maven父POM的位置，如果省略则默认值为 <code>../pom.xml</code>。</li>
</ol>

<h3 id="作业三创建多模块项目">作业三：创建多模块项目</h3>
<p>创建一个多模块Maven项目，结构如下：</p>
<div class="codehilite"><pre><span></span><code>user-project/
├── pom.xml                    # 父POM（packaging=pom）
├── user-common/               # 公共模块
│   └── pom.xml
├── user-api/                  # API接口定义
│   └── pom.xml
└── user-service/              # 业务实现
    └── pom.xml
</code></pre></div>

<p><strong>要求：</strong></p>
<ol>
<li>父POM中定义：
   - 统一 <code>groupId</code>：<code>com.example</code>
   - 统一 <code>version</code>：<code>1.0-SNAPSHOT</code>
   - <code>&lt;modules&gt;</code> 聚合所有子模块
   - <code>&lt;properties&gt;</code> 定义 <code>java.version = 11</code>
   - <code>&lt;dependencyManagement&gt;</code> 管理 <code>junit</code> 版本为 <code>4.13.2</code></li>
<li>子模块 <code>user-api</code> 中定义一个接口 <code>UserService</code></li>
<li>子模块 <code>user-service</code> 依赖 <code>user-api</code>，并实现该接口</li>
<li>子模块 <code>user-common</code> 依赖 <code>user-api</code></li>
<li>所有子模块继承父POM</li>
</ol>
<p>验证：在父项目根目录执行 <code>mvn clean compile</code>，所有模块应编译成功。</p>
