<h3 id="配置脚本">配置脚本</h3>
<p><code>uv init</code> 生成的项目默认没有入口模块配置。要让项目可以通过 <code>uv run</code> 直接执行，或发布后提供命令行工具，需要在 <code>pyproject.toml</code> 中配置 <code>[project.scripts]</code>：</p>
<div class="codehilite lang-toml"><pre><span></span><code><span class="k">[project.scripts]</span>
<span class="c1"># 等号左边是命令名称，右边是 "模块路径:函数名"</span>
<span class="n">my-cli</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s2">"my_project:main"</span>
</code></pre></div>

<p>配置后：
- 项目内执行 <code>uv run my-cli</code> 即可调用 <code>my_project/__init__.py</code> 中的 <code>main()</code> 函数
- 发布到 PyPI 后，用户 <code>pip install</code> 安装即可在终端使用 <code>my-cli</code> 命令</p>
<h3 id="安装依赖">安装依赖</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 添加依赖</span>
uv<span class="w"> </span>add<span class="w"> </span>requests

<span class="c1"># 添加开发依赖</span>
uv<span class="w"> </span>add<span class="w"> </span>--dev<span class="w"> </span>pytest

<span class="c1"># 指定版本</span>
uv<span class="w"> </span>add<span class="w"> </span><span class="s2">"fastapi&gt;=0.100.0"</span>
</code></pre></div>

<p>执行 <code>uv add</code> 后，UV 会自动：</p>
<ol>
<li>解析依赖树，找到满足所有约束的最新版本</li>
<li>安装到当前项目的虚拟环境</li>
<li>更新 <code>pyproject.toml</code> 中的 <code>dependencies</code></li>
<li>生成/更新 <code>uv.lock</code> 锁定文件</li>
</ol>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 查看当前依赖树（类似 pipdeptree）</span>
uv<span class="w"> </span>tree
</code></pre></div>

</code></pre></div>

<h3 id="同步环境">同步环境</h3>
<p>如果别人拉取了你的代码，或者你想根据 <code>pyproject.toml</code> / <code>uv.lock</code> 重建环境：</p>
<div class="codehilite lang-shell"><pre><span></span><code>uv<span class="w"> </span>sync
</code></pre></div>

<p><code>uv sync</code> 会根据 <code>uv.lock</code>（如果有）或 <code>pyproject.toml</code> 安装所有依赖，确保环境与锁文件一致。</p>
<h3 id="运行项目">运行项目</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 运行指定文件</span>

<span class="c1"># 运行指定模块</span>

</code></pre></div>

<p><code>uv run</code> 会自动激活虚拟环境并执行命令，无需手动 <code>source .venv/bin/activate</code>。</p>
<h2 id="虚拟环境管理">虚拟环境管理</h2>
<p>UV 可以独立管理虚拟环境，而不必依赖项目。</p>
<h3 id="创建虚拟环境">创建虚拟环境</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 在当前目录创建 .venv</span>
uv<span class="w"> </span>venv

<span class="c1"># 指定目录</span>
uv<span class="w"> </span>venv<span class="w"> </span>my-env

<span class="c1"># 指定 Python 版本</span>
uv<span class="w"> </span>venv<span class="w"> </span>--python<span class="w"> </span><span class="m">3</span>.11

<span class="c1"># 指定 Python 版本范围</span>
uv<span class="w"> </span>venv<span class="w"> </span>--python<span class="w"> </span><span class="m">3</span>.10
</code></pre></div>

<h3 id="激活与退出">激活与退出</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 激活</span>
<span class="nb">source</span><span class="w"> </span>.venv/bin/activate

<span class="c1"># 退出</span>
deactivate
</code></pre></div>

<h3 id="查看环境信息">查看环境信息</h3>
<div class="codehilite lang-shell"><pre><span></span><code>uv<span class="w"> </span>venv<span class="w"> </span>--list<span class="w">   </span><span class="c1"># 显示所有管理的 venv（需要配合项目）</span>
</code></pre></div>

<blockquote>
<p>UV 会在项目根目录创建 <code>.venv</code>，并在 <code>pyproject.toml</code> 中记录。你不需要手动管理 <code>venv</code> 的路径——<code>uv run</code> 会自动检测。</p>
</blockquote>
<h3 id="UV-的项目级-vs-全局级">UV 的项目级 vs 全局级</h3>
<table>
<thead>
<tr>
<th style="text-align: left;">模式</th>
<th style="text-align: left;">命令</th>
<th style="text-align: left;">说明</th>
</tr>
</thead>
<tbody>
<tr>
<td style="text-align: left;">项目级</td>
<td style="text-align: left;"><code>uv add</code> / <code>uv sync</code> / <code>uv run</code></td>
<td style="text-align: left;">关联 <code>pyproject.toml</code>，依赖写入项目</td>
</tr>
<tr>
<td style="text-align: left;">全局级</td>
<td style="text-align: left;"><code>uv pip install</code> / <code>uv venv</code></td>
<td style="text-align: left;">独立于任何项目，像传统 pip 一样使用</td>
</tr>
</tbody>
</table>
<blockquote>
<p>UV 的全局模式兼容 pip 的用法。如果你有现成的 <code>requirements.txt</code>：</p>
<p><code>shell
uv pip install -r requirements.txt</code></p>
<p>项目模式比全局模式更推荐使用。</p>
</blockquote>
<h3 id="全局缓存">全局缓存</h3>
<p>UV 使用全局缓存（<code>~/.cache/uv</code>）来存储下载的包，多个项目共享同一份缓存。</p>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 查看缓存信息</span>
uv<span class="w"> </span>cache<span class="w"> </span>dir

<span class="c1"># 清理缓存</span>
uv<span class="w"> </span>cache<span class="w"> </span>clean
</code></pre></div>

<h2 id="Running-Tools-无需安装即可运行">Running Tools —— 无需安装即可运行</h2>
<p>在开发中经常需要临时运行一些工具，比如 <code>black</code>、<code>ruff</code>、<code>pre-commit</code> 等。传统做法是先 <code>pip install</code>，用完再卸载。UV 提供了更优雅的方式：</p>
<h3 id="uvx-一键运行">uvx —— 一键运行</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 运行一个工具，无需安装</span>
uvx<span class="w"> </span>ruff<span class="w"> </span>check<span class="w"> </span>.

<span class="c1"># 等价于传统的</span>
<span class="c1"># pip install ruff &amp;&amp; ruff check . &amp;&amp; pip uninstall ruff</span>

<span class="c1"># 指定版本</span>
uvx<span class="w"> </span>bandit@1.7.5<span class="w"> </span>.

<span class="c1"># 传递参数（跟在 `--` 后面）</span>
uvx<span class="w"> </span>cowsay<span class="w"> </span>--<span class="w"> </span><span class="s2">"Hello, UV!"</span>
</code></pre></div>

<p><code>uvx</code> 会：</p>
<ol>
<li>在临时虚拟环境中安装指定包</li>
<li>运行对应命令</li>
<li>结束后清理环境</li>
</ol>
<h3 id="uv-tool-持久安装-CLI-工具">uv tool —— 持久安装 CLI 工具</h3>
<p>如果你想长期使用一个工具：</p>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 安装</span>
uv<span class="w"> </span>tool<span class="w"> </span>install<span class="w"> </span>ruff

<span class="c1"># 运行</span>
ruff<span class="w"> </span>check<span class="w"> </span>.

<span class="c1"># 查看所有安装的工具</span>
uv<span class="w"> </span>tool<span class="w"> </span>list

<span class="c1"># 更新</span>
uv<span class="w"> </span>tool<span class="w"> </span>upgrade<span class="w"> </span>ruff

<span class="c1"># 卸载</span>
uv<span class="w"> </span>tool<span class="w"> </span>uninstall<span class="w"> </span>ruff
</code></pre></div>

<h3 id="在项目中添加工具依赖">在项目中添加工具依赖</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 将工具作为开发依赖添加到项目中</span>
uv<span class="w"> </span>add<span class="w"> </span>--dev<span class="w"> </span>ruff<span class="w"> </span>black<span class="w"> </span>mypy
</code></pre></div>

<p>然后在项目中：</p>
<div class="codehilite lang-shell"><pre><span></span><code>uv<span class="w"> </span>run<span class="w"> </span>ruff<span class="w"> </span>check<span class="w"> </span>.
uv<span class="w"> </span>run<span class="w"> </span>black<span class="w"> </span>.
uv<span class="w"> </span>run<span class="w"> </span>mypy<span class="w"> </span>src/
</code></pre></div>

<blockquote>
<p>通过 <code>uv add --dev</code> 安装的工具，其他协作者执行 <code>uv sync</code> 后同样可用，这是团队协作推荐的方式。</p>
</blockquote>
<h2 id="构建与发布">构建与发布</h2>
<p>UV 内置了构建和发布功能，完全替代了 <code>build</code> + <code>twine</code>。</p>
<h3 id="构建">构建</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 构建 sdist 和 wheel</span>
uv<span class="w"> </span>build

<span class="c1"># 产物在 dist/ 目录下</span>
ls<span class="w"> </span>dist/
<span class="c1"># my_project-0.1.0.tar.gz</span>
<span class="c1"># my_project-0.1.0-py3-none-any.whl</span>
</code></pre></div>

<blockquote>
<p><code>uv build</code> 会读取 <code>pyproject.toml</code> 中的 <code>[build-system]</code> 配置，使用后端工具（如 <code>hatchling</code>）完成构建。</p>
</blockquote>
<h3 id="发布">发布</h3>
<div class="codehilite lang-shell"><pre><span></span><code><span class="c1"># 发布到 PyPI</span>
uv<span class="w"> </span>publish

<span class="c1"># 指定 token（推荐用环境变量）</span>
<span class="nv">UV_PUBLISH_TOKEN</span><span class="o">=</span>pypi-xxxxx<span class="w"> </span>uv<span class="w"> </span>publish

<span class="c1"># 发布到私有仓库</span>
uv<span class="w"> </span>publish<span class="w"> </span><span class="se">\</span>
<span class="w">  </span>--publish-url<span class="w"> </span>私有仓库地址<span class="se">\</span>
<span class="w">  </span>--username<span class="w"> </span>你的用户名<span class="se">\</span>
<span class="w">  </span>--password<span class="w"> </span>你的密码<span class="se">\</span>
<span class="w">  </span>dist/*
</code></pre></div>

<blockquote>
<p><code>uv publish</code> 直接替代了 <code>twine upload</code>。</p>
<p>首次发布需要先在 pypi.org 注册账号并创建 API token，UV 也支持使用 <code>.pypirc</code> 配置文件。</p>
</blockquote>
<h2 id="Makefile-统一项目命令入口">Makefile —— 统一项目命令入口</h2>
<blockquote>
<p><code>make</code> 是 macOS 和 Linux 系统自带的工具，但 Windows 默认没有。Windows 用户可以按以下方式安装：</p>
<p>```shell</p>
<h1 id="方式一Chocolatey推荐">方式一：Chocolatey（推荐）</h1>
<p>choco install make</p>
<h1 id="方式二winget">方式二：winget</h1>
<p>winget install GnuWin32.Make</p>
<h1 id="方式三通过-Git-Bash-安装安装-Git-时勾选-Git-Bash-即可">方式三：通过 Git Bash 安装（安装 Git 时勾选 Git Bash 即可）</h1>
<h1 id="然后在-Git-Bash-中运行-make或将其加入-PATH">然后在 Git Bash 中运行 make，或将其加入 PATH</h1>
<p>```</p>
<p>安装后验证：</p>
<p><code>shell
make --version</code></p>
</blockquote>
<p>虽然 UV 提供了丰富的命令，但团队成员（或未来的你）仍需要记住 <code>uv run pytest</code>、<code>uv run ruff check</code>、<code>uv build</code> 等一串命令。<strong>Makefile</strong> 可以把常用操作封装成简短一致的名字。</p>
<h3 id="一个典型的-Python-UV-项目的-Makefile">一个典型的 Python + UV 项目的 Makefile</h3>
<div class="codehilite lang-makefile"><pre><span></span><code><span class="nf">.PHONY</span><span class="o">:</span><span class="w"> </span><span class="n">install</span> <span class="n">test</span> <span class="n">lint</span> <span class="n">format</span> <span class="n">build</span> <span class="n">clean</span>

<span class="c"># 安装依赖</span>
<span class="nf">install</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>sync

<span class="c"># 运行测试</span>
<span class="nf">test</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>run<span class="w"> </span>pytest

<span class="c"># 代码检查</span>
<span class="nf">lint</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>run<span class="w"> </span>ruff<span class="w"> </span>check<span class="w"> </span>.

<span class="c"># 自动格式化</span>
<span class="nf">format</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>run<span class="w"> </span>ruff<span class="w"> </span>format<span class="w"> </span>.

<span class="c"># 构建分发包</span>
<span class="nf">build</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>build

<span class="c"># 清理构建产物和缓存</span>
<span class="nf">clean</span><span class="o">:</span>
<span class="w">    </span>rm<span class="w"> </span>-rf<span class="w"> </span>dist/
<span class="w">    </span>rm<span class="w"> </span>-rf<span class="w"> </span>.pytest_cache/
<span class="w">    </span>uv<span class="w"> </span>cache<span class="w"> </span>clean
</code></pre></div>

<p>使用方式：</p>
<div class="codehilite lang-shell"><pre><span></span><code>make<span class="w"> </span>install<span class="w">   </span><span class="c1"># uv sync</span>
make<span class="w"> </span><span class="nb">test</span><span class="w">      </span><span class="c1"># uv run pytest</span>
make<span class="w"> </span>lint<span class="w">      </span><span class="c1"># uv run ruff check .</span>
make<span class="w"> </span>format<span class="w">    </span><span class="c1"># uv run ruff format .</span>
make<span class="w"> </span>build<span class="w">     </span><span class="c1"># uv build</span>
make<span class="w"> </span>clean<span class="w">     </span><span class="c1"># 清理</span>
</code></pre></div>

<h3 id="带参数的目标">带参数的目标</h3>
<div class="codehilite lang-makefile"><pre><span></span><code><span class="nf">.PHONY</span><span class="o">:</span><span class="w"> </span><span class="n">publish</span>

<span class="c"># 发布到指定仓库，用法: make publish REPO_URL=https://...</span>
<span class="nf">publish</span><span class="o">:</span>
<span class="w">    </span>uv<span class="w"> </span>publish<span class="w"> </span>--publish-url<span class="w"> </span><span class="k">$(</span>REPO_URL<span class="k">)</span>
</code></pre></div>

<h3 id="串联多个任务">串联多个任务</h3>
<div class="codehilite lang-makefile"><pre><span></span><code><span class="nf">.PHONY</span><span class="o">:</span><span class="w"> </span><span class="n">ci</span>

<span class="c"># CI 流程：检查 → 测试 → 构建</span>
<span class="nf">ci</span><span class="o">:</span><span class="w"> </span>
<span class="w">    </span>lint<span class="w"> </span><span class="nb">test</span><span class="w"> </span>build
</code></pre></div>

<div class="codehilite lang-shell"><pre><span></span><code>make<span class="w"> </span>ci<span class="w">   </span><span class="c1"># 依次执行 lint → test → build</span>
</code></pre></div>

<blockquote>
<p>Makefile 的核心价值是<strong>约定</strong>：不管项目用什么工具链，新人只需 <code>make test</code> 就能跑测试，<code>make build</code> 就能构建。对于 CI/CD 也天然适配。</p>
</blockquote>
