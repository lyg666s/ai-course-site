<h4 id="SQL-注入">SQL 注入</h4>
<p>上面的 <code>search_products</code> 直接把用户输入拼进了 SQL 字符串。来验证一下：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="c1"># 正常搜索</span>
<span class="k">await</span> <span class="n">search_products</span><span class="p">(</span><span class="s2">"iPhone"</span><span class="p">)</span>
</code></pre></div>

<p>输出符合预期：</p>
<div class="codehilite"><pre><span></span><code>=== 搜索 'iPhone' ===
  [1] iPhone 16 - Apple
  [2] iPhone 15 - Apple
</code></pre></div>

<p>现在换攻击者的输入：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="k">await</span> <span class="n">search_products</span><span class="p">(</span><span class="s2">"%' OR 1=1 --"</span><span class="p">)</span>
</code></pre></div>

<p>拼接后的 SQL：</p>
<div class="codehilite lang-sql"><pre><span></span><code><span class="k">SELECT</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="k">FROM</span><span class="w"> </span><span class="n">product</span><span class="w"> </span><span class="k">WHERE</span><span class="w"> </span><span class="n">name</span><span class="w"> </span><span class="k">LIKE</span><span class="w"> </span><span class="s1">'%%'</span><span class="w"> </span><span class="k">OR</span><span class="w"> </span><span class="mi">1</span><span class="o">=</span><span class="mi">1</span><span class="w"> </span><span class="c1">-- %'</span>
</code></pre></div>

<p><code>OR 1=1</code> 永远为真，<code>--</code> 注释掉后续内容——<strong>所有数据被暴露</strong>：</p>
<div class="codehilite"><pre><span></span><code>  [1] iPhone 16 - Apple
  [2] iPhone 15 - Apple
  [3] Galaxy S25 - Samsung
  [4] Xiaomi 15 - Xiaomi
</code></pre></div>

<p>这还只是查询。同样的拼接方式在<strong>按 ID 删除</strong>里一样有效：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="c1"># 正常删除，删掉 id=3（Galaxy S25）</span>
<span class="k">await</span> <span class="n">delete_product_by_id</span><span class="p">(</span><span class="s2">"3"</span><span class="p">)</span>
<span class="c1"># 输出：✅ 删除完成，id=3</span>
</code></pre></div>

<p>现在攻击者传入：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="k">await</span> <span class="n">delete_product_by_id</span><span class="p">(</span><span class="s2">"1 OR 1=1"</span><span class="p">)</span>
</code></pre></div>

<p>拼接后的 SQL：</p>
<div class="codehilite lang-sql"><pre><span></span><code><span class="k">DELETE</span><span class="w"> </span><span class="k">FROM</span><span class="w"> </span><span class="n">product</span><span class="w"> </span><span class="k">WHERE</span><span class="w"> </span><span class="n">id</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="mi">1</span><span class="w"> </span><span class="k">OR</span><span class="w"> </span><span class="mi">1</span><span class="o">=</span><span class="mi">1</span>
</code></pre></div>

<p><code>WHERE id = 1 OR 1=1</code> 匹配<strong>所有行</strong>——整张表被清空：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="c1"># 再查询，数据已经没了</span>
<span class="k">await</span> <span class="n">search_products</span><span class="p">(</span><span class="s2">"iPhone"</span><span class="p">)</span>
<span class="c1"># 输出：（无结果，数据已被删光）</span>
</code></pre></div>

<p>这就是经典的 <strong>SQL 注入</strong>——攻击者通过篡改输入改变 SQL 语句的意图，轻则偷数据，重则删库跑路。</p>
<h4 id="修复参数化绑定">修复：参数化绑定</h4>
<p>解决方案是：<strong>SQL 结构与数据分离</strong>。用 <code>:参数名</code> 作为占位符，通过字典传入值：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="k">async</span> <span class="k">def</span><span class="w"> </span><span class="nf">search_products</span><span class="p">(</span><span class="n">keyword</span><span class="p">:</span> <span class="nb">str</span><span class="p">):</span>
<span class="w">    </span><span class="sd">"""按关键字搜索商品——参数化绑定，安全"""</span>
    <span class="n">engine</span> <span class="o">=</span> <span class="n">get_engine</span><span class="p">()</span>
    <span class="k">async</span> <span class="k">with</span> <span class="n">engine</span><span class="o">.</span><span class="n">connect</span><span class="p">()</span> <span class="k">as</span> <span class="n">conn</span><span class="p">:</span>
        <span class="n">result</span> <span class="o">=</span> <span class="k">await</span> <span class="n">conn</span><span class="o">.</span><span class="n">execute</span><span class="p">(</span>
            <span class="n">text</span><span class="p">(</span><span class="s2">"SELECT * FROM product WHERE name LIKE :keyword"</span><span class="p">),</span>
            <span class="p">{</span><span class="s2">"keyword"</span><span class="p">:</span> <span class="sa">f</span><span class="s2">"%</span><span class="si">{</span><span class="n">keyword</span><span class="si">}</span><span class="s2">%"</span><span class="p">},</span>
        <span class="p">)</span>
        <span class="n">rows</span> <span class="o">=</span> <span class="n">result</span><span class="o">.</span><span class="n">fetchall</span><span class="p">()</span>
        <span class="k">for</span> <span class="n">row</span> <span class="ow">in</span> <span class="n">rows</span><span class="p">:</span>
            <span class="nb">print</span><span class="p">(</span><span class="sa">f</span><span class="s2">"  [</span><span class="si">{</span><span class="n">row</span><span class="o">.</span><span class="n">id</span><span class="si">}</span><span class="s2">] </span><span class="si">{</span><span class="n">row</span><span class="o">.</span><span class="n">name</span><span class="si">}</span><span class="s2"> - </span><span class="si">{</span><span class="n">row</span><span class="o">.</span><span class="n">brand</span><span class="si">}</span><span class="s2">"</span><span class="p">)</span>
</code></pre></div>

<p>再用恶意输入试一次：</p>
<div class="codehilite lang-python lang-norun"><pre><span></span><code><span class="k">await</span> <span class="n">search_products</span><span class="p">(</span><span class="s2">"%' OR 1=1 --"</span><span class="p">)</span>
<span class="c1"># 输出：（无结果，%' OR 1=1 -- 被当作普通字符串匹配，不会命中任何商品名）</span>
</code></pre></div>

<p>原理：参数化绑定将 SQL 模板和参数值<strong>分开发送</strong>给数据库。数据库先解析 SQL 结构，再把参数值作为<strong>纯数据</strong>填入。无论攻击者输入什么，都不会被当作 SQL 指令执行。</p>
<p>手写 SQL 能跑，但两个核心问题摆在这里：一是注入风险，二是写字符串容易出错、没有 IDE 检查和补全。下一节引入 Core 表达式来解决这两个问题。</p>
<h4 id="总结">总结</h4>
<p>使用<code>RAW SQL</code>会带来以下问题：</p>
<ol>
<li>开发成本高</li>
<li>易出错</li>
<li>有注入风险</li>
<li>无法适配不同数据库</li>
</ol>
<p>但由于其高性能和极大的灵活性，仍然会有小概率用到</p>

<h2 id="执行时机">执行时机</h2>
<p>session 在下面的情况下会触发执行 SQL</p>
<ol>
<li>
<p><code>session.flush()</code>，执行记录的操作，但不提交</p>
</li>
<li>
<p><code>session.commit()</code>，先自动<code>flush</code>，再提交</p>
</li>
<li>
<p><code>session.execute()</code>，执行传入的 SQL 语句，不提交</p>
</li>
</ol>
<ul>
<li>当<code>autoflush=True</code>，则会先将 session 中 pending 的操作 <code>flush</code> 到数据库，再执行传入的 SQL，这是默认值</li>
<li>当<code>autoflush=False</code>，仅执行传入的 SQL，pending 操作保留在 session 中不动</li>
</ul>
<ol start="4">
<li><code>模型对象.字段</code>，当<code>expire_on_commit=True</code>时，可能会触发执行，不提交</li>
</ol>
<p>当 session 提交后，它会把 session 当中关联的模型对象的每一个字段都标记为过期，因为这些字段可能已经跟数据库不一样了。后续读取这些字段的时候，它会重新触发查询，将该对象的所有字段同步为数据库的字段值。</p>
<p>这一切的前提条件是要开启<code>expire_on_commit=True</code></p>
<p>开启这个配置会损耗性能，同时会带来一些其他问题，所以说往往会关闭。</p>
<ol start="5">
<li><code>session.refresh(模型对象)</code>，同步模型对象，不提交</li>
</ol>
<ul>
<li>将数据库真实的值同步到模型对象。当<code>expire_on_commit=False</code>时，才可能需要使用该方法</li>
</ul>
<h2 id="总结_2">总结</h2>
<ol>
<li>简单 CRUD 用 ORM 更顺手，复杂查询（聚合、批量更新）可混用 Core 表达式，前两者都难以处理的情况下，可以考虑使用 RAW SQL，但要注意 SQL 注入问题</li>
<li>耗时操作（比如I/O）尽量不要放到一次连接中</li>
<li><code>session</code> 的能力总结：</li>
<li>模型结合</li>
<li>统一管理事务</li>
<li>记录操作、统一执行</li>
</ol>
