<h2 id="系统监控概述">系统监控概述</h2>
<h3 id="为什么需要系统监控">为什么需要系统监控</h3>
<p>在应用上线后，我们需要实时了解应用的运行状态：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    A[应用上线] --&gt; B{运行状态如何？}
    B --&gt; C[服务是否存活？]
    B --&gt; D[内存是否充足？]
    B --&gt; E[请求响应是否正常？]
    B --&gt; F[数据库连接是否可用？]
    B --&gt; G[有哪些Bean被加载？]

    style B fill:#ffcdd2
</code></pre></div>

<p>如果缺乏监控手段，问题往往只能等到用户反馈时才发现，排查困难、影响面大。</p>
<table>
<thead>
<tr>
<th>场景</th>
<th>没有监控</th>
<th>有监控</th>
</tr>
</thead>
<tbody>
<tr>
<td>服务宕机</td>
<td>用户反馈才知道</td>
<td>立即告警，快速定位</td>
</tr>
<tr>
<td>内存泄漏</td>
<td>OOM 后才发现</td>
<td>提前发现增长趋势</td>
</tr>
<tr>
<td>慢接口</td>
<td>用户投诉后排查</td>
<td>实时查看请求耗时</td>
</tr>
<tr>
<td>配置错误</td>
<td>上线后才发现</td>
<td>查看 /env 确认配置</td>
</tr>
</tbody>
</table>
<h3 id="什么是-Spring-Boot-Actuator">什么是 Spring Boot Actuator</h3>
<p><strong>Spring Boot Actuator</strong> 是 Spring Boot 提供的<strong>生产级监控</strong>模块，通过一组 HTTP 端点（Endpoint）暴露应用的运行信息，包括健康状态、指标数据、配置信息、Bean 列表等。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph 应用
        App[图书管理系统]
        Actuator[Actuator]
        App --&gt; Actuator
    end

    subgraph 端点
        H[/health/]
        M[/metrics/]
        E[/env/]
        B[/beans/]
    end

    Actuator --&gt; H
    Actuator --&gt; M
    Actuator --&gt; E
    Actuator --&gt; B

    style Actuator fill:#e8f5e9
</code></pre></div>

</blockquote>
<p>从 Spring Boot 2.6 开始，info 端点中的 env 贡献者（用于显示 info.<em> 属性）默认被禁用了。这意味着，即使你正确配置了 info.app.</em> 属性，访问 /actuator/info 也只会得到一个空的 {}。要启用它，必须在配置中添加 management.info.env.enabled=true。</p>
<div class="codehilite"><pre><span></span><code>management:
  info:
    env:

<h3 id="heapdump-堆转储">/heapdump —— 堆转储</h3>
<p>下载堆内存快照（HProf 格式），用于离线分析内存泄漏。</p>
<div class="codehilite"><pre><span></span><code>GET /actuator/heapdump
</code></pre></div>

<p>浏览器会载 <code>heapdump.hprof</code> 文件，可使用 Eclipse MAT 或 VisualVM 分析。</p>
<blockquote>
<p>[!CAUTION]</p>
<p><code>/heapdump</code> 会生成整个堆的快照，文件可能很大（几百 MB 甚至 GB），且下载期间会暂停应用（STW）。生产环境慎用。</p>
</blockquote>
<p>从 Spring Boot 3.5 开始，heapdump 端点的默认访问权限被设置为 NONE，这是一种安全改进。这意味着，仅仅“暴露”和“启用”是不够的，还必须显式配置其访问权限。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nl">management</span><span class="p">:</span>
<span class="w">  </span><span class="n">endpoint</span><span class="p">:</span>
<span class="w">    </span><span class="n">heapdump</span><span class="p">:</span>
<span class="w">      </span><span class="n">access</span><span class="p">:</span><span class="w"> </span><span class="n">unrestricted</span><span class="w"> </span><span class="err">#</span><span class="w"> </span><span class="mf">3.5</span><span class="o">+</span><span class="w"> </span><span class="n">必须显式设置为</span><span class="w"> </span><span class="n">unrestricted</span><span class="err">，</span><span class="n">否则无法访问</span>
</code></pre></div>

<h2 id="注意事项">注意事项</h2>
<h3 id="1-不要暴露所有端点">1. 不要暴露所有端点</h3>
<p>生产环境使用 <code>include: health,info,metrics</code> 等必要端点即可，避免暴露 <code>env</code>、<code>beans</code>、<code>heapdump</code> 等敏感端点。</p>
<h3 id="2-env-可能泄露敏感信息">2. /env 可能泄露敏感信息</h3>
<p><code>/env</code> 端点可能包含数据库密码、API 密钥等。建议：
- 隐藏敏感值（<code>show-values: never</code>）
- 或不暴露 <code>/env</code> 端点</p>
<h3 id="3-Actuator-端口独立">3. Actuator 端口独立</h3>
<p>生产环境建议使用独立端口访问 Actuator，避免与业务流量混合。</p>
<h3 id="4-健康检查的性能开销">4. 健康检查的性能开销</h3>
<p>健康检查会检查数据库、磁盘等组件，频繁调用有一定开销。可以配置缓存：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">management</span><span class="p">:</span>
<span class="w">  </span><span class="nt">endpoint</span><span class="p">:</span>
<span class="w">    </span><span class="nt">health</span><span class="p">:</span>
<span class="w">      </span><span class="nt">cache</span><span class="p">:</span>
<span class="w">        </span><span class="nt">time-to-live</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">5s</span>
</code></pre></div>

<h3 id="5-不要禁用所有端点">5. 不要禁用所有端点</h3>
<p>如果为了安全禁用所有端点，会导致无法监控应用。建议暴露必要端点，通过安全配置保护。</p>
<h3 id="6-日志级别的动态修改">6. 日志级别的动态修改</h3>
<p>动态修改日志级别是临时手段，应用重启后会恢复。如果修改后忘记恢复，可能产生大量日志。</p>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>系统监控的意义</strong>：实时了解应用运行状态，快速定位问题</li>
<li><strong>Spring Boot Actuator 集成</strong>：添加依赖即可使用</li>
<li><strong>常用端点</strong>：
   - <code>/health</code>：健康状态
   - <code>/info</code>：应用信息
   - <code>/metrics</code>：指标数据
   - <code>/env</code>：环境属性
   - <code>/beans</code>：Bean 列表
   - <code>/mappings</code>：请求映射
   - <code>/loggers</code>：日志级别管理
   - <code>/threaddump</code>：线程快照
   - <code>/heapdump</code>：堆转储</li>
<li><strong>端点配置</strong>：
   - 暴露哪些端点（include/exclude）
   - 自定义端点路径
   - 独立端口配置</li>
<li><strong>安全配置</strong>：限制访问权限，隐藏敏感信息</li>
<li><strong>实战应用</strong>：为图书管理系统开启完整的监控能力</li>
</ol>
