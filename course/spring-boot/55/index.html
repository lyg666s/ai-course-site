系统监控概述

为什么需要系统监控

在应用上线后，我们需要实时了解应用的运行状态：

flowchart LR
    A[应用上线] --> B{运行状态如何？}
    B --> C[服务是否存活？]
    B --> D[内存是否充足？]
    B --> E[请求响应是否正常？]
    B --> F[数据库连接是否可用？]
    B --> G[有哪些Bean被加载？]

    style B fill:#ffcdd2

如果缺乏监控手段，问题往往只能等到用户反馈时才发现，排查困难、影响面大。

场景 没有监控 有监控
服务宕机 用户反馈才知道 立即告警，快速定位
内存泄漏 OOM 后才发现 提前发现增长趋势
慢接口 用户投诉后排查 实时查看请求耗时
配置错误 上线后才发现 查看 /env 确认配置

什么是 Spring Boot Actuator

Spring Boot Actuator 是 Spring Boot 提供的生产级监控模块，通过一组 HTTP 端点（Endpoint）暴露应用的运行信息，包括健康状态、指标数据、配置信息、Bean 列表等。

Actuator 的核心能力

能力 说明
健康检查 应用及依赖组件（数据库、缓存等）的健康状态
指标监控 JVM、HTTP 请求、数据库连接池等指标
配置查看 环境变量、配置属性、系统属性
Bean 管理 查看容器中所有 Bean 的信息
请求映射 查看所有 URL 与 Controller 的映射关系
日志管理 动态调整日志级别
线程快照 查看线程堆栈
堆转储 下载堆内存快照

Actuator 快速集成

1. 添加依赖

在 pom.xml 中添加 Actuator Starter：

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>

2. 启动应用

添加依赖后，无需任何配置即可访问默认端点：

http://localhost:8080/actuator

默认响应：

{
    "_links": {
        "self": {
            "href": "http://localhost:8080/actuator",
            "templated": false
        },
        "health": {
            "href": "http://localhost:8080/actuator/health",
            "templated": false
        },
        "health-path": {
            "href": "http://localhost:8080/actuator/health/{*path}",
            "templated": true
        }
    }
}

[!NOTE] 默认情况下，Spring Boot 只暴露 /health 端点（通过 HTTP）。其他端点虽然在应用内部存在，但不会被 Web 访问。需要通过配置显式暴露。

3. 查看健康状态

GET http://localhost:8080/actuator/health

响应：

{
    "status": "UP"
}

/health —— 健康状态

用于检查应用及其依赖组件的健康状态。

{
    "status": "UP",
    "components": {
        "db": {
            "status": "UP",
            "details": {
                "database": "PostgreSQL",
                "validationQuery": "isValid()"
            }
        },
        "diskSpace": {
            "status": "UP",
            "details": {
                "total": 500107862016,
                "free": 300107862016,
                "threshold": 10485760
            }
        },
        "ping": {
            "status": "UP"
        }
    }
}

健康状态的可能值：

状态 说明
UP 正常
DOWN 异常
OUT_OF_SERVICE 暂停服务
UNKNOWN 未知

[!NOTE] 默认情况下，健康检查只返回 status，不显示详细信息。需要在配置中开启 show-details。

management:
  endpoint:
    health:
      show-details: always   # always / never / when-authorized

/info —— 应用信息

展示应用的自定义信息，需要在配置中定义：

info:
  app:
    name: 图书管理系统
    version: 1.0.0
    author: 技术团队
    description: 基于 Spring Boot 的图书管理系统

访问 GET /actuator/info：

{
    "app": {
        "name": "图书管理系统",
        "version": "1.0.0",
        "author": "技术团队",
        "description": "基于 Spring Boot 的图书管理系统"
    }
}

默认 info 端点不会自动暴露，可以通过 application.yml 配置暴露哪些端点：

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,env,beans,loggers
        # 或使用 "*" 暴露所有端点
        # exclude: env,beans   # 排除特定端点
配置 说明
include: health,info 只暴露指定端点
include: "*" 暴露所有端点
exclude: env,beans 排除指定端点
不配置 只暴露 /health

[!CAUTION]

生产环境不要使用 include: "*"，应根据需要暴露必要的端点，避免敏感信息泄露。

从 Spring Boot 2.6 开始，info 端点中的 env 贡献者（用于显示 info. 属性）默认被禁用了。这意味着，即使你正确配置了 info.app. 属性，访问 /actuator/info 也只会得到一个空的 {}。要启用它，必须在配置中添加 management.info.env.enabled=true。

management:
  info:
    env:
      enabled: true   # 必须开启，否则 info.* 属性不会显示

/heapdump —— 堆转储

下载堆内存快照（HProf 格式），用于离线分析内存泄漏。

GET /actuator/heapdump

浏览器会载 heapdump.hprof 文件，可使用 Eclipse MAT 或 VisualVM 分析。

[!CAUTION]

/heapdump 会生成整个堆的快照，文件可能很大（几百 MB 甚至 GB），且下载期间会暂停应用（STW）。生产环境慎用。

从 Spring Boot 3.5 开始，heapdump 端点的默认访问权限被设置为 NONE，这是一种安全改进。这意味着，仅仅“暴露”和“启用”是不够的，还必须显式配置其访问权限。

management:
  endpoint:
    heapdump:
      access: unrestricted # 3.5+ 必须显式设置为 unrestricted，否则无法访问

端点配置

1. 自定义端点路径

修改基础路径：

management:
  endpoints:
    web:
      base-path: /manage   # 默认 /actuator

修改后端点地址变为 http://localhost:8080/manage/health。

修改特定端点路径：

management:
  endpoints:
    web:
      path-mapping:
        health: status   # 将 /health 改为 /status

2. 修改 Actuator 端口

如果不想让 Actuator 与业务共享端口，可以配置独立端口：

management:
  server:
    port: 9090   # Actuator 独立端口

配置后，Actuator 端点可通过 http://localhost:9090/actuator/health 访问，与业务端口 8080 分开。

[!NOTE] 使用独立端口时，如果配置了 management.server.port，还需要配置 management.server.address 限制访问地址（如只允许内网访问）。

3. 启用/禁用端点

management:
  endpoint:
    health:
      enabled: true
    beans:
      enabled: false   # 禁用 beans 端点

4. 端点缓存

Actuator 端点默认会缓存响应，可以调整缓存时间：

management:
  endpoint:
    health:
      cache:
        time-to-live: 5s   # 健康检查结果缓存 5 秒

实战：为图书管理系统开启监控

需求

为图书管理系统集成 Actuator，实现以下监控能力： 1. 暴露健康检查、指标、环境、Bean 等常用端点 2. 配置健康检查显示详细信息 3. 配置 /info 展示应用信息 4. 使用独立端口 9090 访问 Actuator

实现步骤

步骤一：添加依赖

<dependency>
    <groupId>org.springframework.boot</groupId>

</dependency>

步骤二：配置 Actuator

info:

端点安全配置

1. 隐藏敏感端点的值

management:
  endpoint:
    env:
      show-values: never   # 隐藏配置值
    configprops:
      show-values: never

2. 使用独立端口 + 内网地址

management:
  server:
    port: 9090
    address: 127.0.0.1   # 只监听本地

[!NOTE] 生产环境建议将 Actuator 端口设为独立端口，并限制只允许内网访问，避免暴露给公网。

3. 自定义健康检查的安全级别

management:
  endpoint:
    health:
      show-details: when-authorized   # 认证用户才能看到详情
      roles: ADMIN                     # 只有 ADMIN 角色能查看详情

4. 端点访问控制建议

端点 生产环境建议
/health 允许访问（用于负载均衡健康检查）
/info 允许访问（展示应用基本信息）
/metrics 仅内网访问
/env 隐藏或不暴露
/beans 隐藏或不暴露
/heapdump 隐藏或不暴露
/loggers 仅内网访问

注意事项

1. 不要暴露所有端点

生产环境使用 include: health,info,metrics 等必要端点即可，避免暴露 env、beans、heapdump 等敏感端点。

2. /env 可能泄露敏感信息

/env 端点可能包含数据库密码、API 密钥等。建议： - 隐藏敏感值（show-values: never） - 或不暴露 /env 端点

3. Actuator 端口独立

生产环境建议使用独立端口访问 Actuator，避免与业务流量混合。

4. 健康检查的性能开销

健康检查会检查数据库、磁盘等组件，频繁调用有一定开销。可以配置缓存：

management:
  endpoint:
    health:
      cache:
        time-to-live: 5s

5. 不要禁用所有端点

如果为了安全禁用所有端点，会导致无法监控应用。建议暴露必要端点，通过安全配置保护。

6. 日志级别的动态修改

动态修改日志级别是临时手段，应用重启后会恢复。如果修改后忘记恢复，可能产生大量日志。
