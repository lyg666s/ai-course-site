<h2 id="请求映射注解">请求映射注解</h2>

<h3 id="路径映射的匹配规则">路径映射的匹配规则</h3>

<thead>
<tr>
<th>规则</th>
<th>示例</th>
<th>匹配路径</th>

<tr>
<td>路径参数</td>
<td><code>@GetMapping("/books/{id}")</code></td>

<tr>
<td>通配符</td>

<tr>
<td>正则匹配</td>

</tr>

<h4 id="2-参数绑定失败的处理">2. 参数绑定失败的处理</h4>
<p>当 <code>@RequestParam</code> 设为 <code>required=true</code> 且缺失时，Spring 会抛出 <code>MissingServletRequestParameterException</code>，可通过全局异常处理统一响应。</p>
<h4 id="3-路径变量类型转换">3. 路径变量类型转换</h4>
<p>Spring 自动将路径变量转换为方法参数类型。如果转换失败，会抛出 <code>MethodArgumentTypeMismatchException</code>。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@GetMapping</span><span class="p">(</span><span class="s">"/books/{id}"</span><span class="p">)</span>

<span class="c1">// 请求 /books/abc 时，'abc' 无法转换为 Long，抛出异常</span>
</code></pre></div>

<h2 id="参数校验">参数校验</h2>
<h3 id="参数校验的重要性">参数校验的重要性</h3>
<p>在 Web 开发中，客户端提交的数据往往不可靠，必须经过校验才能使用。如果没有校验，可能导致：</p>
<ul>
<li>空指针异常（如 name 为 null）</li>
<li>数据库错误（如年龄超出范围）</li>
<li>安全漏洞（如注入攻击）</li>
</ul>
<p><strong>校验的层次：</strong></p>
<ol>
<li>客户端校验（前端表单校验）—— 用户体验</li>
<li>服务端校验（后端参数校验）—— <strong>必须执行，保证数据安全</strong></li>
</ol>
<blockquote>
<p>[!NOTE]
客户端校验可以被绕过，<strong>服务端校验是最后一道防线</strong>，必须严格执行。</p>
</blockquote>
<h3 id="Bean-Validation-简介">Bean Validation 简介</h3>
<p><strong>Bean Validation</strong> 是 Java 的一个标准规范（JSR 303/380），通过注解的方式对 Java Bean 的属性进行校验。Spring Boot 集成了 Hibernate Validator（Bean Validation 的参考实现），无需额外配置即可使用。</p>
<p>Spring Boot 的 <code>spring-boot-starter-web</code> 已经包含了 <code>spring-boot-starter-validation</code>，无需额外添加。如果项目中未包含，可以手动添加：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>org.springframework.boot<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-boot-starter-validation<span class="nt">&lt;/artifactId&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<blockquote>
<p>[!NOTE]
在 Spring Boot 2.3+ 中，<code>spring-boot-starter-web</code> 不再默认包含 <code>validation</code>，需要显式添加。确保 <code>pom.xml</code> 中有此依赖。</p>
</blockquote>

<h3 id="引入Lombok">引入Lombok</h3>
<p><strong>Lombok是一个Java库，它能通过注解自动生成样板代码</strong>，从而帮助开发者摆脱编写getter、setter、构造方法等重复性劳动，让代码更加简洁</p>
<h4 id="安装和配置Lombok">安装和配置Lombok</h4>
<table>
<thead>
<tr>
<th>方面</th>
<th>描述</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>核心目标</strong></td>
<td>消除Java代码中的样板代码（boilerplate code），提高开发效率。</td>
</tr>
<tr>
<td><strong>实现方式</strong></td>
<td>提供一系列注解，在<strong>编译时</strong>自动生成对应的字节码，注入到<code>.class</code>文件中。</td>
</tr>
<tr>
<td><strong>主要用途</strong></td>
<td>简化POJO（Plain Old Java Object）、Java Bean、实体类等的创建。</td>
</tr>
<tr>
<td><strong>工作方式</strong></td>
<td>非运行时反射，而是通过<strong>编译时注解处理（APT）</strong> 技术，在代码编译阶段“插入”处理逻辑。</td>
</tr>
</tbody>
</table>
<p>为了让 IDEA 能识别并支持 Lombok 的注解（如提供代码提示），需要先安装插件。</p>

<li><strong>搜索插件</strong>：在设置窗口左侧选择 <code>Plugins</code>，然后切换到顶部的 <code>Marketplace</code> 标签页。</li>
<li><strong>安装插件</strong>：在搜索框输入 <code>Lombok</code>，找到插件（图标是一个红色辣椒或咖啡杯），点击 <code>Install</code> 安装。</li>
<li><strong>重启 IDEA</strong>：安装完成后，根据提示重启 IDEA 使插件生效。</li>
</ol>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>请求映射注解</strong>：
   - <code>@RequestMapping</code> 及组合注解（@GetMapping、@PostMapping 等）
   - 路径匹配规则（精确匹配、路径参数、通配符）</li>
<li><strong>参数绑定注解</strong>：
   - <code>@PathVariable</code>：提取 URL 路径变量
   - <code>@RequestParam</code>：提取查询参数
   - <code>@RequestBody</code>：绑定请求体 JSON 到 Java 对象
   - <code>@RequestHeader</code>：提取请求头</li>
<li><strong>RESTful API 设计规范</strong>：资源命名、HTTP 方法映射、状态码使用</li>
<li><strong>参数校验</strong>：
   - Bean Validation 注解：@NotNull、@NotBlank、@Size、@Min 等
   - @Valid 触发校验，@Validated 支持分组校验
   - 校验失败抛出 <code>MethodArgumentNotValidException</code></li>
</ol>
