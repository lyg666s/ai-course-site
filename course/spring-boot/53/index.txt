<h3 id="默认行为">默认行为</h3>
<p>不配置任何策略时，Spring Batch 遇到异常会：
1. 回滚当前 Chunk 的事务
2. 标记 Step 为 <code>FAILED</code>
3. 标记 Job 为 <code>FAILED</code>
4. 结束执行</p>

    D --&gt; E[Step 失败]
    E --&gt; F[Job 失败]

<h2 id="Skip-跳过机制">Skip 跳过机制</h2>
<h3 id="什么是-Skip">什么是 Skip</h3>
<p><strong>Skip</strong> 允许在遇到特定异常时<strong>跳过当前记录</strong>，继续处理后续数据。适用于数据本身有问题的场景。</p>
<h3 id="基本配置">基本配置</h3>
<p>使用 <code>faultTolerant()</code> 启用容错模式，通过 <code>skip()</code> 和 <code>skipLimit()</code> 配置：</p>

<h2 id="Retry-重试机制">Retry 重试机制</h2>
<h3 id="什么是-Retry">什么是 Retry</h3>
<p><strong>Retry</strong> 允许在遇到<strong>临时性异常</strong>时自动重试，如果重试成功则继续，重试失败则按配置跳过或失败。适用于网络抖动、数据库死锁等场景。</p>
<h3 id="基本配置_1">基本配置</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Bean</span>

<span class="w">                      </span><span class="n">PlatformTransactionManager</span><span class="w"> </span><span class="n">transactionManager</span><span class="p">,</span>
<span class="w">                      </span><span class="n">ItemReader</span><span class="o">&lt;</span><span class="n">Book</span><span class="o">&gt;</span><span class="w"> </span><span class="n">reader</span><span class="p">,</span>
<span class="w">                      </span><span class="n">ItemWriter</span><span class="o">&lt;</span><span class="n">Book</span><span class="o">&gt;</span><span class="w"> </span><span class="n">writer</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>

<h3 id="Retry-执行流程">Retry 执行流程</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    A[执行操作] --&gt; B{成功？}

    D --&gt;|否| E[失败/跳过]

<h3 id="Skip-与-Retry-组合">Skip 与 Retry 组合</h3>
<p>重试失败后，可以配置跳过：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="p">.</span><span class="na">faultTolerant</span><span class="p">()</span>

<span class="p">.</span><span class="na">skip</span><span class="p">(</span><span class="n">IllegalArgumentException</span><span class="p">.</span><span class="na">class</span><span class="p">)</span><span class="w">     </span><span class="c1">// 数据错误，直接跳过</span>
<span class="p">.</span><span class="na">retryLimit</span><span class="p">(</span><span class="mi">3</span><span class="p">)</span>
<span class="p">.</span><span class="na">retry</span><span class="p">(</span><span class="n">TransientDataAccessException</span><span class="p">.</span><span class="na">class</span><span class="p">)</span><span class="w"> </span><span class="c1">// 临时故障，重试 3 次</span>

<p>[!NOTE]

</blockquote>

<h2 id="Restart-断点续传">Restart 断点续传</h2>
<h3 id="什么是-Restart">什么是 Restart</h3>
<p><strong>Restart</strong> 允许作业失败后<strong>从上次中断点继续执行</strong>，而不是从头开始。Spring Batch 通过 <code>ExecutionContext</code> 保存执行状态，实现断点续传。</p>
<h3 id="Restart-的原理">Restart 的原理</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant Job as Job
    participant Step as Step
    participant Ctx as ExecutionContext
    participant DB as 数据库

    Job-&gt;&gt;Step: 开始处理
    Step-&gt;&gt;Ctx: 记录读取位置
    Step-&gt;&gt;DB: 处理数据（每 Chunk 提交）
    Note over Step: 处理到第 50 条时失败
    Step-&gt;&gt;Ctx: 保存当前状态
    Step--&gt;&gt;Job: 抛出异常

    Note over Job: 人工修复后重启
    Job-&gt;&gt;Ctx: 读取上次执行状态
    Ctx--&gt;&gt;Step: 从第 51 条继续
    Step-&gt;&gt;DB: 继续处理
</code></pre></div>

<h3 id="Restart-的条件">Restart 的条件</h3>
<p>作业可以重启的前提：</p>
<table>
<thead>
<tr>
<th>条件</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td>状态为 <code>FAILED</code></td>
<td>作业失败后可以重启</td>
</tr>
<tr>
<td>状态为 <code>STOPPED</code></td>
<td>作业被停止后可以重启</td>
</tr>
<tr>
<td>不满足</td>
<td><code>COMPLETED</code>不能重启</td>
</tr>
</tbody>
</table>

<h2 id="注意事项">注意事项</h2>
<h3 id="1-skip-和-retry-的执行顺序">1. skip 和 retry 的执行顺序</h3>
<div class="codehilite"><pre><span></span><code>1. 尝试执行操作
2. 失败 → 判断是否可重试
3. 可重试 → 重试（最多 retryLimit 次）
4. 重试仍失败 → 判断是否可跳过
5. 可跳过 → 跳过并记录（最多 skipLimit 次）
6. 不可跳过或超过 limit → Step 失败
</code></pre></div>

<h3 id="2-skipLimit-是累积的">2. skipLimit 是累积的</h3>
<p><code>skipLimit(5)</code> 表示<strong>整个 Step</strong> 最多跳过 5 条，不是每个 Chunk。到达上限后 Step 失败。</p>
<h3 id="3-noSkip-的优先级">3. noSkip 的优先级</h3>
<p><code>noSkip(Exception.class)</code> 的优先级高于 <code>skip()</code>，用于排除不希望跳过的异常：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="p">.</span><span class="na">skip</span><span class="p">(</span><span class="n">Exception</span><span class="p">.</span><span class="na">class</span><span class="p">)</span><span class="w">          </span><span class="c1">// 跳过所有异常</span>
<span class="p">.</span><span class="na">noSkip</span><span class="p">(</span><span class="n">NullPointerException</span><span class="p">.</span><span class="na">class</span><span class="p">)</span><span class="w">  </span><span class="c1">// 但空指针不跳过</span>
</code></pre></div>

<h3 id="4-saveState-与-restart">4. saveState 与 restart</h3>
<ul>
<li><code>FlatFileItemReader.saveState(true)</code>：支持断点续传（默认）</li>
<li>禁用后每次从头读取</li>
<li>数据库 Reader（如 JdbcPagingItemReader）默认支持 restart</li>
</ul>
<h3 id="5-restart-的限制">5. restart 的限制</h3>
<ul>
<li><code>COMPLETED</code> 状态不能重启</li>
<li><code>startLimit</code> 限制最多启动次数</li>
<li>修改 Reader 的资源（如文件）可能导致重启失败</li>
</ul>
<h3 id="6-错误数据的清理">6. 错误数据的清理</h3>
<p>错误表会逐渐积累，建议定期清理：</p>
<div class="codehilite lang-sql"><pre><span></span><code><span class="c1">-- 清理 30 天前的错误记录</span>
<span class="k">DELETE</span><span class="w"> </span><span class="k">FROM</span><span class="w"> </span><span class="n">book_import_error</span>
<span class="k">WHERE</span><span class="w"> </span><span class="n">created_at</span><span class="w"> </span><span class="o">&lt;</span><span class="w"> </span><span class="k">CURRENT_TIMESTAMP</span><span class="w"> </span><span class="o">-</span><span class="w"> </span><span class="nb">INTERVAL</span><span class="w"> </span><span class="s1">'30 days'</span><span class="p">;</span>
</code></pre></div>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>异常处理概述</strong>：数据异常、临时异常、致命异常及对应策略</li>
<li><strong>Skip 跳过机制</strong>：
   - <code>skipLimit</code>、<code>skip(Exception.class)</code>、<code>noSkip</code>
   - <code>SkipPolicy</code> 自定义跳过条件
   - <code>SkipListener</code> 记录被跳过的数据</li>
<li><strong>Retry 重试机制</strong>：
   - <code>retryLimit</code>、<code>retry(Exception.class)</code>
   - <code>BackOffPolicy</code>（固定退避、指数退避）
   - <code>RetryListener</code> 记录重试信息</li>
<li><strong>Restart 断点续传</strong>：
   - 基于 <code>ExecutionContext</code> 保存状态
   - <code>JobOperator.restart()</code>
   - <code>startLimit</code>、<code>allowStartIfComplete</code>、<code>saveState</code></li>
<li><strong>错误数据管理</strong>：
   - 写入错误表、错误文件
   - 通过 <code>SkipListener</code> 统一记录</li>
</ol>
