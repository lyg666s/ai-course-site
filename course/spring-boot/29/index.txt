<h2 id="导入从单表到关联表">导入：从单表到关联表</h2>
<p>在前几节课中，我们只操作了 <code>book</code> 单表。但在实际业务中，表之间往往存在关联关系：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph 数据库
        B[(book)]
        O[(orders)]
        OI[(order_item)]
    end

    O --&gt;|one-to-many| OI
    OI --&gt;|many-to-one| B
</code></pre></div>

<p><strong>JPA 关联映射</strong> 让我们可以在 Java 对象中直接操作关联关系，而无需手动编写 JOIN SQL。</p>
<table>
<thead>
<tr>
<th>关联类型</th>
<th>数据库表现</th>
<th>Java 表现</th>
</tr>
</thead>
<tbody>
<tr>
<td>一对一</td>
<td>外键 + UNIQUE</td>
<td><code>@OneToOne</code></td>
</tr>
<tr>
<td>一对多</td>
<td>外键在多的一方</td>
<td><code>@OneToMany</code> / <code>@ManyToOne</code></td>
</tr>
<tr>
<td>多对多</td>
<td>中间表</td>
<td><code>@ManyToMany</code></td>
</tr>
</tbody>
</table>
<p>本节课将以 <strong>订单（Order）- 订单项（OrderItem）- 图书（Book）</strong> 这一业务场景为主线，深入讲解 JPA 关联映射的实战应用。</p>

<h3 id="单向关联-vs-双向关联">单向关联 vs 双向关联</h3>
<table>
<thead>
<tr>
<th>关联方式</th>
<th>说明</th>
<th>代码表现</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>单向关联</strong></td>
<td>只有一方持有另一方的引用</td>
<td>只在 <code>OrderItem</code> 中有 <code>Order</code> 字段</td>
</tr>
<tr>
<td><strong>双向关联</strong></td>
<td>双方互相持有引用</td>
<td><code>Order</code> 中有 <code>List&lt;OrderItem&gt;</code>，<code>OrderItem</code> 中有 <code>Order</code></td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]
双向关联便于双向导航，但需要维护关系两端的一致性。通常建议<strong>单向关联</strong>，除非确实需要双向遍历。</p>
</blockquote>

<h2 id="N1-查询问题与解决方案">N+1 查询问题与解决方案</h2>
<h3 id="什么是-N1-查询问题">什么是 N+1 查询问题</h3>
<p><strong>N+1 查询问题</strong> 是 JPA/Hibernate 中最常见、也最容易被忽视的性能陷阱。它指的是：当查询一个实体列表时（1 次查询），JPA 为了获取每个实体关联的数据，又额外执行了 N 次查询（N 为实体数量），导致总共执行了 N+1 次 SQL。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Q1["SELECT * FROM orders&lt;br/&gt;(1 次查询)"] --&gt; Q2["SELECT * FROM order_item WHERE order_id = 1&lt;br/&gt;(1 次)"]
    Q1 --&gt; Q3["SELECT * FROM order_item WHERE order_id = 2&lt;br/&gt;(1 次)"]
    Q1 --&gt; Q4["SELECT * FROM order_item WHERE order_id = 3&lt;br/&gt;(1 次)"]
    Q1 --&gt; Q5["... (N 次)"]

    style Q1 fill:#e3f2fd
    style Q2 fill:#ffcdd2
    style Q3 fill:#ffcdd2
    style Q4 fill:#ffcdd2
</code></pre></div>

<h3 id="问题复现">问题复现</h3>
<p>假设我们查询 10 个订单，并在循环中访问每个订单的订单项：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// ❌ 典型的 N+1 问题</span>
<span class="nd">@Transactional</span><span class="p">(</span><span class="n">readOnly</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="kc">true</span><span class="p">)</span>
<span class="kd">public</span><span class="w"> </span><span class="n">List</span><span class="o">&lt;</span><span class="n">Order</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">getAllOrders</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="k">for</span><span class="w"> </span><span class="p">(</span><span class="n">Order</span><span class="w"> </span><span class="n">order</span><span class="w"> </span><span class="p">:</span><span class="w"> </span><span class="n">orders</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>

<h3 id="N1-问题的根源">N+1 问题的根源</h3>
<h4 id="懒加载的副作用">懒加载的副作用</h4>
<p>懒加载是为了“按需加载”而设计的，但在循环中逐条访问关联数据时，反而会触发多次查询。</p>
<h4 id="急加载的陷阱">急加载的陷阱</h4>
<p><code>@ManyToOne</code> 和 <code>@OneToOne</code> 的默认抓取策略是 <code>EAGER</code>，会导致在查询主实体时，自动执行额外的查询来加载关联实体。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// ❌ 即使不访问 order 字段，查询 OrderItem 时也会触发 N+1</span>
<span class="nd">@Entity</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">OrderItem</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nd">@ManyToOne</span><span class="w">  </span><span class="c1">// 默认 EAGER，会额外查询 Order</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">Order</span><span class="w"> </span><span class="n">order</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div>

<p>执行 <code>findAll()</code> 查询 <code>OrderItem</code> 时，会先查 <code>order_item</code> 表，然后对每个 <code>OrderItem</code> 再查一次 <code>orders</code> 表。<strong>即使你不需要 <code>order</code> 数据，它也会被加载！</strong></p>
<h3 id="解决方案一JOIN-FETCHJPQL">解决方案一：JOIN FETCH（JPQL）</h3>
<p><code>JOIN FETCH</code> 在 JPQL 中显式指定加载关联数据，生成一条 <strong>LEFT JOIN</strong> 或 <strong>INNER JOIN</strong> SQL，一次性加载所有数据。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Repository</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">interface</span> <span class="nc">OrderRepository</span><span class="w"> </span><span class="kd">extends</span><span class="w"> </span><span class="n">JpaRepository</span><span class="o">&lt;</span><span class="n">Order</span><span class="p">,</span><span class="w"> </span><span class="n">Long</span><span class="o">&gt;</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="nd">@Query</span><span class="p">(</span><span class="s">"SELECT o FROM Order o JOIN FETCH o.items i JOIN FETCH i.book WHERE o.id = :id"</span><span class="p">)</span>
<span class="w">    </span><span class="n">Optional</span><span class="o">&lt;</span><span class="n">Order</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">findByIdWithItems</span><span class="p">(</span><span class="nd">@Param</span><span class="p">(</span><span class="s">"id"</span><span class="p">)</span><span class="w"> </span><span class="n">Long</span><span class="w"> </span><span class="n">id</span><span class="p">);</span>

<span class="w">    </span><span class="nd">@Query</span><span class="p">(</span><span class="s">"SELECT o FROM Order o JOIN FETCH o.items i JOIN FETCH i.book"</span><span class="p">)</span>
<span class="w">    </span><span class="n">List</span><span class="o">&lt;</span><span class="n">Order</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">findAllWithItems</span><span class="p">();</span>
<span class="p">}</span>
</code></pre></div>

<p><strong>生成的 SQL：</strong></p>
<div class="codehilite lang-sql"><pre><span></span><code><span class="k">SELECT</span><span class="w"> </span><span class="n">o</span><span class="p">.</span><span class="o">*</span><span class="p">,</span><span class="w"> </span><span class="n">i</span><span class="p">.</span><span class="o">*</span><span class="p">,</span><span class="w"> </span><span class="n">b</span><span class="p">.</span><span class="o">*</span><span class="w"> </span>
<span class="k">FROM</span><span class="w"> </span><span class="n">orders</span><span class="w"> </span><span class="n">o</span><span class="w"> </span>
<span class="k">LEFT</span><span class="w"> </span><span class="k">JOIN</span><span class="w"> </span><span class="n">order_item</span><span class="w"> </span><span class="n">i</span><span class="w"> </span><span class="k">ON</span><span class="w"> </span><span class="n">o</span><span class="p">.</span><span class="n">id</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">i</span><span class="p">.</span><span class="n">order_id</span><span class="w"> </span>
<span class="k">LEFT</span><span class="w"> </span><span class="k">JOIN</span><span class="w"> </span><span class="n">book</span><span class="w"> </span><span class="n">b</span><span class="w"> </span><span class="k">ON</span><span class="w"> </span><span class="n">i</span><span class="p">.</span><span class="n">book_id</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">b</span><span class="p">.</span><span class="n">id</span><span class="p">;</span>
</code></pre></div>

<blockquote>
<p>✅ <strong>优点</strong>：只执行 1 次查询，性能最优。
❌ <strong>缺点</strong>：</p>
<ul>
<li>多个 <code>JOIN FETCH</code> 可能导致结果集膨胀（笛卡尔积）。</li>
<li>无法与分页（<code>Pageable</code>）良好配合（内存分页 vs 数据库分页）。</li>
<li>SQL 是静态的，不易动态调整加载内容。</li>
</ul>
</blockquote>
<h3 id="解决方案二EntityGraph推荐">解决方案二：EntityGraph（推荐）</h3>
<p><code>@EntityGraph</code> 是 JPA 2.1 引入的功能，通过注解声明要加载的关联路径，让 JPA 在查询时自动生成相应的 SQL。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Repository</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">interface</span> <span class="nc">OrderRepository</span><span class="w"> </span><span class="kd">extends</span><span class="w"> </span><span class="n">JpaRepository</span><span class="o">&lt;</span><span class="n">Order</span><span class="p">,</span><span class="w"> </span><span class="n">Long</span><span class="o">&gt;</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="nd">@EntityGraph</span><span class="p">(</span><span class="n">attributePaths</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="p">{</span><span class="s">"items"</span><span class="p">,</span><span class="w"> </span><span class="s">"items.book"</span><span class="p">})</span>
<span class="w">    </span><span class="nd">@Query</span><span class="p">(</span><span class="s">"SELECT o FROM Order o WHERE o.id = :id"</span><span class="p">)</span>
<span class="w">    </span><span class="n">Optional</span><span class="o">&lt;</span><span class="n">Order</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">findByIdWithItems</span><span class="p">(</span><span class="nd">@Param</span><span class="p">(</span><span class="s">"id"</span><span class="p">)</span><span class="w"> </span><span class="n">Long</span><span class="w"> </span><span class="n">id</span><span class="p">);</span>

<span class="w">    </span><span class="nd">@EntityGraph</span><span class="p">(</span><span class="n">attributePaths</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="p">{</span><span class="s">"items"</span><span class="p">,</span><span class="w"> </span><span class="s">"items.book"</span><span class="p">})</span>
<span class="w">    </span><span class="n">List</span><span class="o">&lt;</span><span class="n">Order</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">findAll</span><span class="p">();</span>
<span class="p">}</span>
</code></pre></div>

<p>当你在方法上标注 <code>@EntityGraph(attributePaths = {"items", "items.book"})</code> 时，Spring Data JPA 做了两件核心的事：</p>
<ul>
<li><strong>动态生成抓取策略</strong>：它告诉 JPA 持久化提供者（如 Hibernate），在生成 SQL 时，<strong>必须</strong>通过 <code>LEFT JOIN</code> 一次性将 <code>Order</code>、<code>OrderItem</code>（items）以及 <code>Book</code>（items.book）这三张表的数据全部拉取出来。</li>
<li><strong>覆盖默认懒加载</strong>：即使你的 <code>Order</code> 实体中 <code>items</code> 字段标记为 <code>LAZY</code>（懒加载），这个注解也会强制在当前查询中将其改为 <code>EAGER</code>（立即加载），保证在查询关闭前所有数据都已填充到对象中。</li>
</ul>
<blockquote>
<p>✅ <strong>优点</strong>：类型安全，配置集中，可复用。
❌ <strong>缺点</strong>：静态定义，无法在运行时动态调整。</p>
</blockquote>
<h3 id="解决方案三批量抓取Batch-Fetching">解决方案三：批量抓取（Batch Fetching）</h3>
<h4 id="配置全局批量抓取大小">配置全局批量抓取大小</h4>
<p>在 <code>application.yml</code> 中配置：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">jpa</span><span class="p">:</span>
<span class="w">    </span><span class="nt">properties</span><span class="p">:</span>
<span class="w">      </span><span class="nt">hibernate</span><span class="p">:</span>
<span class="w">        </span><span class="nt">default_batch_fetch_size</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">20</span>
</code></pre></div>

<p>Hibernate 会将 N 次查询合并为 <code>N / batch_size</code> 次查询：</p>
<div class="codehilite lang-sql"><pre><span></span><code><span class="c1">-- 假设批量大小为 20，查询 10 个订单的订单项</span>
<span class="c1">-- 不会执行 10 次，而是 1 次：</span>
<span class="k">SELECT</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="k">FROM</span><span class="w"> </span><span class="n">order_item</span><span class="w"> </span><span class="k">WHERE</span><span class="w"> </span><span class="n">order_id</span><span class="w"> </span><span class="k">IN</span><span class="w"> </span><span class="p">(</span><span class="mi">1</span><span class="p">,</span><span class="mi">2</span><span class="p">,</span><span class="mi">3</span><span class="p">,</span><span class="mi">4</span><span class="p">,</span><span class="mi">5</span><span class="p">,</span><span class="mi">6</span><span class="p">,</span><span class="mi">7</span><span class="p">,</span><span class="mi">8</span><span class="p">,</span><span class="mi">9</span><span class="p">,</span><span class="mi">10</span><span class="p">);</span>
</code></pre></div>

<h4 id="使用-BatchSize-注解">使用 @BatchSize 注解</h4>
<p>在实体类上精确控制：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Entity</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">Order</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nd">@OneToMany</span><span class="p">(</span><span class="n">mappedBy</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"order"</span><span class="p">,</span><span class="w"> </span><span class="n">fetch</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">FetchType</span><span class="p">.</span><span class="na">LAZY</span><span class="p">)</span>
<span class="w">    </span><span class="nd">@BatchSize</span><span class="p">(</span><span class="n">size</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="mi">10</span><span class="p">)</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">List</span><span class="o">&lt;</span><span class="n">OrderItem</span><span class="o">&gt;</span><span class="w"> </span><span class="n">items</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">ArrayList</span><span class="o">&lt;&gt;</span><span class="p">();</span>
<span class="p">}</span>
</code></pre></div>

<blockquote>
<p>✅ <strong>优点</strong>：无需修改 JPQL，代码改动小。
❌ <strong>缺点</strong>：仍然是多次查询（N / batch_size 次），只是减少了次数，未完全消除。</p>
</blockquote>

<h3 id="N1-问题最佳实践总结">N+1 问题最佳实践总结</h3>
<ol>
<li><strong>全局设置为 LAZY</strong></li>
</ol>
<p><code>java
   @ManyToOne(fetch = FetchType.LAZY)
   @OneToOne(fetch = FetchType.LAZY)</code>
   这是避免 N+1 问题的第一步。</p>
<ol start="2">
<li><strong>按需加载，而非一刀切</strong></li>
</ol>
<ul>
<li>默认只加载当前需要的数据。</li>
<li>需要关联数据时，在 Repository 方法中使用 <code>JOIN FETCH</code> 或 <code>EntityGraph</code>。</li>
</ul>
<ol start="3">
<li><strong>使用 <code>@EntityGraph</code> 优于手写 <code>JOIN FETCH</code></strong></li>
</ol>
<ul>
<li>更可维护，支持复用。</li>
<li>避免 <code>JOIN FETCH</code> 与分页的冲突。</li>

<h2 id="注意事项">注意事项</h2>
<ol>
<li><strong>双向关联维护一致性</strong>：必须通过 <code>addItem</code> / <code>removeItem</code> 同时设置两端，否则 JPA 可能无法正确保存外键。</li>
<li><strong>级联删除风险</strong>：<code>CascadeType.REMOVE</code> 会物理删除子记录，慎用。建议使用状态字段实现逻辑删除。</li>
<li><strong>循环引用序列化</strong>：在 REST 返回中，双向关联可能造成循环引用导致 <code>StackOverflowError</code>，可使用 <code>@JsonIgnore</code> 忽略一方，或使用 DTO 返回。此外，实体类的 toString() 方法如果包含双向关联，同样会在日志打印、调试时引发栈溢出，建议使用 Lombok 的 @ToString.Exclude 排除关联字段，避免循环调用。同时处理这两个问题，才能彻底杜绝因循环引用引发的异常。</li>
<li><strong>外键非空约束</strong>：<code>@JoinColumn(nullable = false)</code> 确保数据完整性，与数据库 <code>NOT NULL</code> 约束一致。</li>
<li><strong>性能优化</strong>：使用 <code>LAZY</code> + 按需预加载，避免不必要的查询。</li>
<li><strong>N+1 问题排查</strong>：开启 SQL 日志，监控 <code>findAll</code> 等批量查询方法是否产生大量重复 SQL。</li>
</ol>
<h2 id="小结">小结</h2>
<p>本节课我们以订单-订单项-图书的业务场景为主线，学习了：</p>
<ol>
<li><strong>数据库表设计</strong>：明确外键关系、级联删除策略和索引。</li>
<li><strong>关联关系映射</strong>：
   - <code>@ManyToOne</code> / <code>@OneToMany</code> 实现一对多双向关联
   - <code>mappedBy</code> 指定维护方
   - <code>@JoinColumn</code> 定义外键列</li>
<li><strong>级联操作（CascadeType）</strong>：<code>PERSIST</code>、<code>MERGE</code>、<code>REMOVE</code>、<code>ALL</code> 的使用与风险。</li>
<li><strong>懒加载（LAZY） vs 急加载（EAGER）</strong>：推荐 LAZY + 按需预加载。</li>
<li><strong>N+1 查询问题</strong>：
   - 问题的根源：默认 EAGER 和循环中触发懒加载
   - 四种解决方案：JOIN FETCH、EntityGraph、批量抓取
   - 方案对比与选择指南
   - 最佳实践总结</li>
<li><strong>实战应用</strong>：完整的订单创建、查询、取消功能实现。</li>
</ol>
