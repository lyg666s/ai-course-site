<h2 id="AOP-概述">AOP 概述</h2>
<h3 id="什么是-AOP">什么是 AOP</h3>
<p><strong>AOP（Aspect Oriented Programming，面向切面编程）</strong> 是一种编程范式，它允许开发者将横切关注点（Cross-Cutting Concerns）从业务逻辑中分离出来，实现代码的模块化复用。</p>
<p><strong>横切关注点</strong> 是指那些分散在应用各个模块中的共同功能，如日志记录、性能监控、事务管理、权限校验等。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph 传统编程
        M1[模块1] --&gt; L1[日志]
        M1 --&gt; T1[事务]
        M2[模块2] --&gt; L2[日志]
        M2 --&gt; T2[事务]
        M3[模块3] --&gt; L3[日志]
        M3 --&gt; T3[事务]
    end

    subgraph AOP编程
        M4[模块1] -.-&gt; AOP[AOP切面&lt;br/&gt;日志/事务/监控]
        M5[模块2] -.-&gt; AOP
        M6[模块3] -.-&gt; AOP
    end

    style AOP fill:#e8f5e9
</code></pre></div>

<h3 id="为什么需要-AOP">为什么需要 AOP</h3>
<table>
<thead>
<tr>
<th>问题</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>代码重复</strong></td>
<td>日志、监控等代码在每个方法中重复出现</td>
</tr>
<tr>
<td><strong>关注点混杂</strong></td>
<td>业务逻辑与非业务逻辑混合在一起，降低可读性</td>
</tr>
<tr>
<td><strong>维护困难</strong></td>
<td>修改日志格式需要改动所有相关方法</td>
</tr>
<tr>
<td><strong>难以复用</strong></td>
<td>横切逻辑无法在其他模块中复用</td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]
AOP 的核心价值在于<strong>关注点分离</strong>。让业务逻辑专注于核心业务，让横切关注点独立管理和维护。</p>
</blockquote>
<h2 id="AOP-核心概念">AOP 核心概念</h2>
<h3 id="核心术语">核心术语</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    Aspect[切面 Aspect&lt;br/&gt;横切关注点的模块化] --&gt; Advice[通知 Advice&lt;br/&gt;切面在某个连接点的具体行为]
    Aspect --&gt; Pointcut[切点 Pointcut&lt;br/&gt;匹配连接点的表达式]
    Aspect --&gt; Weaving[织入 Weaving&lt;br/&gt;将切面应用到目标对象的过程]

    JoinPoint[连接点 JoinPoint&lt;br/&gt;程序执行过程中可插入切面的点] --&gt; Pointcut
    Target[目标对象 Target Object&lt;br/&gt;被通知的对象] --&gt; Weaving
    Proxy[代理对象 Proxy&lt;br/&gt;应用通知后创建的对象] --&gt; Weaving

    style Aspect fill:#e3f2fd
    style Advice fill:#e8f5e9
    style Pointcut fill:#fff3e0
</code></pre></div>

<table>
<thead>
<tr>
<th>术语</th>
<th>说明</th>
<th>生活类比</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>连接点（Join Point）</strong></td>
<td>程序执行过程中可插入切面的点（如方法调用、异常抛出）</td>
<td>所有可以安检的入口</td>
</tr>
<tr>
<td><strong>切点（Pointcut）</strong></td>
<td>匹配连接点的表达式，决定哪些连接点会被通知</td>
<td>选择哪些入口需要安检</td>
</tr>
<tr>
<td><strong>通知（Advice）</strong></td>
<td>切面在特定连接点执行的具体行为</td>
<td>安检动作（扫描、检查）</td>
</tr>
<tr>
<td><strong>切面（Aspect）</strong></td>
<td>切点 + 通知的集合，横切关注点的模块化</td>
<td>安检员 + 安检规则</td>
</tr>
<tr>
<td><strong>织入（Weaving）</strong></td>
<td>将切面应用到目标对象并创建代理对象的过程</td>
<td>把安检设备和流程部署到位</td>
</tr>
<tr>
<td><strong>目标对象（Target）</strong></td>
<td>被通知的原始业务对象</td>
<td>需要安检的旅客</td>
</tr>
<tr>
<td><strong>代理对象（Proxy）</strong></td>
<td>应用通知后创建的对象，包含增强后的行为</td>
<td>安检后放行的旅客</td>
</tr>
</tbody>
</table>

<h2 id="动态代理基础">动态代理基础</h2>
<h3 id="什么是动态代理">什么是动态代理</h3>
<p>Spring AOP 的底层实现基于<strong>动态代理</strong>。动态代理在运行时为目标对象动态生成代理对象，通过代理对象间接调用目标对象，在调用前后插入增强逻辑。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Proxy[代理对象]
    Proxy --&gt;|增强逻辑| ProxyLogic[前置/后置处理]
    ProxyLogic --&gt; Target[目标对象]
    Target --&gt;|返回结果| Client

    style Proxy fill:#fff3e0
</code></pre></div>

<h3 id="两种动态代理方式">两种动态代理方式</h3>
<table>
<thead>
<tr>
<th>代理方式</th>
<th>实现机制</th>
<th>适用条件</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>JDK 动态代理</strong></td>
<td>基于接口的代理，使用 <code>java.lang.reflect.Proxy</code></td>
<td>目标类实现了至少一个接口</td>
</tr>
<tr>
<td><strong>CGLIB 代理</strong></td>
<td>基于类继承的代理，通过生成目标类的子类来实现</td>
<td>目标类没有实现接口</td>
</tr>
</tbody>
</table>

<h2 id="CGLIB-动态代理">CGLIB 动态代理</h2>
<h3 id="基本实现_1">基本实现</h3>
<p>CGLIB（Code Generation Library）通过继承目标类来生成代理，不需要接口。</p>
<p><strong>步骤一：添加依赖</strong></p>
<p>在非 Spring Boot 环境中需要添加依赖：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>cglib<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>cglib<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;version&gt;</span>3.3.0<span class="nt">&lt;/version&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<p>在 Spring Boot 项目中，直接添加<code>spring-boot-starter-aop</code> 即可：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>org.springframework.boot<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-boot-starter-aop<span class="nt">&lt;/artifactId&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<p><strong>步骤二：创建目标类（无接口）</strong></p>
<div class="codehilite lang-java"><pre><span></span><code><span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">BookServiceImpl</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="c1">// 必须提供无参构造函数</span>
<span class="w">    </span><span class="kd">public</span><span class="w"> </span><span class="nf">BookServiceImpl</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="k">this</span><span class="p">.</span><span class="na">bookRepository</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">BookRepository</span><span class="p">();</span>
<span class="w">    </span><span class="p">}</span>

<h2 id="Spring-AOP-的代理选择策略">Spring AOP 的代理选择策略</h2>
<p>Spring AOP同样采用动态代理机制，在运行时会自动选择使用 JDK 代理还是 CGLIB 代理。</p>
<h3 id="选择规则">选择规则</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    Start[开始] --&gt; Q1{目标类是否&lt;br/&gt;实现了接口？}
    Q1 --&gt;|是| Q2{配置是否强制&lt;br/&gt;使用 CGLIB？}
    Q1 --&gt;|否| CGLIB[使用 CGLIB 代理]
    Q2 --&gt;|是| CGLIB
    Q2 --&gt;|否| JDK[使用 JDK 动态代理]
</code></pre></div>

<blockquote>
<p>[!NOTE]
可以通过配置控制代理的选择结果。</p>
</blockquote>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>AOP 的核心思想</strong>：将横切关注点从业务逻辑中分离，实现模块化复用。</li>
<li><strong>AOP 核心术语</strong>：切面、连接点、切点、通知、织入、目标对象、代理对象。</li>
<li><strong>通知类型</strong>：前置、后置、异常、最终、环绕通知。</li>
<li><strong>JDK 动态代理</strong>：基于接口，使用 <code>java.lang.reflect.Proxy</code> + <code>InvocationHandler</code>。</li>
<li><strong>CGLIB 代理</strong>：基于继承，使用 <code>Enhancer</code> + <code>MethodInterceptor</code>。</li>
<li><strong>Spring AOP 代理选择策略</strong>：
   - 有接口 → JDK 代理（默认）
   - 无接口 → CGLIB 代理（默认）
   - 可通过 <code>proxy-target-class=true</code> 强制 CGLIB</li>
</ol>
