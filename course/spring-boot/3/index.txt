<h3 id="为什么需要分层">为什么需要分层</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Controller[Controller 层]
    Controller --&gt; Service[Service 层]
    Service --&gt; Repository[Repository 层]
    Repository --&gt; DB[(数据库)]

    subgraph 职责
        Controller --&gt; C1[接收请求&lt;br/&gt;参数校验&lt;br/&gt;返回响应]

        Repository --&gt; R1[数据存取&lt;br/&gt;SQL 操作]
    end

<p><strong>分层的好处：</strong></p>
<table>
<thead>
<tr>
<th>好处</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>职责清晰</strong></td>
<td>每层只做自己分内的事，代码易于理解</td>
</tr>
<tr>
<td><strong>可维护性</strong></td>
<td>修改某层代码不影响其他层</td>
</tr>
<tr>
<td><strong>可测试性</strong></td>
<td>每层可以独立进行单元测试</td>
</tr>
<tr>
<td><strong>可替换性</strong></td>
<td>可以替换某层的实现（如更换数据库）而不影响其他层</td>
</tr>
</tbody>
</table>
<h2 id="三层架构设计">三层架构设计</h2>
<h3 id="架构概述">架构概述</h3>
<p>三层架构是 Spring Boot 项目中最常见的组织方式：</p>
<table>
<thead>
<tr>
<th>层级</th>
<th>职责</th>
<th>不应包含</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Controller</strong></td>
<td>接收请求、参数校验、返回 JSON</td>
<td>业务逻辑、数据库操作</td>
</tr>
<tr>
<td><strong>Service</strong></td>
<td>核心业务逻辑、事务管理</td>
<td>HTTP 处理、直接 SQL</td>
</tr>
<tr>
<td><strong>Repository</strong></td>
<td>数据持久化、CRUD 操作</td>
<td>业务逻辑</td>
</tr>
</tbody>
</table>

<h2 id="依赖注入与层间调用">依赖注入与层间调用</h2>
<h3 id="依赖注入">依赖注入</h3>
<p>在 <code>BookController</code> 中，我们使用了 <code>@Autowired</code> 注入 <code>BookService</code>：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Autowired</span>
<span class="kd">private</span><span class="w"> </span><span class="n">BookService</span><span class="w"> </span><span class="n">bookService</span><span class="p">;</span>
</code></pre></div>

<p><strong>使用 Spring 的依赖注入：</strong></p>
<ul>
<li>Spring 容器在创建 <code>BookController</code> 时，会自动找到 <code>BookService</code> 的实现类（<code>BookServiceImpl</code>），并将其注入。</li>
<li>这样做的好处是：<code>BookController</code> 不需要关心 <code>BookService</code> 是如何创建的，也不关心它用的是哪个实现类。</li>
</ul>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>Spring Boot 标准目录结构</strong>：主启动类、controller、service、repository、model、dto、config 等包的职责。</li>
<li><strong>三层架构设计</strong>：Controller（接收请求）→ Service（业务逻辑）→ Repository（数据访问）。</li>
<li><strong>搭建项目骨架</strong>：创建了 Model、Repository、Service、Controller 各层的代码。</li>
<li><strong>依赖注入</strong>：通过 <code>@Autowired</code> 让 Spring 容器自动注入依赖，实现层与层之间的解耦。</li>
<li><strong>接口测试</strong>：使用 Postman 验证各层联调是否正常。</li>
</ol>
