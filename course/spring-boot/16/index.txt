<h2 id="过滤器与拦截器概述">过滤器与拦截器概述</h2>
<p>在 Web 开发中，经常需要在请求处理的前后执行一些通用逻辑，如日志记录、权限校验、性能监控、请求参数预处理等。Spring 提供了两种机制：<strong>过滤器（Filter）</strong> 和 <strong>拦截器（Interceptor）</strong>。</p>
<h3 id="什么是-Filter过滤器">什么是 Filter（过滤器）</h3>
<p><strong>Filter</strong> 是 Java Servlet 规范定义的组件，在请求到达 Servlet 之前和响应返回客户端之后执行。它对所有请求有效，不依赖 Spring 框架。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Filter[Filter]
    Filter --&gt; Servlet[Servlet/DispatcherServlet]
    Servlet --&gt; Filter
    Filter --&gt; Client

    style Filter fill:#e3f2fd
</code></pre></div>

<h3 id="什么是-Interceptor拦截器">什么是 Interceptor（拦截器）</h3>
<p><strong>Interceptor</strong> 是 Spring 框架提供的组件，基于 AOP 思想，在请求进入 Controller 之前和之后执行。它只对 Spring 管理的 Controller 方法有效。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Filter[Filter]
    Filter --&gt; Dispatcher[DispatcherServlet]
    Dispatcher --&gt; Interceptor[Interceptor]
    Interceptor --&gt; Controller[Controller]
    Controller --&gt; Interceptor
    Interceptor --&gt; Dispatcher
    Dispatcher --&gt; Filter
    Filter --&gt; Client

    style Filter fill:#e3f2fd
    style Interceptor fill:#e8f5e9
</code></pre></div>

<h2 id="Filter-实战">Filter 实战</h2>
<h3 id="Filter-接口">Filter 接口</h3>
<p>Spring 中的 <code>Filter</code> 接口实际上是 <strong>Servlet 规范</strong> 的一部分，它定义在 <code>javax.servlet</code> 包中。Filter 是 Java Web 应用中的一种强大组件，用于在请求到达 Servlet 或响应返回客户端之前，对其进行拦截和处理。</p>
<p><code>Filter</code> 接口定义了三个方法，分别对应其生命周期的不同阶段。</p>
<table>
<thead>
<tr>
<th>方法</th>
<th>执行时机</th>
<th>主要用途</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong><code>init(FilterConfig)</code></strong></td>
<td>Web 容器启动时，Filter 实例被创建后立即调用，且<strong>仅调用一次</strong>。</td>
<td>执行 Filter 的初始化工作，例如从 <code>FilterConfig</code> 中获取初始化参数。</td>
</tr>
<tr>
<td><strong><code>doFilter(...)</code></strong></td>
<td>每当有匹配的客户端请求时被调用。</td>
<td>核心过滤方法，在此实现请求/响应的拦截、处理和传递。必须调用 <code>chain.doFilter()</code> 将请求传递给下一个 Filter 或目标 Servlet。</td>
</tr>
<tr>
<td><strong><code>destroy()</code></strong></td>
<td>Web 容器关闭或 Filter 被移除时调用，<strong>仅调用一次</strong>。</td>
<td>执行清理工作，如释放资源。</td>
</tr>
</tbody>
</table>

<h3 id="注册-Filter-的三种方式">注册 Filter 的三种方式</h3>
<p><strong>方式一：使用 @Component 自动注册（默认所有请求）</strong></p>
<p>在 Filter 类上添加 <code>@Component</code>，Spring Boot 会自动将其注册到所有请求路径。</p>
<p><strong>方式二：使用 @WebFilter + @ServletComponentScan</strong></p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@WebFilter</span><span class="p">(</span><span class="n">urlPatterns</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"/api/*"</span><span class="p">)</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">MyFilter</span><span class="w"> </span><span class="kd">implements</span><span class="w"> </span><span class="n">Filter</span><span class="w"> </span><span class="p">{</span><span class="w"> </span><span class="p">...</span><span class="w"> </span><span class="p">}</span>
</code></pre></div>

<p>在主启动类上添加 <code>@ServletComponentScan</code>。</p>
<p><strong>方式三：使用 FilterRegistrationBean 手动注册（推荐，可配置路径和顺序）</strong></p>
<div class="codehilite lang-java"><pre><span></span><code><span class="kn">package</span><span class="w"> </span><span class="nn">com.example.bookmanager.config</span><span class="p">;</span>

<span class="nd">@Configuration</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">FilterConfig</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="nd">@Bean</span>
<span class="w">    </span><span class="kd">public</span><span class="w"> </span><span class="n">FilterRegistrationBean</span><span class="o">&lt;</span><span class="n">LoggingFilter</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">loggingFilter</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="n">FilterRegistrationBean</span><span class="o">&lt;</span><span class="n">LoggingFilter</span><span class="o">&gt;</span><span class="w"> </span><span class="n">registrationBean</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">FilterRegistrationBean</span><span class="o">&lt;&gt;</span><span class="p">();</span>
<span class="w">        </span><span class="n">registrationBean</span><span class="p">.</span><span class="na">setFilter</span><span class="p">(</span><span class="k">new</span><span class="w"> </span><span class="n">LoggingFilter</span><span class="p">());</span>
<span class="w">        </span><span class="c1">// 配置拦截路径</span>
<span class="w">        </span><span class="n">registrationBean</span><span class="p">.</span><span class="na">addUrlPatterns</span><span class="p">(</span><span class="s">"/api/*"</span><span class="p">);</span>
<span class="w">        </span><span class="c1">// 配置执行顺序（数字越小越先执行）</span>
<span class="w">        </span><span class="n">registrationBean</span><span class="p">.</span><span class="na">setOrder</span><span class="p">(</span><span class="mi">1</span><span class="p">);</span>
<span class="w">        </span><span class="k">return</span><span class="w"> </span><span class="n">registrationBean</span><span class="p">;</span>
<span class="w">    </span><span class="p">}</span>
<span class="p">}</span>
</code></pre></div>

<blockquote>
<p>[!NOTE]
使用 <code>FilterRegistrationBean</code> 可以精确控制路径匹配和多个 Filter 的执行顺序，推荐在需要精细配置时使用。</p>
</blockquote>
<h2 id="Interceptor-实战">Interceptor 实战</h2>
<h3 id="HandlerInterceptor接口">HandlerInterceptor接口</h3>
<p><code>HandlerInterceptor</code> 是 Spring Web MVC 框架中用于在请求处理流程的特定节点（如控制器方法执行前后）插入自定义逻辑的接口。它支持实现日志记录、权限检查等横切关注点，有助于避免代码重复</p>
<p><code>HandlerInterceptor</code> 接口定义了三个核心方法，它们在请求处理的不同阶段被调用。</p>
<table>
<thead>
<tr>
<th>方法</th>
<th>执行时机</th>
<th>返回值</th>
<th>主要用途</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong><code>preHandle</code></strong></td>
<td>在<strong>控制器（Handler）方法执行之前</strong>被调用。</td>
<td><code>boolean</code>：返回<code>true</code>则继续执行后续流程；返回<code>false</code>则中断执行链。</td>
<td>权限检查、登录验证、请求日志记录等前置处理。</td>
</tr>
<tr>
<td><strong><code>postHandle</code></strong></td>
<td>在<strong>控制器方法执行之后</strong>，但在<strong>视图渲染之前</strong>被调用。</td>
<td><code>void</code></td>
<td>对返回的<code>ModelAndView</code>对象进行修改，如添加额外的模型数据。</td>
</tr>
<tr>
<td><strong><code>afterCompletion</code></strong></td>
<td>在<strong>整个请求处理完成之后</strong>（即视图渲染完毕）被调用。</td>
<td><code>void</code></td>
<td>进行资源清理、记录请求处理总时间等善后工作。</td>
</tr>
</tbody>
</table>

<h2 id="注意事项">注意事项</h2>
<h3 id="1-Filter-中注入-Bean-的问题">1. Filter 中注入 Bean 的问题</h3>
<p>在 <code>@Component</code> 标记的 Filter 中可以直接注入 Spring Bean，但使用 <code>new</code> 创建的 Filter 无法自动注入。推荐使用 <code>@Component</code> 方式，或通过 <code>FilterRegistrationBean</code> 配合构造函数注入。</p>
<h3 id="2-拦截器与-AOP-的关系">2. 拦截器与 AOP 的关系</h3>
<p>拦截器本质上是 AOP 的一种简化实现，但只能拦截 Controller 方法。如果需要更细粒度的拦截（如特定注解的方法），应使用 AOP 切面。</p>
<h3 id="3-静态资源拦截">3. 静态资源拦截</h3>
<p>Spring Boot 默认对静态资源（<code>/static/**</code>、<code>/public/**</code> 等）不经过 <code>DispatcherServlet</code>，因此拦截器不会拦截静态资源请求。如需拦截，应配置 <code>WebMvcConfigurer.addResourceHandlers</code> 或使用 Filter。</p>
<h3 id="4-排除路径的配置">4. 排除路径的配置</h3>
<p>在注册拦截器时，可使用 <code>excludePathPatterns</code> 排除特定路径，如登录接口、健康检查等。</p>
<h3 id="5-多个过滤器的顺序">5. 多个过滤器的顺序</h3>
<p>使用 <code>FilterRegistrationBean.setOrder()</code> 控制执行顺序，数字越小越先执行。</p>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>Filter（过滤器）</strong>：Servlet 规范的组件，对所有请求有效，不依赖 Spring。</li>
<li><strong>Interceptor（拦截器）</strong>：Spring 框架的组件，对 Controller 方法有效，可以注入 Spring Bean。</li>
<li><strong>两者的区别</strong>：规范不同、生效范围不同、粒度不同。</li>
<li><strong>Filter 实战</strong>：通过 <code>OncePerRequestFilter</code> 实现请求日志过滤器，使用 <code>FilterRegistrationBean</code> 注册。</li>
<li><strong>Interceptor 实战</strong>：通过 <code>HandlerInterceptor</code> 实现权限认证拦截器，使用 <code>WebMvcConfigurer</code> 注册。</li>
<li><strong>执行顺序</strong>：Filter → DispatcherServlet → Interceptor → Controller。</li>
</ol>
