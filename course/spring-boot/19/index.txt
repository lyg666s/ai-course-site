<h2 id="从-Spring-MVC-到-Spring-WebFlux">从 Spring MVC 到 Spring WebFlux</h2>
<h3 id="传统-Spring-MVC-的局限性">传统 Spring MVC 的局限性</h3>
<p>在传统的 Spring MVC 中，每个请求都会占用一个线程，直到请求处理完成。这种“每请求一线程”模型在以下场景中会遇到瓶颈：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Tomcat[Tomcat 线程池]
    Tomcat --&gt; T1[线程1 处理请求]
    Tomcat --&gt; T2[线程2 处理请求]
    Tomcat --&gt; T3[线程3 处理请求]
    Tomcat --&gt; T4[...]

    T1 --&gt; DB1[等待数据库响应]
    T2 --&gt; DB2[等待数据库响应]
    T3 --&gt; API[等待外部 API 响应]

    style DB1 fill:#ffcdd2
    style DB2 fill:#ffcdd2
    style API fill:#ffcdd2
</code></pre></div>

<p>当请求需要等待 I/O 操作（如数据库查询、远程 API 调用）时，线程会<strong>阻塞等待</strong>，此时线程无法处理其他请求，造成资源浪费。</p>
<table>
<thead>
<tr>
<th>问题</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>线程资源浪费</strong></td>
<td>大量线程在等待 I/O 时处于阻塞状态</td>
</tr>
<tr>
<td><strong>上下文切换开销</strong></td>
<td>线程数量增加导致 CPU 频繁切换</td>
</tr>
<tr>
<td><strong>并发能力受限</strong></td>
<td>系统支持的并发请求数受限于线程池大小</td>
</tr>
<tr>
<td><strong>响应延迟</strong></td>
<td>高并发时线程排队，响应时间增加</td>
</tr>
</tbody>
</table>
<h3 id="Servlet-31-非阻塞-IO-的不足">Servlet 3.1 非阻塞 I/O 的不足</h3>
<p>Servlet 3.1 虽然提供了非阻塞 I/O 的 API，但 Servlet API 的其他部分（如 Filter）仍然是同步阻塞的。这使得在 Servlet 容器中构建完整的非阻塞应用变得困难。</p>
<h3 id="Spring-WebFlux-的诞生">Spring WebFlux 的诞生</h3>
<p>Spring WebFlux 是 Spring Framework 5.0 引入的响应式 Web 框架，它<strong>完全非阻塞</strong>，支持响应式流（Reactive Streams）规范，可以运行在 Netty、Undertow 和 Servlet 3.1+ 容器上。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph Spring MVC
        MVC[Spring MVC] --&gt; Servlet[Servlet API]
        Servlet --&gt; Tomcat[Tomcat]
        MVC --&gt; Sync[同步/阻塞]
    end

    subgraph Spring WebFlux
        WebFlux[Spring WebFlux] --&gt; Reactor[Reactor]
        Reactor --&gt; Async[异步/非阻塞]
        WebFlux --&gt; Netty[Netty]
        WebFlux --&gt; Undertow[Undertow]
        WebFlux --&gt; Servlet31[Servlet 3.1+]
    end

    style WebFlux fill:#e8f5e9
</code></pre></div>

<blockquote>
<p>[!NOTE]
Spring WebFlux 并不是要替代 Spring MVC。两者在 Spring Framework 中共存，开发者可以根据场景选择使用。</p>
<p>[!NOTE]</p>
<p>Spring WebFlux 是构建微服务架构核心组件Spring Cloud Gateway的基础，这也是我们课程安排 Spring WebFlux 的主要原因。</p>
</blockquote>
<h2 id="响应式编程核心概念">响应式编程核心概念</h2>
<h3 id="什么是响应式编程">什么是响应式编程</h3>
<p><strong>响应式编程</strong>是一种基于异步数据流的编程范式，其核心目标是构建弹性、韧性和高效的系统，能够从容应对高并发场景下的流量波动。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Data[数据源] --&gt; Stream[数据流]
    Stream --&gt; Operator1[操作符1]
    Operator1 --&gt; Operator2[操作符2]
    Operator2 --&gt; Subscribe[订阅者]

    style Stream fill:#e3f2fd
    style Subscribe fill:#e8f5e9
</code></pre></div>

<h3 id="响应式编程的核心特性">响应式编程的核心特性</h3>
<table>
<thead>
<tr>
<th>特性</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>非阻塞 I/O</strong></td>
<td>线程在等待 I/O 时可以处理其他任务，极大提升线程利用率</td>
</tr>
<tr>
<td><strong>异步流处理</strong></td>
<td>将数据抽象为流，通过声明式操作符进行处理</td>
</tr>
<tr>
<td><strong>背压（Backpressure）</strong></td>
<td>消费者可以根据自身处理能力，主动控制生产者的数据发送速度</td>
</tr>
</tbody>
</table>
<h3 id="什么是背压">什么是背压</h3>
<p>背压是响应式编程区别于普通异步编程的关键特性。在异步通信中，如果生产者发送数据的速度远大于消费者的处理速度，会导致数据积压，最终引发内存溢出。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Producer[生产者&lt;br/&gt;快速生产] --&gt;|背压信号| Consumer[消费者&lt;br/&gt;处理慢]
    Consumer --&gt;|请求 1 个| Producer
    Producer --&gt;|发送 1 个| Consumer

    style Consumer fill:#fff3e0
</code></pre></div>

<p>背压机制允许消费者根据自身处理能力，主动向生产者反馈需求，调节数据生产的速度，实现生产与消费的平衡。</p>

<h2 id="Spring-WebFlux-两种编程模型">Spring WebFlux 两种编程模型</h2>
<p>Spring WebFlux 提供了两种编程模型供开发者选择，它们共享相同的响应式底层：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    subgraph WebFlux[Spring WebFlux]
        Annotated[注解式控制器&lt;br/&gt;Annotated Controllers]
        Functional[函数式端点&lt;br/&gt;Functional Endpoints]
    end

    Annotated --&gt; Reactor[Reactor 响应式底层]
    Functional --&gt; Reactor
    Reactor --&gt; Netty[Netty / Undertow]

    style Annotated fill:#e3f2fd
    style Functional fill:#e8f5e9
</code></pre></div>

<table>
<thead>
<tr>
<th>编程模型</th>
<th>说明</th>
<th>风格</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>注解式控制器</strong></td>
<td>使用 <code>@Controller</code>、<code>@RestController</code>、<code>@RequestMapping</code> 等注解，与 Spring MVC 风格一致</td>
<td>声明式、传统</td>
</tr>
<tr>
<td><strong>函数式端点</strong></td>
<td>使用 <code>RouterFunction</code> 和 <code>HandlerFunction</code>，以函数式方式定义路由和处理逻辑</td>
<td>函数式、现代</td>
</tr>
</tbody>
</table>

<h2 id="函数式端点Functional-Endpoints">函数式端点（Functional Endpoints）</h2>
<p>函数式端点是 Spring WebFlux 提供的另一种编程模型，使用 <code>RouterFunction</code> 和 <code>HandlerFunction</code> 来定义路由和处理逻辑。</p>
<h3 id="核心组件">核心组件</h3>
<table>
<thead>
<tr>
<th>组件</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>RouterFunction</code></td>
<td>定义路由规则，将请求路径映射到处理函数</td>
</tr>
<tr>
<td><code>HandlerFunction</code></td>
<td>处理请求的函数，接收 <code>ServerRequest</code>，返回 <code>Mono&lt;ServerResponse&gt;</code></td>
</tr>
<tr>
<td><code>ServerRequest</code></td>
<td>封装 HTTP 请求的不可变对象</td>
</tr>
<tr>
<td><code>ServerResponse</code></td>
<td>封装 HTTP 响应的不可变对象</td>
</tr>
</tbody>
</table>

<h2 id="注解式-vs-函数式如何选择">注解式 vs 函数式：如何选择</h2>
<table>
<thead>
<tr>
<th>对比维度</th>
<th>注解式控制器</th>
<th>函数式端点</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>学习曲线</strong></td>
<td>低（与 Spring MVC 一致）</td>
<td>中等（需要理解函数式编程）</td>
</tr>
<tr>
<td><strong>代码量</strong></td>
<td>较少</td>
<td>较多</td>
</tr>
<tr>
<td><strong>灵活性</strong></td>
<td>有限</td>
<td>高度灵活</td>
</tr>
<tr>
<td><strong>可测试性</strong></td>
<td>良好</td>
<td>优秀（纯函数）</td>
</tr>
<tr>
<td><strong>适用场景</strong></td>
<td>大多数常规 REST API</td>
<td>需要精细控制、轻量级网关</td>
</tr>
<tr>
<td><strong>团队偏好</strong></td>
<td>大多数团队熟悉</td>
<td>需要函数式编程基础</td>
</tr>
</tbody>
</table>
<blockquote>
<p>[!NOTE]
两种模型可以<strong>混合使用</strong>，在同一个项目中部分接口使用注解式，部分使用函数式。</p>
</blockquote>
<h2 id="WebClient-响应式-HTTP-客户端">WebClient 响应式 HTTP 客户端</h2>

<h3 id="WebClient核心方法">WebClient核心方法</h3>
<h4 id="请求构建方法HTTP-方法">请求构建方法（HTTP 方法）</h4>
<ul>
<li><strong><code>get()</code> / <code>post()</code> / <code>put()</code> / <code>delete()</code> 等</strong>
  这些方法用于指定 HTTP 请求方法，返回 <code>WebClient.RequestHeadersUriSpec</code>（对于 GET/HEAD/DELETE）或 <code>WebClient.RequestBodyUriSpec</code>（对于 POST/PUT/PATCH 等带请求体的方法），从而开始构建一个请求。</li>
</ul>
<p><code>java
  webClient.get()          // 构建 GET 请求
  webClient.post()         // 构建 POST 请求</code></p>
<h4 id="URI-指定方法">URI 指定方法</h4>
<ul>
<li><strong><code>uri(String uri, Object... uriVariables)</code></strong>
  用于设置请求的目标路径，支持路径变量占位符（<code>{id}</code>）。后续参数按顺序替换占位符，也可使用 <code>Map</code> 或 <code>URI</code> 对象。该方法返回当前构建器，支持链式调用。</li>
</ul>
<p><code>java
  .uri("/users/{id}", id)          // 路径变量替换
  .uri("/users")                   // 静态路径</code></p>
<h4 id="请求体设置方法仅用于-POSTPUTPATCH">请求体设置方法（仅用于 POST/PUT/PATCH）</h4>
<ul>
<li><strong><code>bodyValue(Object body)</code></strong>
  直接设置请求体对象，框架会自动进行序列化（如 JSON）。适用于简单对象。</li>
</ul>
<p><code>java
  .bodyValue(user)</code></p>
<ul>
<li><strong><code>body(Publisher&lt;?&gt; publisher, Class&lt;?&gt; elementClass)</code></strong>
  用于流式发送响应式数据源（如 <code>Flux</code>、<code>Mono</code>），适合大数据或流式场景。
  例如：<code>.body(Flux.just(user1, user2), User.class)</code>。</li>
</ul>
<h4 id="响应获取方法">响应获取方法</h4>
<p><strong><code>retrieve()</code></strong> （最常用）</p>
<p>直接获取响应体，返回 <code>WebClient.ResponseSpec</code>，提供对响应状态码和体的便捷处理。之后必须调用 <code>bodyToMono</code> 或 <code>bodyToFlux</code> 来提取响应体。</p>
<ul>
<li>
<p><strong><code>bodyToMono(Class&lt;T&gt; targetClass)</code></strong>
  将响应体反序列化为一个 <code>Mono&lt;T&gt;</code>（适用于单个对象）。</p>
</li>
<li>
<p><strong><code>bodyToFlux(Class&lt;T&gt; targetClass)</code></strong>
  将响应体反序列化为一个 <code>Flux&lt;T&gt;</code>（适用于集合或流式数据）。</p>
</li>
</ul>
<p><code>java
  .retrieve()
  .bodyToMono(User.class)   // 返回 Mono&lt;User&gt;
  .bodyToFlux(User.class)   // 返回 Flux&lt;User&gt;</code></p>
<p><strong><code>exchangeToMono(Function&lt;ClientResponse, Mono&lt;T&gt;&gt; handler)</code></strong></p>
<p>更底层的响应处理方式，可以访问完整的 <code>ClientResponse</code>（包括状态码、头部、Cookie 等），适用于需要精细控制响应处理的场景（如检查响应头、处理不同状态码等）。使用后需手动释放或消费响应体。</p>
<h4 id="错误处理状态码处理">错误处理（状态码处理）</h4>
<ul>
<li><strong><code>onStatus(Predicate&lt;HttpStatus&gt; statusPredicate, Function&lt;ClientResponse, Mono&lt;? extends  Throwable&gt;&gt; exceptionFunction)</code></strong>
  属于 <code>ResponseSpec</code> 的方法，用于针对特定的 HTTP 状态码自定义异常转换。当响应状态匹配谓词时，执行异常函数，最终抛出指定的错误。</li>
</ul>
<p><code>java
  .onStatus(status -&gt; status.is4xxClientError(),
            response -&gt; Mono.error(new RuntimeException("用户不存在")))</code></p>
<p>还可以链式调用多个 <code>onStatus</code>，分别处理 404、500 等。若不处理，默认对 4xx/5xx 响应会抛出 <code>WebClientResponseException</code>。</p>

<h2 id="注意事项">注意事项</h2>
<h3 id="避免阻塞操作">避免阻塞操作</h3>
<p>在 WebFlux 中，<strong>任何阻塞操作都会破坏响应式架构</strong>。以下操作需要避免：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// ❌ 错误：阻塞操作</span>
<span class="n">User</span><span class="w"> </span><span class="n">user</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">userRepository</span><span class="p">.</span><span class="na">findById</span><span class="p">(</span><span class="n">id</span><span class="p">).</span><span class="na">block</span><span class="p">();</span><span class="w">  </span><span class="c1">// 不要使用 block()！</span>
<span class="n">Thread</span><span class="p">.</span><span class="na">sleep</span><span class="p">(</span><span class="mi">1000</span><span class="p">);</span><span class="w">  </span><span class="c1">// 不要使用 Thread.sleep()！</span>

<span class="c1">// ✅ 正确：非阻塞方式</span>
<span class="n">Mono</span><span class="o">&lt;</span><span class="n">User</span><span class="o">&gt;</span><span class="w"> </span><span class="n">userMono</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">userRepository</span><span class="p">.</span><span class="na">findById</span><span class="p">(</span><span class="n">id</span><span class="p">);</span>
<span class="k">return</span><span class="w"> </span><span class="n">userMono</span><span class="p">.</span><span class="na">delayElement</span><span class="p">(</span><span class="n">Duration</span><span class="p">.</span><span class="na">ofSeconds</span><span class="p">(</span><span class="mi">1</span><span class="p">));</span>
</code></pre></div>

<h3 id="线程模型">线程模型</h3>
<p>WebFlux 使用<strong>少量事件循环线程</strong>处理所有请求，因此<strong>不要在线程局部变量（如 ThreadLocal）中存储数据</strong>。</p>
<h3 id="调试困难">调试困难</h3>
<p>响应式编程的异步特性使得调试比同步代码更困难。建议使用 <code>log()</code> 操作符进行调试：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="n">Flux</span><span class="p">.</span><span class="na">just</span><span class="p">(</span><span class="mi">1</span><span class="p">,</span><span class="w"> </span><span class="mi">2</span><span class="p">,</span><span class="w"> </span><span class="mi">3</span><span class="p">)</span>
<span class="w">    </span><span class="p">.</span><span class="na">log</span><span class="p">()</span><span class="w">  </span><span class="c1">// 打印每个操作</span>
<span class="w">    </span><span class="p">.</span><span class="na">map</span><span class="p">(</span><span class="n">i</span><span class="w"> </span><span class="o">-&gt;</span><span class="w"> </span><span class="n">i</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="mi">2</span><span class="p">)</span>
<span class="w">    </span><span class="p">.</span><span class="na">subscribe</span><span class="p">();</span>
</code></pre></div>

<h3 id="选择合适的场景">选择合适的场景</h3>
<p>WebFlux 适合 <strong>I/O 密集型</strong>和<strong>高并发</strong>场景。对于 <strong>CPU 密集型</strong>任务，传统阻塞模型可能更合适。</p>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>Spring MVC 的局限性</strong>：每请求一线程模型在 I/O 等待时浪费线程资源。</li>
<li><strong>Spring WebFlux 的诞生</strong>：Spring 5.0 引入的响应式 Web 框架，完全非阻塞，支持背压。</li>
<li>
<p><strong>响应式编程核心概念</strong>：非阻塞 I/O、异步流处理、背压。</p>
</li>
<li>
<p><strong>Spring WebFlux两种编程模型</strong>：</p>
</li>
</ol>
<ul>
<li>
<p><strong>注解式控制器</strong>：与 Spring MVC 风格一致，返回 <code>Mono</code>/<code>Flux</code></p>
</li>
<li>
<p><strong>函数式端点</strong>：使用 <code>RouterFunction</code> + <code>HandlerFunction</code></p>
</li>
</ul>
<ol start="5">
<li>
<p><strong>注解式控制器实战</strong>：CRUD 接口、Service 层、异常处理</p>
</li>
<li>
<p><strong>函数式端点实战</strong>：Handler 定义、Router 配置、路由组合</p>
</li>
<li>
<p><strong>WebClient</strong>：响应式 HTTP 客户端，替代 RestTemplate</p>
</li>
</ol>
