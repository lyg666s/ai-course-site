<ul>

<h2 id="什么是循环依赖">什么是循环依赖</h2>
<h3 id="定义">定义</h3>
<p><strong>循环依赖</strong> 是指两个或多个 Bean 之间相互依赖，形成闭环。例如：A 依赖 B，B 依赖 A；或 A 依赖 B，B 依赖 C，C 依赖 A。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    A[Bean A] --&gt;|依赖| B[Bean B]
    B --&gt;|依赖| A

    style A fill:#e3f2fd
    style B fill:#fff3e0
</code></pre></div>

<h3 id="产生原因">产生原因</h3>
<p>在 Spring IoC 容器中，循环依赖通常发生在以下场景：</p>
<ol>
<li><strong>构造器注入</strong>：A 的构造方法需要 B，B 的构造方法需要 A，导致无法创建任何一个。</li>
<li><strong>字段/Setter 注入</strong>：A 在创建后注入 B，B 在创建后注入 A，Spring 可以通过提前暴露未完全初始化的对象来解决。</li>
</ol>
<blockquote>
<p>[!NOTE]
Spring 能够解决 <strong>字段注入</strong> 和 <strong>Setter 注入</strong> 的循环依赖，但 <strong>构造器注入</strong> 的循环依赖无法解决。</p>
</blockquote>
<h2 id="构造器注入导致的循环依赖">构造器注入导致的循环依赖</h2>
<h3 id="问题复现">问题复现</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// A 依赖 B</span>
<span class="nd">@Component</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">A</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="kd">final</span><span class="w"> </span><span class="n">B</span><span class="w"> </span><span class="n">b</span><span class="p">;</span>

<span class="w">    </span><span class="kd">public</span><span class="w"> </span><span class="nf">A</span><span class="p">(</span><span class="n">B</span><span class="w"> </span><span class="n">b</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="k">this</span><span class="p">.</span><span class="na">b</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">b</span><span class="p">;</span>

<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="kd">final</span><span class="w"> </span><span class="n">A</span><span class="w"> </span><span class="n">a</span><span class="p">;</span>

<span class="w">    </span><span class="p">}</span>

<h3 id="为什么构造器注入无法解决循环依赖">为什么构造器注入无法解决循环依赖</h3>
<p>Spring 创建 Bean 的流程如下：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    Start[开始创建 Bean A] --&gt; Step1[调用构造方法]
    Step1 --&gt; Step2[需要注入依赖 B]
    Step2 --&gt; Step3[开始创建 Bean B]
    Step3 --&gt; Step4[调用构造方法]
    Step4 --&gt; Step5[需要注入依赖 A]
    Step5 --&gt; Step6[A 正在创建中&lt;br/&gt;无法获取]
    Step6 --&gt; Error[抛出循环依赖异常]
</code></pre></div>

<blockquote>
<p>[!NOTE]
构造器注入要求 Bean 在创建时就必须完成所有依赖的注入。在创建 A 时发现需要 B，于是去创建 B；创建 B 时又发现需要 A，而此时 A 还在创建中且尚未完成，因此无法获取，导致死循环。</p>
</blockquote>
<h2 id="字段Setter-注入解决循环依赖">字段/Setter 注入解决循环依赖</h2>
<p>将构造器注入改为 Setter 注入或字段注入，Spring 可以解决循环依赖。</p>
<h3 id="方式一字段注入">方式一：字段注入</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Component</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">A</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nd">@Autowired</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">B</span><span class="w"> </span><span class="n">b</span><span class="p">;</span>
<span class="p">}</span>

<span class="nd">@Component</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">B</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nd">@Autowired</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">A</span><span class="w"> </span><span class="n">a</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div>

<span class="w">    </span><span class="p">}</span>
<span class="p">}</span>

<span class="nd">@Component</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">B</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">A</span><span class="w"> </span><span class="n">a</span><span class="p">;</span>

</code></pre></div>

<blockquote>
<p>[!NOTE]</p>
<p>请注意，上述代码能够正确执行的前提是ClassA和ClassB的作用域都是Singleton。</p>
<p>同时，从 Spring Boot 2.6.0 开始，<em>默认</em>禁止循环依赖，需要设置如下配置项来开启循环依赖支持：</p>
<p><code>spring:
  main:
          allow-circular-references:true</code></p>

<h4 id="单例与原型作用域">单例与原型作用域</h4>
<p>在 Spring IoC 容器中，Bean 的<strong>默认作用域是单例（singleton）</strong>，也就是说不管对 Bean 的引用有多少个，容器只会创建一个实例。而<strong>原型（prototype）作用域</strong>则不同，每次请求 Bean 时，Spring IoC 容器都会创建一个新的对象实例。</p>
<p>从两种作用域的效果而言，我们总结一条开发上的经验：<strong>对于无状态的 Bean，应使用单例作用域；反之，对于有状态的 Bean，则应使用原型作用域。</strong></p>
<p>那么，什么样的 Bean 属于有状态的呢？结合 Web 应用程序，我们可以明确：对于每次 HTTP 请求，我们都应该创建一个 Bean  来代表这一次的请求对象；同样，对于会话而言，我们也需要针对每个会话创建一个会话状态对象。这些都是常见的有状态的 Bean。</p>
<h3 id="为什么-Setter字段注入可以解决">为什么 Setter/字段注入可以解决</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    Start[开始创建 Bean A] --&gt; Step1[实例化 A&lt;br/&gt;调用默认构造方法]
    Step1 --&gt; Step2[将 A 的早期引用放入缓存]
    Step2 --&gt; Step3[开始创建 Bean B]
    Step3 --&gt; Step4[实例化 B]
    Step4 --&gt; Step5[将 B 的早期引用放入缓存]
    Step5 --&gt; Step6[填充 B 的属性 A]
    Step6 --&gt; Step7[从缓存获取 A 的早期引用]
    Step7 --&gt; Step8[完成 B 的创建]
    Step8 --&gt; Step9[继续填充 A 的属性 B]
    Step9 --&gt; Step10[完成 A 的创建]
</code></pre></div>

<blockquote>
<p>[!NOTE]
关键区别在于：Setter/字段注入允许先实例化对象（调用无参构造方法），再通过 Setter 或反射注入依赖。Spring 在对象实例化后、完全初始化前，会将“早期引用”暴露出来，供其他 Bean 使用。</p>
</blockquote>
<h2 id="三级缓存机制">三级缓存机制</h2>
<p>Spring 通过 <strong>三级缓存</strong> 巧妙地解决了单例 Bean 之间的 Setter / 字段注入循环依赖问题。理解这三层缓存的交互，是掌握 IoC 容器核心原理的关键。</p>
<hr />
<h3 id="三级缓存的职责与存储内容">三级缓存的职责与存储内容</h3>

<td>将 A 的早期引用注入到 B 的 <code>a</code> 属性中</td>
<td>—</td>
</tr>
<tr>
<td><strong>12</strong></td>
<td>B 继续完成其他属性填充，执行 <code>@PostConstruct</code>、<code>InitializingBean</code> 等初始化回调</td>
<td>—</td>
</tr>
<tr>
<td><strong>13</strong></td>
<td>B 完全初始化，将 B 的完整实例移入<strong>一级缓存</strong></td>

<td>—</td>
</tr>
<tr>

</tr>

<h3 id="二级缓存的关键作用">二级缓存的关键作用</h3>
<ul>
<li><strong>防止重复创建早期引用</strong>：当多个 Bean 同时依赖 A 时，若每次都去三级缓存取工厂，可能多次生成代理对象（导致不一致）。二级缓存确保<strong>只有第一次</strong>会触发工厂，后续直接复用已生成的早期对象。</li>
<li><strong>保持代理对象唯一性</strong>：如果 A 需要 AOP 代理，三级缓存的工厂会返回代理对象，放入二级缓存后，所有依赖 A 的 Bean 获得的是<strong>同一个代理实例</strong>，符合单例语义。</li>
<li><strong>提升性能</strong>：工厂 <code>getObject()</code> 可能涉及复杂逻辑，缓存早期对象避免重复执行。</li>
</ul>
<h3 id="为什么需要三级缓存二级不够吗">为什么需要三级缓存，二级不够吗？</h3>
<p>如果只用二级缓存（即实例化后直接放入一个 <code>earlySingletonObjects</code>），则<strong>无法处理需要 AOP 代理的场景</strong>。因为代理对象的生成通常在 Bean 初始化之后（通过后置处理器），而循环依赖发生时，目标 Bean 尚处于“未初始化完成”状态，此时生成代理的时机必须由工厂延迟控制。三级缓存将“创建早期引用”的逻辑封装在 <code>ObjectFactory</code> 中，只有真正需要时才会触发，保证了代理生成的正确时机。</p>
<p>通过上述缓存机制，Spring 在保证单例的前提下，优雅地解决了大部分 Setter/字段注入的循环依赖问题，同时兼顾了代理、作用域等复杂特性。</p>
<h2 id="Lazy-延迟注入解决循环依赖">@Lazy 延迟注入解决循环依赖</h2>
<p><code>@Lazy</code> 注解可以让 Spring 在注入时创建一个代理对象，实际使用时才真正创建目标 Bean，从而打破循环依赖。</p>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>循环依赖的定义</strong>：多个 Bean 相互依赖形成闭环。</li>
<li><strong>构造器注入的循环依赖</strong>：无法解决，会抛出异常。</li>
<li><strong>Setter/字段注入的循环依赖</strong>：Spring 可以解决，利用三级缓存。</li>
<li><strong>三级缓存机制</strong>：
   - 一级缓存：完全初始化的 Bean
   - 二级缓存：早期暴露的 Bean 实例
   - 三级缓存：ObjectFactory 工厂</li>
<li><strong>@Lazy 延迟注入</strong>：使用代理对象打破循环。</li>
<li><strong>重构设计</strong>：优先通过设计避免循环依赖。</li>
</ol>
