<h2 id="缓存三大问题">缓存三大问题</h2>
<h3 id="缓存穿透">缓存穿透</h3>
<h4 id="什么是缓存穿透">什么是缓存穿透</h4>
<p><strong>缓存穿透</strong>是指查询一个<strong>不存在的数据</strong>，缓存和数据库中都没有。由于缓存中没有记录，每次请求都会穿透缓存直接查询数据库。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; Cache[缓存]
    Cache --&gt;|未命中| DB[数据库]
    DB --&gt;|无数据| Client
    Cache -.-&gt;|每次都不命中| DB

    style DB fill:#ffcdd2
</code></pre></div>

<p>危害：</p>
<ul>
<li>大量的请求直接打到数据库，造成数据库压力过大</li>
<li>恶意攻击者可以利用这一点进行攻击（如查询不存在的 ID）</li>
</ul>
<h4 id="解决方案">解决方案</h4>
<p><strong>方案一：缓存空值（推荐）</strong></p>
<p>将查询结果为 <code>null</code> 的情况也缓存起来，设置较短的过期时间（如 5 分钟）。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Cacheable</span><span class="p">(</span><span class="n">value</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"books"</span><span class="p">,</span><span class="w"> </span><span class="n">key</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"#id"</span><span class="p">)</span><span class="w"> </span>
<span class="kd">public</span><span class="w"> </span><span class="n">Book</span><span class="w"> </span><span class="nf">getBookById</span><span class="p">(</span><span class="n">Long</span><span class="w"> </span><span class="n">id</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">bookRepository</span><span class="p">.</span><span class="na">findById</span><span class="p">(</span><span class="n">id</span><span class="p">);</span>
<span class="p">}</span>
</code></pre></div>

<p>但默认情况下，Spring Cache <strong>不缓存 null 值</strong>。我们需要调整配置：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// 在 CacheManager 配置中允许缓存 null</span>
<span class="nd">@Bean</span>
<span class="kd">public</span><span class="w"> </span><span class="n">CacheManager</span><span class="w"> </span><span class="nf">cacheManager</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="n">CaffeineCacheManager</span><span class="w"> </span><span class="n">cacheManager</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">CaffeineCacheManager</span><span class="p">();</span>
<span class="w">    </span><span class="n">cacheManager</span><span class="p">.</span><span class="na">setAllowNullValues</span><span class="p">(</span><span class="kc">true</span><span class="p">);</span><span class="w">  </span><span class="c1">// 允许缓存 null</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">cacheManager</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div>

<p><strong>方案二：布隆过滤器（Bloom Filter）</strong></p>
<p>在缓存之前增加布隆过滤器，判断 Key 是否可能存在。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[客户端] --&gt; BF[布隆过滤器]
    BF --&gt;|可能存在| Cache[缓存]
    BF --&gt;|肯定不存在| Return[直接返回空]
    Cache --&gt;|未命中| DB[数据库]

    style BF fill:#fff9c4
</code></pre></div>

<p><strong>布隆过滤器（Bloom Filter）</strong> 是一种空间效率很高的<strong>概率型数据结构</strong>，用于判断一个元素是否可能在一个集合中。它的核心特点是：</p>
<ul>
<li><strong>判断“不存在”一定准确</strong>：如果布隆过滤器说元素不存在，那它一定不存在。</li>
<li><strong>判断“存在”可能误判</strong>：如果它说元素存在，元素不一定真的存在，存在<strong>假阳性</strong>。</li>
<li>标准布隆过滤器<strong>不支持删除元素</strong>，也不存储元素本身。</li>
</ul>
<p>结构上就是一种位数组，该位数组中每个元素的初始值都是0。在创建布隆过滤器时，会先将所有key进行n次hash运算，并将布隆过滤器中对应位置的值设置为1，相当于把所有的key保存到了布隆过滤器中。如果所有对应位置元素的值都为1，说明key在库中存在如果有任意一个位置的值不为1，说明key在库中不存在。</p>
<p><img loading="lazy" alt="image-20260915212303325" src="/ai-course-site/spring-boot/assets/ch41/image-20260915212303325.png" /></p>
<p><strong>为什么会有误判？</strong>因为多个不同元素可能哈希到相同的位。例如：</p>
<ul>
<li>插入 <code>apple</code> 时，把第 1、4、7 位置为 1；</li>
<li>插入 <code>banana</code> 时，把第 2、5、7 位置为 1；</li>
<li>查询一个从未插入的 <code>cherry</code>，它恰好映射到第 1、5、7 位，而这些位都被其他元素置为 1，于是布隆过滤器会误判 <code>cherry</code> 存在。</li>
</ul>
<p>但反过来，如果某个元素确实被插入过，那么它对应的所有位一定已经被置为 1，所以不会出现“实际存在却判断不存在”的假阴性。</p>
<p>布隆过滤器的典型应用：</p>
<ul>
<li>缓存穿透防护：先查布隆过滤器，避免查询不存在的数据；</li>
<li>爬虫 URL 去重；</li>
<li>数据库避免查询不存在的键；</li>
<li>推荐系统去重；</li>
<li>网络安全中的黑名单判断；</li>
<li>区块链和分布式系统中的集合成员判断。</li>
</ul>
<p>一句话总结：<strong>布隆过滤器用多个哈希函数把元素映射到位数组中，以少量空间和一定误判率换取高效的存在性判断；说“不存在”一定可信，说“存在”只是可能存在。</strong></p>
<p>布隆过滤器的实现较为复杂，通常需要借助 Redis 或 Guava。</p>

<h3 id="缓存击穿">缓存击穿</h3>
<h4 id="什么是缓存击穿">什么是缓存击穿</h4>
<p><strong>缓存击穿</strong>是指一个<strong>热点 Key</strong>（如热门商品、首页数据）在缓存失效的瞬间，大量并发请求同时访问，导致所有请求都打到数据库。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant T1 as 线程1
    participant T2 as 线程2
    participant T3 as 线程3
    participant Cache as 缓存
    participant DB as 数据库

    Note over T1,T3: 缓存 Key 失效瞬间
    T1-&gt;&gt;Cache: 查询缓存（未命中）
    T2-&gt;&gt;Cache: 查询缓存（未命中）
    T3-&gt;&gt;Cache: 查询缓存（未命中）
    T1-&gt;&gt;DB: 执行查询
    T2-&gt;&gt;DB: 执行查询
    T3-&gt;&gt;DB: 执行查询
    Note over T1,T3: 3 次数据库查询
</code></pre></div>

<h4 id="解决方案_1">解决方案</h4>
<p><strong>方案一：sync 属性（Spring Cache 内置）</strong></p>
<p>在 <code>@Cacheable</code> 中启用 <code>sync = true</code>，确保只有一个线程执行方法，其他线程等待。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Cacheable</span><span class="p">(</span><span class="n">value</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"books"</span><span class="p">,</span><span class="w"> </span><span class="n">key</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"#id"</span><span class="p">,</span><span class="w"> </span><span class="n">sync</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="kc">true</span><span class="p">)</span>
<span class="kd">public</span><span class="w"> </span><span class="n">Book</span><span class="w"> </span><span class="nf">getBookById</span><span class="p">(</span><span class="n">Long</span><span class="w"> </span><span class="n">id</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">bookRepository</span><span class="p">.</span><span class="na">findById</span><span class="p">(</span><span class="n">id</span><span class="p">);</span>
<span class="p">}</span>
</code></pre></div>

<p><strong>方案二：互斥锁（分布式锁）</strong></p>
<p>对于分布式系统，可以使用 Redis 分布式锁。</p>
<blockquote>
<p>[!NOTE]
单实例应用使用 <code>sync = true</code> 即可；分布式部署需要分布式锁。我们在介绍Redis时再作进一步展开。</p>
</blockquote>
<h3 id="缓存雪崩">缓存雪崩</h3>
<h4 id="什么是缓存雪崩">什么是缓存雪崩</h4>
<p><strong>缓存雪崩</strong>是指<strong>大量缓存同时失效</strong>（如设置了相同的过期时间），导致大量请求瞬间涌入数据库，引发数据库压力激增甚至宕机。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client1[请求1] --&gt; Cache1[缓存失效]
    Client2[请求2] --&gt; Cache2[缓存失效]
    ClientN[请求N] --&gt; CacheN[缓存失效]
    Cache1 --&gt; DB[(数据库)]
    Cache2 --&gt; DB
    CacheN --&gt; DB

    style DB fill:#ffcdd2
</code></pre></div>

<h4 id="危害">危害</h4>
<ul>
<li>数据库瞬间压力巨大，可能导致连接耗尽、服务不可用</li>
<li>引发连锁故障（数据库挂掉 → 应用挂掉）</li>
</ul>
<h4 id="解决方案_2">解决方案</h4>

<h2 id="缓存一致性">缓存一致性</h2>
<h3 id="什么是一致性问题">什么是一致性问题</h3>
<p>当数据库中的数据更新后，缓存中的数据仍为旧值，导致读取到的数据不一致。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    DB[(数据库)] --&gt;|更新| DB2[(数据库新值)]
    Cache[缓存] --&gt;|旧值| Client[客户端读取旧值]

    style Cache fill:#ffcdd2
</code></pre></div>

<h3 id="推荐方案Cache-Aside旁路缓存模式">推荐方案：Cache-Aside（旁路缓存）模式</h3>
<p>Cache-Aside模式的核心是：<strong>读时先查缓存，未命中再查数据库并回填缓存；写时先更新数据库，再删除缓存</strong></p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TD
    Start([开始]) --&gt; Op{操作类型?}

    Op --&gt;|读请求| ReadCache["查询缓存"]
    ReadCache --&gt; CacheHit{缓存命中?}
    CacheHit --&gt;|是| ReturnCache["返回缓存数据"]
    ReturnCache --&gt; EndRead([读结束])

    CacheHit --&gt;|否| QueryDB["查询数据库"]
    QueryDB --&gt; DBNull{数据库有数据?}
    DBNull --&gt;|否| ReturnNull["返回空/未找到"]
    ReturnNull --&gt; EndRead

    DBNull --&gt;|是| WriteCache["将数据写入缓存"]
    WriteCache --&gt; ReturnDB["返回数据库数据"]
    ReturnDB --&gt; EndRead

    Op --&gt;|写请求| UpdateDB["更新数据库"]
    UpdateDB --&gt; DeleteCache["删除缓存"]
    DeleteCache --&gt; EndWrite([写结束])
</code></pre></div>

<ul>
<li><strong>读流程</strong>：应用先访问缓存；命中则直接返回；未命中则查询数据库，若数据库有数据，则写入缓存后再返回。</li>
<li><strong>写流程</strong>：应用先更新数据库，然后删除缓存。下次读请求未命中时，会从数据库加载最新数据并回填缓存。</li>
<li><strong>为什么写时删除缓存而不是更新缓存</strong>：删除更简单，也能避免并发写导致缓存与数据库不一致；更新缓存可能引入额外的并发覆盖问题。</li>
</ul>
<p>在 Spring Cache 中，我们使用 <code>@CacheEvict</code> 实现：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@CacheEvict</span><span class="p">(</span><span class="n">value</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"books"</span><span class="p">,</span><span class="w"> </span><span class="n">key</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"#book.id"</span><span class="p">)</span>
<span class="kd">public</span><span class="w"> </span><span class="kt">void</span><span class="w"> </span><span class="nf">updateBook</span><span class="p">(</span><span class="n">Book</span><span class="w"> </span><span class="n">book</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="n">bookRepository</span><span class="p">.</span><span class="na">update</span><span class="p">(</span><span class="n">book</span><span class="p">);</span>
<span class="p">}</span>
</code></pre></div>

<p><strong>一致性增强</strong>：如果对一致性要求较高，可以配合延迟双删等方式进一步降低不一致窗口。</p>
<h3 id="延迟双删策略">延迟双删策略</h3>
<p>在高并发场景下，先更新数据库再删除缓存，仍可能存在短暂的不一致窗口。<strong>延迟双删</strong>能进一步降低不一致概率。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant App as 应用
    participant DB as 数据库
    participant Cache as 缓存

    App-&gt;&gt;Cache: 1. 删除缓存
    App-&gt;&gt;DB: 2. 更新数据库
    App-&gt;&gt;App: 3. 延迟 500ms
    App-&gt;&gt;Cache: 4. 再次删除缓存
</code></pre></div>

<p>实现方式：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="kd">public</span><span class="w"> </span><span class="kt">void</span><span class="w"> </span><span class="nf">updateBook</span><span class="p">(</span><span class="n">Book</span><span class="w"> </span><span class="n">book</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="c1">// 1. 删除缓存</span>
<span class="w">    </span><span class="n">cacheManager</span><span class="p">.</span><span class="na">getCache</span><span class="p">(</span><span class="s">"books"</span><span class="p">).</span><span class="na">evict</span><span class="p">(</span><span class="n">book</span><span class="p">.</span><span class="na">getId</span><span class="p">());</span>

<span class="w">    </span><span class="c1">// 2. 更新数据库</span>
<span class="w">    </span><span class="n">bookMapper</span><span class="p">.</span><span class="na">updateById</span><span class="p">(</span><span class="n">book</span><span class="p">);</span>

<span class="w">    </span><span class="c1">// 3. 延迟后再删除一次（异步）</span>
<span class="w">    </span><span class="k">new</span><span class="w"> </span><span class="n">Thread</span><span class="p">(()</span><span class="w"> </span><span class="o">-&gt;</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="k">try</span><span class="w"> </span><span class="p">{</span>
<span class="w">            </span><span class="n">Thread</span><span class="p">.</span><span class="na">sleep</span><span class="p">(</span><span class="mi">200</span><span class="p">);</span><span class="w">  </span><span class="c1">// 延迟 200ms</span>
<span class="w">            </span><span class="n">cacheManager</span><span class="p">.</span><span class="na">getCache</span><span class="p">(</span><span class="s">"books"</span><span class="p">).</span><span class="na">evict</span><span class="p">(</span><span class="n">book</span><span class="p">.</span><span class="na">getId</span><span class="p">());</span>
<span class="w">        </span><span class="p">}</span><span class="w"> </span><span class="k">catch</span><span class="w"> </span><span class="p">(</span><span class="n">InterruptedException</span><span class="w"> </span><span class="n">ignored</span><span class="p">)</span><span class="w"> </span><span class="p">{}</span>
<span class="w">    </span><span class="p">}).</span><span class="na">start</span><span class="p">();</span><span class="w">   </span>
<span class="p">}</span>
</code></pre></div>

<p>[!NOTE]
延迟双删适用于对一致性要求极高的场景。延迟时间通常设置为数据库主从同步的时间窗口。</p>

<h3 id="6-避免缓存大对象">6. 避免缓存大对象</h3>
<p>缓存大对象（如包含大量字段的列表）会占用大量内存，建议：
- 只缓存必要字段（使用 DTO）
- 拆分缓存（单个对象 vs 列表）
- 设置合理大小限制</p>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>缓存穿透</strong>：查询不存在的数据，解决方式：缓存空值、布隆过滤器。</li>
<li><strong>缓存击穿</strong>：热点 Key 失效瞬间大量请求，解决方式：<code>sync = true</code>、分布式锁。</li>
<li><strong>缓存雪崩</strong>：大量缓存同时失效，解决方式：分散 TTL、随机 TTL、缓存预热。</li>
<li><strong>缓存一致性</strong>：推荐 Cache-Aside（先更新数据库，再删除缓存），延迟双删提高一致性。</li>
<li><strong>最佳实践</strong>：粒度选择、TTL 设置、监控告警、预热、降级。</li>
</ol>
