<h2 id="JDBC-规范概述">JDBC 规范概述</h2>
<h3 id="什么是-JDBC">什么是 JDBC</h3>
<p><strong>JDBC（Java Database Connectivity）</strong> 是 Java 语言访问关系型数据库的标准 API，由 <code>java.sql</code> 和 <code>javax.sql</code> 包组成。它定义了一套统一的接口，让 Java 程序可以通过相同的方式访问不同的数据库。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR

        JDBC[JDBC 接口]

        Driver2[PostgreSQL Driver]
        Driver3[Oracle Driver]
    end

    subgraph 数据库
        DB1[(MySQL)]
        DB2[(PostgreSQL)]
        DB3[(Oracle)]
    end

    App --&gt; JDBC
    JDBC --&gt; Driver1
    JDBC --&gt; Driver2
    JDBC --&gt; Driver3
    Driver1 --&gt; DB1
    Driver2 --&gt; DB2
    Driver3 --&gt; DB3
</code></pre></div>

<blockquote>
<p>[!NOTE]
JDBC 是一套“接口规范”，具体实现由各数据库厂商提供（称为数据库驱动）。开发者只需要面向 JDBC 接口编程，更换数据库时只需更换驱动和连接信息，代码逻辑无需修改。</p>

<h4 id="DriverManager驱动管理器"><code>DriverManager</code>（驱动管理器）</h4>
<ul>
<li><strong>核心职责</strong>：作为 JDBC 架构的“服务注册中心”，负责加载并注册数据库驱动（如 MySQL、Oracle 的驱动类），并根据传入的 JDBC URL 从已注册的驱动列表中匹配合适的驱动，从而建立与数据库的物理连接。</li>
<li><strong>关键方法</strong>：<code>getConnection(String url, String user, String password)</code>。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>自动加载</strong>：JDBC 4.0+ 利用 SPI（服务提供者机制），驱动包中的 <code>META-INF/services</code> 会被自动扫描，不再需要手动执行 <code>Class.forName()</code>。</li>
<li><strong>连接参数</strong>：除了用户名密码，还可在 URL 后追加参数（如 <code>?useSSL=false&amp;serverTimezone=UTC</code>），或通过 <code>Properties</code> 对象传入超时时间、连接池初始大小等扩展属性。</li>
<li><strong>注意事项</strong>：该接口是重量级的静态工厂，通常在应用启动时初始化一次，不建议在业务代码中频繁调用（实际生产环境多交给 HikariCP 等连接池代理）。</li>
</ul>
<hr />
<h4 id="Connection数据库连接"><code>Connection</code>（数据库连接）</h4>
<ul>
<li><strong>核心职责</strong>：代表与数据库服务器之间的一个网络会话（Session）。它是执行 SQL 语句的上下文环境，也是事务管理的核心边界。</li>
<li><strong>关键方法</strong>：<code>createStatement()</code>、<code>prepareStatement(String sql)</code>、<code>setAutoCommit(boolean)</code>、<code>commit()</code>、<code>rollback()</code>、<code>close()</code>。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>事务控制</strong>：默认是自动提交（<code>autoCommit=true</code>），即每条 DML 语句执行后立即持久化。为了确保业务原子性（如转账），需关闭自动提交（<code>setAutoCommit(false)</code>），在全部成功时 <code>commit()</code>，异常时 <code>rollback()</code>。</li>
<li><strong>隔离级别</strong>：可通过 <code>setTransactionIsolation()</code> 设置读未提交、读已提交、可重复读、串行化，以平衡数据一致性与并发性能。</li>
<li><strong>资源管理</strong>：<code>Connection</code> 是重量级资源，必须在使用后显式关闭（建议放在 <code>try-with-resources</code> 中），否则会导致连接泄露，耗尽数据库连接数。</li>
</ul>
<hr />
<h4 id="Statement静态-SQL-执行器"><code>Statement</code>（静态 SQL 执行器）</h4>
<ul>
<li><strong>核心职责</strong>：用于执行<strong>静态</strong>的 SQL 语句（即 SQL 字符串在编译时已完全确定），并将执行后的结果返回。</li>
<li><strong>关键方法</strong>：<code>executeQuery(String sql)</code>（查询）、<code>executeUpdate(String sql)</code>（增删改/DDL）、<code>execute(String sql)</code>（通用）。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>致命缺陷（SQL 注入）</strong>：因为 SQL 语句是通过字符串拼接形成的（如 <code>"SELECT * FROM user WHERE id=" + id</code>），若参数 <code>id</code> 包含恶意 <code>' OR '1'='1</code>，会导致整个表数据泄露。<strong>极度不推荐在生产查询代码中使用</strong>。</li>
<li><strong>性能短板</strong>：每次执行时，数据库都需要对 SQL 进行语法解析、编译和生成执行计划，无法复用缓存，在循环批量执行时效率极低。</li>
<li><strong>适用场景</strong>：仅适合执行无需参数参与的 DDL 语句（如 <code>CREATE TABLE</code>）或数据库元数据查询。</li>
</ul>
<hr />
<h4 id="PreparedStatement预编译-SQL-执行器推荐"><code>PreparedStatement</code>（预编译 SQL 执行器，⭐推荐）</h4>
<ul>
<li><strong>核心职责</strong>：继承自 <code>Statement</code>，在创建时即传入带占位符（<code>?</code>）的 SQL 模板，发送给数据库进行<strong>预编译</strong>（生成执行计划），后续仅需传入参数即可复用执行计划。</li>
<li><strong>关键方法</strong>：<code>setXxx(int index, Xxx value)</code>（如 <code>setString</code>、<code>setInt</code>）、<code>executeQuery()</code>、<code>executeUpdate()</code>。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>防 SQL 注入（核心优势）</strong>：预编译机制将参数内容视为<strong>纯数据</strong>而非 SQL 语法结构，即使参数包含恶意关键字，也不会被数据库解析为指令，从根本上杜绝了注入风险。</li>
<li><strong>性能飞跃</strong>：在批量操作（<code>addBatch()</code> + <code>executeBatch()</code>）场景下，只需传输参数数据，网络开销小，且数据库无需重复解析，批量插入数万条记录时性能提升数倍。</li>
<li><strong>注意事项</strong>：占位符 <code>?</code> <strong>仅支持字段值</strong>，不能用于表名、列名、SQL 关键字（如 <code>ORDER BY</code> 后的字段名）等元数据。此外，MySQL 默认未开启服务端预编译（需在 URL 中加 <code>useServerPrepStmts=true</code>）。</li>
</ul>
<hr />
<h4 id="ResultSet结果集"><code>ResultSet</code>（结果集）</h4>
<ul>
<li><strong>核心职责</strong>：封装数据库返回的<strong>临时数据表</strong>（包含行和列），提供游标（Cursor）来逐行遍历查询结果，并提取每一列的值。</li>
<li><strong>关键方法</strong>：<code>next()</code>（移动游标并判断是否有下一行）、<code>getString(int columnIndex)</code>、<code>getString(String columnLabel)</code>、<code>getObject()</code>、<code>close()</code>。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>游标模式</strong>：默认类型为 <code>TYPE_FORWARD_ONLY</code>（只能向前滚动），如需支持双向滚动或游标定位（<code>absolute</code>、<code>previous</code>），需在 <code>createStatement</code> 或 <code>prepareStatement</code> 时指定 <code>ResultSet.TYPE_SCROLL_INSENSITIVE</code>。</li>
<li><strong>数据提取</strong>：建议优先使用<strong>列名</strong>（<code>getString("name")</code>）而非列索引（<code>getString(1)</code>），以增强代码可读性和抗字段顺序变更的能力。注意 JDBC 索引从 1 开始。</li>
<li><strong>生命周期</strong>：<code>ResultSet</code> 必须依附于开启状态的 <code>Statement</code> 和 <code>Connection</code>。一旦父级 <code>Statement</code> 关闭（或者再次执行新的查询），当前的 <code>ResultSet</code> 会自动关闭。为了避免内存泄漏，建议显式调用 <code>close()</code>。</li>
</ul>
<hr />
<h4 id="SQLException数据库异常"><code>SQLException</code>（数据库异常）</h4>
<ul>
<li><strong>核心职责</strong>：JDBC 操作中所有与数据库交互相关的<strong>受查异常（Checked Exception）</strong> 的根类，用于捕获连接失败、语法错误、约束冲突、锁超时等数据库层级的错误。</li>
<li><strong>关键方法</strong>：<code>getErrorCode()</code>（数据库厂商特定的错误码）、<code>getSQLState()</code>（遵循 X/Open 标准的 SQL 状态码，如 "23000" 表示违反约束）、<code>getNextException()</code>（支持异常链）。</li>
<li><strong>展开说明</strong>：</li>
<li><strong>异常链机制</strong>：一个 JDBC 操作可能触发多个底层异常（如网络超时 + 回滚失败），通过 <code>getNextException()</code> 可以遍历完整的异常链表，不要只看第一个异常。</li>
<li><strong>处理策略</strong>：捕获后务必将错误信息转化为业务可读的提示（而非直接抛出堆栈给前端）；在事务上下文中，捕获到 <code>SQLException</code> 后通常需要调用 <code>Connection.rollback()</code> 释放资源锁。</li>
<li><strong>现代替代</strong>：Spring 等框架会将 <code>SQLException</code> 封装为非受查异常（如 <code>DataAccessException</code>），避免业务代码中反复 try-catch。</li>
</ul>

<h2 id="传统-JDBC-的痛点分析">传统 JDBC 的痛点分析</h2>
<p>通过上面的代码，我们可以清晰地看到传统 JDBC 开发的主要痛点：</p>
<h3 id="痛点一重复代码过多">痛点一：重复代码过多</h3>
<p>每个数据库操作都需要重复以下步骤：</p>
<ul>
<li>获取连接</li>
<li>创建 Statement</li>
<li>执行 SQL</li>
<li>处理结果集</li>
<li>关闭资源</li>
</ul>
<p>在大型项目中，这些重复代码占据了大量篇幅，降低了开发效率。</p>
<h3 id="痛点二资源管理繁琐">痛点二：资源管理繁琐</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// 需要手动关闭每个资源，而且顺序不能错</span>
<span class="k">try</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="n">rs</span><span class="w"> </span><span class="o">!=</span><span class="w"> </span><span class="kc">null</span><span class="p">)</span><span class="w"> </span><span class="n">rs</span><span class="p">.</span><span class="na">close</span><span class="p">();</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="n">stmt</span><span class="w"> </span><span class="o">!=</span><span class="w"> </span><span class="kc">null</span><span class="p">)</span><span class="w"> </span><span class="n">stmt</span><span class="p">.</span><span class="na">close</span><span class="p">();</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="n">conn</span><span class="w"> </span><span class="o">!=</span><span class="w"> </span><span class="kc">null</span><span class="p">)</span><span class="w"> </span><span class="n">conn</span><span class="p">.</span><span class="na">close</span><span class="p">();</span>
<span class="p">}</span><span class="w"> </span><span class="k">catch</span><span class="w"> </span><span class="p">(</span><span class="n">SQLException</span><span class="w"> </span><span class="n">e</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="n">e</span><span class="p">.</span><span class="na">printStackTrace</span><span class="p">();</span>
<span class="p">}</span>
</code></pre></div>

<p>忘记关闭连接会导致<strong>连接泄漏</strong>，最终耗尽数据库连接池，应用崩溃。</p>
<h3 id="痛点三异常处理冗长">痛点三：异常处理冗长</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="k">try</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="c1">// 业务代码</span>
<span class="p">}</span><span class="w"> </span><span class="k">catch</span><span class="w"> </span><span class="p">(</span><span class="n">SQLException</span><span class="w"> </span><span class="n">e</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="c1">// 每个方法都要写类似的异常处理</span>
<span class="p">}</span>
</code></pre></div>

<p><code>SQLException</code> 是一个受检异常，必须捕获或声明。每个方法都要重复写 try-catch，代码臃肿。</p>
<h3 id="痛点四结果集映射繁琐">痛点四：结果集映射繁琐</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="n">Book</span><span class="w"> </span><span class="n">book</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">Book</span><span class="p">();</span>
<span class="n">book</span><span class="p">.</span><span class="na">setId</span><span class="p">(</span><span class="n">rs</span><span class="p">.</span><span class="na">getLong</span><span class="p">(</span><span class="s">"id"</span><span class="p">));</span>
<span class="n">book</span><span class="p">.</span><span class="na">setTitle</span><span class="p">(</span><span class="n">rs</span><span class="p">.</span><span class="na">getString</span><span class="p">(</span><span class="s">"title"</span><span class="p">));</span>
<span class="n">book</span><span class="p">.</span><span class="na">setAuthor</span><span class="p">(</span><span class="n">rs</span><span class="p">.</span><span class="na">getString</span><span class="p">(</span><span class="s">"author"</span><span class="p">));</span>
<span class="n">book</span><span class="p">.</span><span class="na">setPrice</span><span class="p">(</span><span class="n">rs</span><span class="p">.</span><span class="na">getDouble</span><span class="p">(</span><span class="s">"price"</span><span class="p">));</span>
<span class="n">book</span><span class="p">.</span><span class="na">setStock</span><span class="p">(</span><span class="n">rs</span><span class="p">.</span><span class="na">getInt</span><span class="p">(</span><span class="s">"stock"</span><span class="p">));</span>
</code></pre></div>

<p>需要手动将 <code>ResultSet</code> 的每列映射到 Java 对象的每个字段。当字段很多时，代码量巨大且容易出错。</p>
<h3 id="痛点五SQL-与-Java-代码耦合">痛点五：SQL 与 Java 代码耦合</h3>
<p>SQL 语句直接写在 Java 代码中，修改 SQL 需要重新编译。在大型项目中，SQL 的调试和维护困难。</p>
<h2 id="Spring-JDBC-解决方案预览">Spring JDBC 解决方案预览</h2>
<p>Spring JDBC 框架（<code>spring-jdbc</code> 模块）针对上述痛点提供了优雅的解决方案：</p>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>数据访问层次架构</strong>：应用程序通过 JDBC 访问数据库，Spring 提供了更高层次的抽象。</li>
<li><strong>JDBC 规范</strong>：Java 标准数据库访问 API，核心接口包括 <code>DriverManager</code>、<code>Connection</code>、<code>Statement</code>、<code>PreparedStatement</code>、<code>ResultSet</code>。</li>
<li><strong>传统 JDBC 开发流程</strong>：加载驱动 → 建立连接 → 创建 Statement → 执行 SQL → 处理结果集 → 释放资源。</li>
<li><strong>传统 JDBC 的五大痛点</strong>：
   - 重复代码多
   - 资源管理繁琐
   - 异常处理冗长
   - 结果集映射繁琐
   - SQL 与 Java 代码耦合</li>
<li><strong>Spring JDBC 预览</strong>：通过 <code>JdbcTemplate</code> 简化 JDBC 操作，后续课程详细展开。</li>
<li><strong>图书管理系统的演进</strong>：从内存存储逐步演进到真实数据库持久化。</li>
</ol>
