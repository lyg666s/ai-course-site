17:T1ce8,<h1 id="拓展知识">拓展知识</h1>
<h2 id="Postgres的其他能力">Postgres的其他能力</h2>
<table>
<thead>
<tr>
<th>名称</th>
<th>它是做什么的</th>
<th>什么场景下关注它</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>备份与恢复</strong></td>
<td>把数据库的数据倒出来存一份（备份），出问题时能从这份存档把数据还原回去（恢复）</td>
<td>上线后必须考虑备份策略</td>
</tr>
<tr>
<td><strong>锁</strong></td>
<td>当多个事务同时读写同一条数据时，锁用来决定谁先谁后，防止数据乱掉</td>
<td>高并发写入、秒杀、库存扣减等场景，锁是性能瓶颈的根源</td>
</tr>
<tr>
<td><strong>视图</strong></td>
<td>把一条 SQL 查询存成一个「虚拟表」，以后可以直接查它，不用每次都写复杂 SQL</td>
<td>报表、权限控制、给业务方暴露简化数据接口时</td>
</tr>
<tr>
<td><strong>物化视图</strong></td>
<td>和视图类似，但会把查询结果真的存成一张物理表，查起来更快，但数据不是实时最新的</td>
<td>大报表、数据仓库、定时刷新的统计看板</td>
</tr>
<tr>
<td><strong>存储过程</strong></td>
<td>把多条 SQL 和逻辑写成一个「函数」，存在数据库里，应用端调一次就能跑完所有逻辑</td>
<td>业务逻辑全在数据库里跑、批量数据处理、减少应用层网络开销时</td>
</tr>
<tr>
<td><strong>触发器</strong></td>
<td>在表上插/改/删数据时，自动执行一段预先写好的逻辑（比如记日志、同步数据）</td>
<td>审计日志、数据同步、自动更新某些字段（如 updated_at）</td>
</tr>
<tr>
<td><strong>CTE 表达式</strong></td>
<td>写一个临时的命名子查询，让多层嵌套的 SQL 更容易阅读和维护</td>
<td>复杂查询拆分、递归查询（树形结构/层级数据）</td>
</tr>
<tr>
<td><strong>全文检索</strong></td>
<td>让你在大量文本里按「相关性」快速搜索，支持中文分词、权重、高亮，比 <code>LIKE</code> 高效精准</td>
<td>站内搜索、文章/商品搜索，任何需要输入框搜内容的场景</td>
</tr>
<tr>
<td><strong>GIN / GiST 索引</strong></td>
<td>特殊索引类型，用来加速全文检索、JSON、数组、空间地理数据等非标类型的查询</td>
<td>全文检索、JSON 字段搜索、数组包含查询、地理位置查询</td>
</tr>
<tr>
<td><strong>BRIN 索引</strong></td>
<td>一种轻量级索引，按数据在磁盘上的物理块范围建索引，占用空间极小</td>
<td>超大表 + 数据天然有序（如时间序列日志），查范围不查单条</td>
</tr>
<tr>
<td><strong>表分区</strong></td>
<td>把一张大表从逻辑上拆成多个小表（分区），查询时只扫相关分区，大幅提升性能和管理效率</td>
<td>日志表、订单表等随时间增长的超大表，尤其是需要按时间淘汰旧数据</td>
</tr>
<tr>
<td><strong>表继承</strong></td>
<td>让一张表从另一张表继承字段，子表可以加自己的字段，查询父表时能查到所有子表数据</td>
<td>数据归档、冷热分层（历史数据放子表）、ORM 的多态继承映射</td>
</tr>
<tr>
<td><strong>插件机制</strong></td>
<td>PostgreSQL 允许你装各种扩展包来增加功能，比如 <code>postgis</code>（地理信息）、<code>pgvector</code>（向量搜索）</td>
<td>当标准功能不够用，需要 GIS、向量检索、定时任务、审计等能力时</td>
</tr>
<tr>
<td><strong>权限系统</strong></td>
<td>控制谁能查、谁能改、谁能建表，精确到字段级别</td>
<td>多租户、数据安全合规、不同角色分权管理时</td>
</tr>
<tr>
<td><strong>FDW（外部表）</strong></td>
<td>在 PostgreSQL 里直接查询另一个数据库（MySQL、Oracle、甚至 CSV 文件）的数据，就像查本地表一样</td>
<td>数据迁移、跨库数据整合、临时拉取外部数据做报表</td>
</tr>
<tr>
<td><strong>JSON / JSONB</strong></td>

<h3 id="数据库设计三范式">数据库设计三范式</h3>
<table>
<thead>
<tr>
<th>范式</th>
<th>核心要求</th>
<th>通俗理解</th>
<th>反例</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>第一范式（1NF）</strong></td>
<td>列不可再分，每列都是原子值</td>
<td>一个格子只存一个值，不存数组或复合数据</td>
<td>一行里存多个联系电话（<code>138xxx, 139xxx</code>）</td>
</tr>
<tr>
<td><strong>第二范式（2NF）</strong></td>
<td>满足1NF + 非主键列完全依赖于主键（消除部分依赖）</td>
<td>复合主键时，每一列都要依赖整个主键，不能只依赖其中一部分</td>
<td><code>订单明细表</code>主键是<code>(订单ID, 商品ID)</code>，但<code>商品名称</code>只依赖<code>商品ID</code></td>
</tr>
<tr>
<td><strong>第三范式（3NF）</strong></td>
<td>满足2NF + 非主键列之间不能有传递依赖</td>
<td>非主键列不能依赖于另一个非主键列</td>
<td><code>学生表</code>有<code>院系ID</code>和<code>院系名称</code>，后者依赖于前者，应拆分出院系表</td>
</tr>
</tbody>
