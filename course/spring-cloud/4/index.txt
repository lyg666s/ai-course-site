17:T18054,<h1 id="服务拆分与接口设计">服务拆分与接口设计</h1>
<h2 id="课程目标">课程目标</h2>
<ul>
<li>理解微服务拆分后各服务的领域模型设计</li>
<li>理解 Entity、DTO、VO 三种数据结构的定位、作用与区别</li>
<li>掌握使用 BeanUtils / Hutool 简化 VO 转换，避免大量 set 方法</li>
<li>掌握使用 MyBatis-Plus 完成 Entity、Mapper、Service、Controller 的完整开发流程</li>
<li>掌握分库设计原则，为三个服务配置独立的数据库</li>

<h2 id="回顾与导入">回顾与导入</h2>
<p>目前，我们完成了多模块工程的搭建，建立了 book-common、book-user、book-product、book-order 四个模块。本节课将进行<strong>服务拆分与接口设计</strong>。</p>
<p>其中<strong>商品服务和用户服务</strong>的 CRUD 较为简单，直接继承 MyBatis-Plus 的 <code>ServiceImpl</code> 即可。但<strong>订单服务</strong>的业务逻辑更复杂：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    A[创建订单请求] --&gt; B[生成订单编号]
    B --&gt; C[保存订单主表 orders]
    C --&gt; D[为每个商品创建快照 item]
    D --&gt; E[创建订单明细 order_item]
    E --&gt; F[计算订单总金额]
    F --&gt; G[返回订单详情]

    style A fill:#e3f2fd
    style G fill:#e8f5e9
</code></pre></div>

<p>订单服务需要同时操作 <strong>orders、item、order_item 三张表</strong>，并在一个事务中保证数据一致性。</p>
<h2 id="分库设计">分库设计</h2>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    A[book-product&lt;br/&gt;商品服务] --&gt; B[(book_product_db&lt;br/&gt;product表)]
    C[book-user&lt;br/&gt;用户服务] --&gt; D[(book_user_db&lt;br/&gt;users表)]
    E[book-order&lt;br/&gt;订单服务] --&gt; F[(book_order_db&lt;br/&gt;orders/order_item/item表)]

    style A fill:#e3f2fd
    style C fill:#e8f5e9
    style E fill:#fff3e0
</code></pre></div>

<blockquote>
<p><strong>分库原则：</strong> 每个微服务拥有独立的数据库，服务之间不能直接访问对方的数据库，只能通过 API 调用获取数据。</p>
</blockquote>
<h2 id="EntityDTOVO-的定位与区别">Entity、DTO、VO 的定位与区别</h2>
<p>在分层架构中，我们经常需要用到三种不同的数据结构，初学者容易混淆它们。理解它们的定位，是设计清晰接口的前提。</p>
<h3 id="三者的定位">三者的定位</h3>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart LR
    Client[前端/调用方] --&gt;|DTO| Controller
    Controller --&gt;|Entity| Service
    Service --&gt;|Entity| Mapper
    Mapper --&gt; DB[(数据库)]
    Controller --&gt;|VO| Client
</code></pre></div>

<table>
<thead>
<tr>
<th>结构</th>
<th>全称</th>
<th>定位</th>
<th>使用位置</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Entity</strong></td>
<td>实体类</td>
<td>数据库表的映射，字段与表结构一一对应</td>
<td>Mapper / Service 层</td>
</tr>
<tr>
<td><strong>DTO</strong></td>
<td>Data Transfer Object</td>
<td>接收前端请求参数，通常包含校验注解</td>
<td>Controller 入参</td>
</tr>
<tr>
<td><strong>VO</strong></td>
<td>View Object</td>
<td>返回给前端的展示数据，可以组合多个 Entity</td>
<td>Controller 出参</td>
</tr>
</tbody>
</table>
<h3 id="为什么不能只用-Entity">为什么不能只用 Entity</h3>
<table>
<thead>
<tr>
<th>问题</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>暴露数据库结构</strong></td>
<td>Entity 包含表的所有字段（如 <code>deleted</code>、<code>internal_remark</code>），不应返回给前端</td>
</tr>
<tr>
<td><strong>无法组合数据</strong></td>
<td>订单详情需要同时返回订单主表和订单项，Entity 无法表达</td>
</tr>
<tr>
<td><strong>无法承载校验</strong></td>
<td>创建订单时，<code>userId</code> 和 <code>items</code> 需要校验，而 Entity 只对应单表</td>
</tr>
<tr>
<td><strong>耦合数据库</strong></td>
<td>数据库字段调整会直接影响前端接口</td>
</tr>
</tbody>
</table>

<h3 id="VO-转换不要手写大量-set">VO 转换：不要手写大量 set</h3>
<p>传统写法（不推荐）：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="w"> </span><span class="n">itemVO</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="p">();</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setItemId</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getId</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setProductId</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getProductId</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setTitle</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getTitle</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setAuthor</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getAuthor</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setPrice</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getPrice</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setQuantity</span><span class="p">(</span><span class="n">orderItem</span><span class="p">.</span><span class="na">getQuantity</span><span class="p">());</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setSubtotal</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getPrice</span><span class="p">()</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="n">orderItem</span><span class="p">.</span><span class="na">getQuantity</span><span class="p">());</span>
</code></pre></div>

<p>当一个 VO 有 10 多个字段时，会写大量重复的 set 方法，容易遗漏且难以维护。</p>
<p>推荐使用 <strong>BeanUtils</strong>（Spring 自带）或 <strong>Hutool库 的 BeanUtil</strong> 自动拷贝同名属性：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// Spring 的 BeanUtils（book-common 已通过 spring-boot-starter-web 间接引入）</span>
<span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="w"> </span><span class="n">itemVO</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="p">();</span>
<span class="n">BeanUtils</span><span class="p">.</span><span class="na">copyProperties</span><span class="p">(</span><span class="n">item</span><span class="p">,</span><span class="w"> </span><span class="n">itemVO</span><span class="p">);</span><span class="w">      </span><span class="c1">// 自动拷贝同名属性</span>
<span class="n">BeanUtils</span><span class="p">.</span><span class="na">copyProperties</span><span class="p">(</span><span class="n">orderItem</span><span class="p">,</span><span class="w"> </span><span class="n">itemVO</span><span class="p">);</span><span class="w"> </span><span class="c1">// 后拷贝的覆盖前面的同名属性</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setSubtotal</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getPrice</span><span class="p">()</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="n">orderItem</span><span class="p">.</span><span class="na">getQuantity</span><span class="p">());</span><span class="w"> </span><span class="c1">// 计算字段手动设置</span>
</code></pre></div>

<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// Hutool 的 BeanUtil（推荐，功能更强大）</span>
<span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="w"> </span><span class="n">itemVO</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">BeanUtil</span><span class="p">.</span><span class="na">copyProperties</span><span class="p">(</span><span class="n">item</span><span class="p">,</span><span class="w"> </span><span class="n">OrderDetailVO</span><span class="p">.</span><span class="na">OrderItemVO</span><span class="p">.</span><span class="na">class</span><span class="p">);</span>
<span class="n">BeanUtil</span><span class="p">.</span><span class="na">copyProperties</span><span class="p">(</span><span class="n">orderItem</span><span class="p">,</span><span class="w"> </span><span class="n">itemVO</span><span class="p">);</span>
<span class="n">itemVO</span><span class="p">.</span><span class="na">setSubtotal</span><span class="p">(</span><span class="n">item</span><span class="p">.</span><span class="na">getPrice</span><span class="p">()</span><span class="w"> </span><span class="o">*</span><span class="w"> </span><span class="n">orderItem</span><span class="p">.</span><span class="na">getQuantity</span><span class="p">());</span>
</code></pre></div>

<h2 id="注意事项">注意事项</h2>
<ol>
<li><strong>事务一致性</strong>：<code>createOrder</code> 需要操作三张表，必须使用 <code>@Transactional</code> 保证数据一致性。</li>
<li><strong>商品快照</strong>：订单保存商品快照（item 表）而不是直接引用商品表，避免商品信息变更影响历史订单。</li>
<li><strong>VO 转换</strong>：使用 <code>BeanUtil.copyProperties</code> 自动拷贝同名属性，避免手写大量 set 方法。对于需要计算的字段（如 <code>subtotal</code>），需要手动设置。</li>
<li><strong>BeanUtil 拷贝顺序</strong>：先拷贝 <code>item</code>，再拷贝 <code>orderItem</code>，后者会覆盖同名的 <code>price</code> 字段（因为订单项的价格是下单时的快照价）。</li>
<li><strong>分库设计</strong>：三个服务对应三个数据库，服务之间不能直接访问对方的数据库。</li>
<li><strong>后续演进</strong>：创建订单时还应该扣减商品库存，这需要调用商品服务（远程调用），将在后续章节中引入 OpenFeign 后实现。</li>
<li><strong>订单编号生成</strong>：使用"ORD + 时间戳 + 序列号"的格式，生产环境应使用分布式 ID 生成器。</li>
</ol>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>分库设计</strong>：三个业务服务对应三个独立数据库。</li>
<li><strong>Entity、DTO、VO 的定位与区别</strong>：
   - <strong>Entity</strong>：数据库表映射，用于 Mapper / Service 层
   - <strong>DTO</strong>：接收请求参数，带校验注解，用于 Controller 入参
   - <strong>VO</strong>：返回展示数据，可组合多个 Entity，用于 Controller 出参</li>
<li><strong>VO 转换简化</strong>：使用 Hutool 的 <code>BeanUtil.copyProperties</code> 自动拷贝同名属性，避免手写 set 方法。</li>
<li><strong>订单服务的复杂实现（重点）</strong>：
   - <code>createOrder</code> 方法操作三张表（orders、item、order_item）
   - 使用 <code>@Transactional</code> 保证事务一致性
   - 商品快照设计保证历史订单不受商品变更影响
   - 使用 <code>BeanUtil</code> 简化 Entity 与 VO 之间的转换</li>
<li><strong>IDEA HTTP Request 测试</strong>：编写 <code>.http</code> 文件，一键执行接口测试。</li>
</ol>
