<h2 id="Nacos集群架构原理">Nacos集群架构原理</h2>
<h3 id="为什么至少需要3个节点">为什么至少需要3个节点</h3>
<p>Nacos集群的配置中心模块依赖Raft协议实现数据一致性。Raft协议要求集群中超过半数（含半数）的节点存活才能正常工作，且选举Leader时也需要多数节点参与投票。2个节点的情况下，如果1个节点宕机，剩余1个节点无法构成多数（2的半数仍为1，但Raft要求严格多数），整个集群将无法选举出Leader，导致配置管理功能不可用。</p>
<p>因此，Nacos集群至少需要3个节点，这是工程纪律。在3节点集群中，允许1个节点故障而不影响整体可用性。</p>
<table>
<thead>
<tr>
<th>集群规模</th>
<th>容忍故障节点数</th>
<th>适用场景</th>
</tr>
</thead>
<tbody>
<tr>
<td>1节点</td>
<td>0</td>
<td>开发测试</td>
</tr>
<tr>
<td>3节点</td>
<td>1</td>
<td>生产环境最低要求</td>
</tr>
<tr>
<td>5节点</td>
<td>2</td>
<td>大规模生产环境</td>
</tr>
</tbody>
</table>
<h3 id="Nacos集群的两种协议">Nacos集群的两种协议</h3>
<p>Nacos集群内部使用两种协议处理不同类型的数据：</p>
<table>
<thead>
<tr>
<th>协议</th>
<th>处理数据类型</th>
<th>一致性模型</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Raft</strong></td>
<td>配置中心数据、持久化实例</td>
<td>CP（强一致）</td>
<td>写入需要多数节点确认，保证配置数据不丢失</td>

<td>临时实例的服务注册数据</td>

</tr>

<p>无论采用何种部署方式，推荐将Nacos集群中所有服务节点放到一个VIP（虚拟IP）下面，然后挂到一个域名下面。这样客户端只需要连接统一入口，无需感知后端具体节点，集群扩缩容时也不需要修改客户端配置。</p>

<h3 id="客户端直连的寻址机制">客户端直连的寻址机制</h3>
<p>Nacos客户端默认提供基于配置的 <code>PropertiesServerListProvider</code>，从 <code>server-addr</code> 配置中获取服务端地址列表。当配置中存在多个服务端地址时，Nacos客户端会用逗号或分号拆分地址列表，并随机选择一个作为当前连接的服务端地址。如果当前选中的地址不可用，客户端会以轮询方式逐一尝试其他地址；尝试完所有地址后，会回到第一个地址继续轮询，直到找到可用地址或客户端停止。</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848,127.0.0.1:8849,127.0.0.1:8850</span>
<span class="w">      </span><span class="nt">config</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848,127.0.0.1:8849,127.0.0.1:8850</span>
</code></pre></div>

<p>这种寻址方式的最大优点是客户端配置非常简单，只需配置 <code>server-addr</code> 即可，无需额外的服务端地址列表配置或额外组件部署。缺点是无法动态修改服务端地址列表，要变更必须创建新的Nacos客户端。</p>

<h2 id="部署Nacos集群节点">部署Nacos集群节点</h2>
<h3 id="解压Nacos安装包">解压Nacos安装包</h3>
<p>由于本机模拟需要3个节点，我们将Nacos解压到3个不同的目录。</p>
<h3 id="配置clusterconf集群文件">配置cluster.conf集群文件</h3>
<p>在<strong>每个节点</strong>的<code>conf</code>目录下，编辑<code>cluster.conf</code>文件，列出集群中所有节点的地址，每行一个节点：</p>
<div class="codehilite lang-bash"><pre><span></span><code><span class="c1"># cluster.conf 内容（三个节点保持一致）：</span>
<span class="m">127</span>.0.0.1:8848
<span class="m">127</span>.0.0.1:8858
<span class="m">127</span>.0.0.1:8868
</code></pre></div>

<h3 id="配置PostgreSQL数据源">配置PostgreSQL数据源</h3>
<p>在<strong>每个节点</strong>的<code>conf/application.properties</code>文件中，添加PostgreSQL数据源配置。首先注释掉或删除原有的Derby配置，然后添加以下内容：</p>
<div class="codehilite lang-properties"><pre><span></span><code><span class="c1"># 数据库类型</span>
<span class="na">spring.sql.init.platform</span><span class="o">=</span><span class="s">postgresql</span>

<span class="c1"># 数据库实例数量</span>
<span class="na">db.num</span><span class="o">=</span><span class="s">1</span>

<span class="c1"># 数据库连接 URL</span>
<span class="na">db.url.0</span><span class="o">=</span><span class="s">jdbc:postgresql://127.0.0.1:5432/nacos?currentSchema=public</span>

<span class="c1"># 数据库用户名和密码</span>
<span class="na">db.user</span><span class="o">=</span><span class="s">postgres</span>
<span class="na">db.password</span><span class="o">=</span><span class="s">admin</span>

<span class="c1"># JDBC 驱动类名 (此配置项至关重要)</span>
<span class="na">db.pool.config.driverClassName</span><span class="o">=</span><span class="s">org.postgresql.Driver</span>

<span class="c1"># (可选) 连接测试查询</span>
<span class="na">db.pool.config.connectionTestQuery</span><span class="o">=</span><span class="s">SELECT 1</span>
</code></pre></div>

<blockquote>
<p><strong>说明：</strong> <code>db.url.0</code>中的<code>.0</code>表示第0个数据库实例。如果使用PostgreSQL主备架构，可以配置<code>db.num=2</code>并添加<code>db.url.1</code>、<code>db.user.1</code>、<code>db.password.1</code>。</p>
</blockquote>
<h3 id="修改节点端口">修改节点端口</h3>
<p>由于本机模拟3个节点，需要为每个节点配置不同的端口。在每个节点的<code>conf/application.properties</code>中添加：</p>
<div class="codehilite lang-properties"><pre><span></span><code><span class="c1"># 节点1</span>
<span class="na">nacos.server.main.port</span><span class="o">=</span><span class="s">8848</span>

<span class="c1"># 节点2</span>
<span class="na">nacos.server.main.port</span><span class="o">=</span><span class="s">8858</span>

<span class="c1"># 节点3</span>
<span class="na">nacos.server.main.port</span><span class="o">=</span><span class="s">8868</span>
</code></pre></div>

<h3 id="修改控制台端口">修改控制台端口</h3>
<div class="codehilite lang-properties"><pre><span></span><code><span class="c1"># 节点1</span>
<span class="na">nacos.console.port</span><span class="o">=</span><span class="s">8080</span>

<span class="c1"># 节点2</span>
<span class="na">nacos.console.port</span><span class="o">=</span><span class="s">8081</span>

<span class="c1"># 节点3</span>
<span class="na">nacos.console.port</span><span class="o">=</span><span class="s">8082</span>
</code></pre></div>

<h2 id="启动Nacos集群">启动Nacos集群</h2>
<h3 id="启动命令">启动命令</h3>
<p>在每个节点的<code>bin</code>目录下，执行启动命令。<strong>注意：</strong> 集群模式不需要加<code>-m standalone</code>参数。</p>
<p>如果已经在<code>application.properties</code>中配置了鉴权信息，启动时不会提示输入。否则，启动程序会提示输入3个鉴权相关配置（<code>NACOS_AUTH_TOKEN</code>、<code>NACOS_AUTH_IDENTITY_KEY</code>、<code>NACOS_AUTH_IDENTITY_VALUE</code>）。</p>
<h3 id="查看启动日志">查看启动日志</h3>
<p>进入每个节点的<code>logs</code>目录，查看<code>start.out</code>文件，确认启动成功：</p>
<div class="codehilite"><pre><span></span><code>Nacos started successfully in cluster mode with external storage in 11183 ms
</code></pre></div>

<blockquote>
<p><strong>注意：</strong> 日志中应显示 <code>cluster mode</code> 和 <code>external storage</code>（表示使用外部PostgreSQL存储），而非单机模式的 <code>stand alone mode. use embedded storage</code>。</p>
</blockquote>

<h2 id="高可用验证实战">高可用验证实战</h2>
<h3 id="验证一节点状态检查">验证一：节点状态检查</h3>
<p>访问任意节点的控制台，在“集群管理 → 节点列表”中确认3个节点状态均为UP。</p>
<h3 id="验证二停止一个节点验证服务可用">验证二：停止一个节点，验证服务可用</h3>
<p>模拟节点故障，停止节点3。</p>
<p><strong>预期结果：</strong></p>
<ol>
<li>控制台的节点列表中，节点3的状态变为DOWN或消失</li>
<li>剩余2个节点仍然正常工作（3节点中剩余2个，满足多数原则）</li>
<li>服务注册与配置管理功能不受影响</li>
<li>配置了多节点地址的客户端自动切换到其他可用节点</li>
</ol>
<h3 id="验证三恢复节点验证重新加入">验证三：恢复节点，验证重新加入</h3>
<p>重新启动节点3。</p>
<p><strong>预期结果：</strong></p>
<ol>
<li>节点3自动加入集群，状态恢复为UP</li>
<li>节点3自动从其他节点同步数据（配置信息、服务列表等）</li>
<li>数据保持一致</li>
</ol>
<h2 id="注意事项">注意事项</h2>
<ol>
<li>
<p><strong>节点数量要求</strong>：Nacos集群至少需要3个节点，这是Raft协议保证一致性的基本要求。2个节点无法在故障时构成多数。</p>
</li>
<li>
<p><strong>PostgreSQL共享存储</strong>：集群模式下必须使用外部PostgreSQL数据库，Derby不支持集群模式。每个节点都需要配置相同的PostgreSQL数据源。</p>
</li>
<li>
<p><strong>cluster.conf一致性</strong>：所有节点的<code>cluster.conf</code>文件内容必须完全一致，否则会出现节点无法正确发现其他成员的问题。</p>
</li>
<li>
<p><strong>端口规划</strong>：Nacos 3.x的控制台端口为8080，与Spring Boot应用常用的8080端口可能冲突，需要注意。</p>
</li>
<li>
<p><strong>客户端直连的局限性</strong>：直连模式下集群扩缩容需要更新所有客户端配置。如果集群规模较大或客户端数量较多，建议引入Nginx/SLB作为统一入口。</p>
</li>
</ol>

</li>
<li>
<p><strong>集群启动与验证</strong>：启动3个节点、通过控制台方式验证集群状态。</p>
