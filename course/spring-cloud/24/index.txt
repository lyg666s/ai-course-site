<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">server</span><span class="p">:</span>
<span class="w">  </span><span class="nt">port</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">8081</span>
<span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">application</span><span class="p">:</span>
<span class="w">    </span><span class="nt">name</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">book-product</span>
<span class="w">  </span><span class="nt">datasource</span><span class="p">:</span>

<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>

<p>这种“配置跟着代码走”的方式存在三个明显的问题：</p>
<table>
<thead>
<tr>
<th>问题</th>
<th>后果</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>改配置要重新打包重启</strong></td>

</tr>
<tr>
<td><strong>配置无法审计</strong></td>

<h2 id="配置中心核心概念与模型">配置中心核心概念与模型</h2>
<h3 id="配置中心的定位">配置中心的定位</h3>
<p>配置中心（Config Center）与注册中心（Registry Center）是Nacos的两大核心能力，两者职责不同：</p>
<table>
<thead>
<tr>
<th>维度</th>
<th>注册中心</th>
<th>配置中心</th>
</tr>
</thead>
<tbody>
<tr>
<td>管理对象</td>
<td>服务实例的地址、健康状态、权重</td>
<td>应用的配置项（数据库连接、业务参数、日志级别等）</td>
</tr>
<tr>
<td>数据变化频率</td>
<td>较高（实例上下线）</td>
<td>较低（配置发布）</td>
</tr>
<tr>
<td>消费方式</td>
<td>服务发现、负载均衡</td>
<td>启动时加载 + 运行时动态刷新</td>
</tr>
<tr>
<td>Nacos对应能力</td>
<td>Nacos Discovery</td>
<td>Nacos Config</td>
</tr>
</tbody>
</table>
<p>在Spring Cloud Alibaba中，<code>spring-cloud-starter-alibaba-nacos-config</code>负责配置中心能力，<code>spring-cloud-starter-alibaba-nacos-discovery</code>负责注册中心能力。两者可以独立使用，也可以共存——本项目两者都会使用。</p>
<h3 id="配置的寻址模型DataId">配置的寻址模型：DataId</h3>
<p>Nacos中的每份配置由<code>DataId</code>唯一标识。在Spring Cloud Alibaba的默认约定下，<code>DataId</code>的构成是：</p>
<div class="codehilite"><pre><span></span><code>${spring.cloud.nacos.config.prefix}-${spring.profiles.active}.${spring.cloud.nacos.config.file-extension}
</code></pre></div>

<table>
<thead>
<tr>
<th>部分</th>
<th>默认值</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>prefix</code></td>
<td><code>${spring.application.name}</code></td>
<td>应用名，即<code>book-product</code></td>
</tr>
<tr>
<td><code>profiles.active</code></td>
<td>无（此时不含横杠和profile段）</td>
<td>如<code>dev</code>、<code>test</code></td>
</tr>
<tr>
<td><code>file-extension</code></td>
<td><code>properties</code></td>
<td>配置格式，本课程使用<code>yml</code></td>
</tr>
</tbody>
</table>
<p>为了避免profile为空导致DataId拼接异常，实际配置中通常会<strong>显式通过<code>spring.config.import</code>指定DataId</strong>，而不是完全依赖默认拼接。本节的推荐写法是：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">config</span><span class="p">:</span>
<span class="w">    </span><span class="nt">import</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">optional:nacos:book-product.yml</span>
</code></pre></div>

<blockquote>
<p><strong><code>optional:</code>前缀的作用：</strong> 如果Nacos中暂时没有这个DataId，应用不会启动失败，而是继续使用本地配置。这在“先集成、后迁移”的过渡阶段非常有用。但<strong>迁移完成后，建议去掉<code>optional:</code></strong>，让“配置缺失”在启动时就暴露出来，而不是等到运行时才发现某个配置项没读到。</p>
</blockquote>
<h2 id="迁移前的准备确认依赖与本地配置">迁移前的准备：确认依赖与本地配置</h2>
<h3 id="确认依赖">确认依赖</h3>
<p>确保<code>pom.xml</code>中已经包含Nacos Config依赖：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.alibaba.cloud<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-cloud-starter-alibaba-nacos-config<span class="nt">&lt;/artifactId&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<h3 id="本地applicationyml只保留接入配置">本地application.yml：只保留“接入配置”</h3>
<p>迁移的核心原则是：<strong>本地只保留“如何连上Nacos”的配置，业务配置全部迁移到Nacos</strong>。</p>
<p>迁移前，book-product的<code>application.yml</code>包含端口、数据源、MyBatis-Plus、Nacos Discovery等配置。迁移时，需要区分两类配置：</p>
<table>
<thead>
<tr>
<th>配置类型</th>
<th>是否迁移</th>
<th>理由</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>spring.config.import</code></td>
<td><strong>不迁移</strong></td>
<td>这是接入配置中心的“入口”，必须在本地</td>
</tr>
<tr>
<td><code>spring.cloud.nacos.discovery.*</code></td>
<td>可保留在本地</td>
<td>服务发现配置；后续可再迁移，本节先保留</td>
</tr>
<tr>
<td><code>spring.application.name</code></td>
<td><strong>不迁移</strong></td>
<td>应用名是启动的基础标识</td>
</tr>
<tr>
<td><code>server.port</code></td>
<td>迁移</td>
<td>属于业务配置</td>
</tr>
<tr>
<td><code>spring.datasource.*</code></td>
<td>迁移</td>
<td>数据源配置</td>
</tr>
<tr>
<td><code>mybatis-plus.*</code></td>
<td>迁移</td>
<td>ORM配置</td>
</tr>
<tr>
<td>业务自定义配置（如超时时间、开关）</td>
<td>迁移</td>
<td>最典型的配置中心内容</td>
</tr>
</tbody>
</table>
<p><strong>迁移后的本地<code>application.yml</code>：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">application</span><span class="p">:</span>
<span class="w">    </span><span class="nt">name</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">book-product</span>
<span class="w">  </span><span class="nt">config</span><span class="p">:</span>
<span class="w">    </span><span class="nt">import</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">optional:nacos:book-product.yml</span><span class="w">    </span><span class="c1"># 从Nacos导入配置</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">config</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
<span class="w">        </span><span class="nt">file-extension</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">yml</span><span class="w">                     </span><span class="c1"># DataId后缀为yml</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
<span class="w">        </span><span class="nt">group</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEFAULT_GROUP</span>
</code></pre></div>

<blockquote>
<p><strong><code>file-extension: yml</code>必须显式配置。</strong> 默认后缀是<code>properties</code>，如果Nacos中的DataId是<code>book-product.yml</code>，本地不声明<code>file-extension: yml</code>，默认拼接或解析时可能不匹配。</p>
</blockquote>
<h2 id="在Nacos中创建配置">在Nacos中创建配置</h2>

<h2 id="验证迁移结果">验证迁移结果</h2>
<h3 id="启动book-product">启动book-product</h3>
<p><strong>启动日志中应出现配置加载相关记录：</strong></p>
<div class="codehilite"><pre><span></span><code> [Nacos Config] Listening config: dataId=book-product.yml, group=DEFAULT_GROUP
</code></pre></div>

<p>如果日志中没有出现类似记录，或者启动时提示“No spring.config.import property has been defined”，说明<code>spring.config.import</code>没有正确配置，或者依赖的导入检查未通过。</p>
<h3 id="验证端口与数据源">验证端口与数据源</h3>
<p><strong>验证端口：</strong> book-product的<code>server.port</code>已经从本地迁移到Nacos，如果Nacos中的配置是<code>8081</code>，服务应正常监听8081。将Nacos中的<code>server.port</code>临时改为<code>8091</code>，<strong>重启</strong>book-product（端口变更不是动态刷新的典型场景，通常需要重启才能生效），确认服务监听8091而不是8081。验证完成后改回8081。</p>
<p><strong>验证数据源：</strong> 调用任意需要数据库的接口（如<code>GET /api/products/1</code>），确认数据源配置正确加载。如果数据源配置没有从Nacos读到，启动时会因无法连接数据库而失败。</p>
<h3 id="验证业务配置已从本地移除">验证业务配置已从本地移除</h3>
<p>打开本地的<code>application.yml</code>，确认<code>server.port</code>、<code>spring.datasource.*</code>、<code>mybatis-plus.*</code>、<code>book.product.*</code>等配置<strong>已经删除</strong>。如果本地还保留着这些配置，Nacos中的同名配置会把本地配置给覆盖（Spring Boot的配置优先级中，本地<code>application.yml</code>通常低于导入的远程配置），迁移就“看起来生效了但实际上没生效”。</p>
<blockquote>
<p><strong>检查方法：</strong> 在Nacos中将<code>book.product.page-size</code>改为<code>20</code>，而本地<code>application.yml</code>中不写这一项。如果应用读到的是<code>20</code>，说明配置确实来自Nacos；如果读到的是某个默认值或旧值，说明本地可能还有残留。</p>
</blockquote>
<h2 id="验证动态刷新">验证动态刷新</h2>
<p>配置迁移的最终目的不仅是“启动时从Nacos读配置”，更是“修改配置无需重启”。</p>
<h3 id="使用RefreshScope验证Value">使用@RefreshScope验证@Value</h3>
<p>在book-product中创建一个读取<code>book.product.page-size</code>的Controller：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@RestController</span>
<span class="nd">@RequestMapping</span><span class="p">(</span><span class="s">"/api/config"</span><span class="p">)</span>
<span class="nd">@RefreshScope</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">ConfigDemoController</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="nd">@Value</span><span class="p">(</span><span class="s">"${book.product.page-size:10}"</span><span class="p">)</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">Integer</span><span class="w"> </span><span class="n">pageSize</span><span class="p">;</span>

<span class="w">    </span><span class="nd">@GetMapping</span><span class="p">(</span><span class="s">"/page-size"</span><span class="p">)</span>
<span class="w">    </span><span class="kd">public</span><span class="w"> </span><span class="n">Result</span><span class="o">&lt;</span><span class="n">Integer</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">getPageSize</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="k">return</span><span class="w"> </span><span class="n">Result</span><span class="p">.</span><span class="na">success</span><span class="p">(</span><span class="n">pageSize</span><span class="p">);</span>
<span class="w">    </span><span class="p">}</span>
<span class="p">}</span>
</code></pre></div>

<p><strong>关键点：</strong></p>
<table>
<thead>
<tr>
<th>要点</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>@RefreshScope</code></td>
<td>标记该Bean在配置刷新时重建，<code>@Value</code>注入的值随之更新</td>
</tr>
<tr>
<td><code>@Value</code>的默认值</td>
<td><code>${book.product.page-size:10}</code>，配置缺失时使用10，避免启动失败</td>
</tr>
<tr>
<td>刷新触发</td>
<td>Nacos中修改配置并发布后，Nacos客户端通过gRPC长连接感知变更，触发刷新</td>
</tr>
</tbody>
</table>
<blockquote>
<p><strong><code>@RefreshScope</code>的适用范围：</strong> 它只对通过<code>@Value</code>或<code>@ConfigurationProperties</code>注入的属性有效。静态字段、构造器注入的属性不会被刷新。对于需要动态刷新的配置类，优先使用<code>@ConfigurationProperties</code>（见下）。</p>
</blockquote>
<h3 id="使用ConfigurationProperties验证配置类">使用@ConfigurationProperties验证配置类</h3>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@Component</span>
<span class="nd">@ConfigurationProperties</span><span class="p">(</span><span class="n">prefix</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="s">"book.product"</span><span class="p">)</span>
<span class="nd">@RefreshScope</span>
<span class="nd">@Data</span>
<span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">BookProductProperties</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">Integer</span><span class="w"> </span><span class="n">pageSize</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="mi">10</span><span class="p">;</span>
<span class="w">    </span><span class="kd">private</span><span class="w"> </span><span class="n">Boolean</span><span class="w"> </span><span class="n">cacheEnabled</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="kc">true</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div>

<p>然后在Controller中注入该配置类并返回：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@GetMapping</span><span class="p">(</span><span class="s">"/properties"</span><span class="p">)</span>
<span class="kd">public</span><span class="w"> </span><span class="n">Result</span><span class="o">&lt;</span><span class="n">Integer</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">getProperties</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">Result</span><span class="p">.</span><span class="na">success</span><span class="p">(</span><span class="n">properties</span><span class="p">.</span><span class="na">getPageSize</span><span class="p">());</span>
<span class="p">}</span>
</code></pre></div>

<p><code>@ConfigurationProperties</code>相对于<code>@Value</code>的优势：支持批量绑定、类型安全、支持JSR-303校验，更适合“一组配置项”的场景。</p>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li>
<p><strong>配置中心的定位</strong>：管理应用的配置项，支持启动加载和运行时动态刷新，与注册中心的职责不同。</p>
</li>
<li>
<p><strong>2025.x的两个版本前提</strong>：必须使用<code>spring.config.import</code>（bootstrap已废弃）</p>
</li>
<li>
<p><strong>配置寻址模型</strong>：DataId由prefix、profile、file-extension构成；本课程通过<code>spring.config.import</code>显式指定<code>book-product.yml</code>。</p>
</li>
<li>
<p><strong>迁移原则</strong>：本地只保留<code>spring.config.import</code>、<code>spring.cloud.nacos.config.*</code>、<code>username/password</code>、<code>spring.application.name</code>；业务配置全部迁移到Nacos。</p>
</li>
<li>
<p><strong>迁移流程</strong>：确认依赖 → 精简本地配置 → 在Nacos创建DataId → 迁移业务配置 → 启动验证 → 确认本地无残留。</p>
</li>
<li>
<p><strong>动态刷新验证</strong>：<code>@RefreshScope</code> + <code>@Value</code>或<code>@ConfigurationProperties</code>，修改Nacos配置后无需重启即可生效。</p>
</li>
</ol>
