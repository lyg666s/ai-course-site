<h2 id="Group分组核心概念">Group分组核心概念</h2>
<h3 id="Group在服务注册中的作用">Group在服务注册中的作用</h3>
<p>Group 是 Nacos 分级模型中的第二层，位于 Namespace 之下、Service 之上。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TB
    N[Nacos Server] --&gt; NS1[Namespace: dev]
    N --&gt; NS2[Namespace: test]
    N --&gt; NS3[Namespace: public]

    NS1 --&gt; G1[Group: DEFAULT_GROUP]
    NS1 --&gt; G2[Group: ORDER_GROUP]

    G1 --&gt; D2[Service: book-product]
    G2 --&gt; D3[Service: book-order]

    NS2 --&gt; G3[Group: DEFAULT_GROUP]
    G3 --&gt; D5[Service: book-product]

    style N fill:#e3f2fd
    style NS1 fill:#e8f5e9
    style NS2 fill:#fff3e0
    style NS3 fill:#f3e5f5
</code></pre></div>

<p>它的核心作用是<strong>在同一个 Namespace 内实现服务的逻辑分组</strong>。</p>
<table>
<thead>
<tr>
<th>特性</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>逻辑隔离</strong></td>
<td>同一 Namespace 内，不同 Group 的服务默认互相不可见</td>
</tr>
<tr>
<td><strong>业务线划分</strong></td>
<td>适合按业务线、项目、团队进行分组</td>
</tr>
<tr>
<td><strong>配置共享</strong></td>
<td>同一 Group 内的服务可以共享配置（配置中心场景）</td>
</tr>
<tr>
<td><strong>灵活组合</strong></td>
<td>与 Namespace 组合使用，实现多维度的隔离</td>
</tr>
</tbody>
</table>
<h3 id="Namespace与Group的分工">Namespace与Group的分工</h3>
<table>
<thead>
<tr>
<th>维度</th>
<th>Namespace</th>
<th>Group</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>隔离级别</strong></td>
<td>环境级隔离（dev/test/prod）</td>
<td>业务线级隔离（order/product/user）</td>
</tr>
<tr>
<td><strong>数据可见性</strong></td>
<td>不同 Namespace 完全不可见</td>
<td>同 Namespace 内不同 Group 默认不可见</td>
</tr>
<tr>
<td><strong>常用场景</strong></td>
<td>环境隔离、多租户</td>
<td>业务线隔离、灰度分组</td>
</tr>
<tr>
<td><strong>配置复杂度</strong></td>
<td>需要创建多个 Namespace</td>
<td>只需修改 <code>group</code> 配置项</td>
</tr>
<tr>
<td><strong>推荐用法</strong></td>
<td>切环境</td>
<td>切业务线</td>
</tr>
</tbody>
</table>
<blockquote>
<p><strong>重要原则：</strong> 不要用 Group 来替代 Namespace 做环境隔离。Namespace 的隔离更彻底（不同 Namespace 的数据在逻辑存储层面就是独立的），而 Group 的隔离仅是服务发现层面的。生产环境推荐“Namespace 切环境，Group 切业务线”。</p>
</blockquote>
<h3 id="分组配置的命名规范">分组配置的命名规范</h3>
<table>
<thead>
<tr>
<th>配置项</th>
<th>推荐命名</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td>Namespace ID</td>
<td><code>dev</code>、<code>test</code>、<code>prod</code></td>
<td>简短、明确，按环境命名</td>
</tr>
<tr>
<td>Group</td>
<td><code>DEFAULT_GROUP</code>、<code>ORDER_GROUP</code>、<code>PDODUCT_GROUP</code></td>
<td>全大写，下划线分隔，按业务线命名</td>
</tr>
</tbody>
</table>
<h2 id="为订单服务配置独立Group">为订单服务配置独立Group</h2>
<h3 id="场景说明">场景说明</h3>
<p>在图书管理系统中，我们可以按业务线将服务分组：</p>
<table>
<thead>
<tr>
<th>服务</th>
<th>业务线</th>
<th>Group</th>
</tr>
</thead>
<tbody>
<tr>
<td>book-product</td>
<td>商品</td>
<td><code>DEFAULT_GROUP</code></td>
</tr>
<tr>
<td>book-user</td>
<td>用户</td>
<td><code>DEFAULT_GROUP</code></td>
</tr>
<tr>
<td>book-order</td>
<td>订单</td>
<td><code>ORDER_GROUP</code></td>
</tr>
</tbody>
</table>
<p>这样，book-order 注册在 <code>ORDER_GROUP</code> 下，而 book-product 和 book-user 注册在 <code>DEFAULT_GROUP</code> 下。默认情况下，book-order 无法发现 <code>DEFAULT_GROUP</code> 下的服务，除非显式指定 Group。</p>
<h3 id="修改book-order的Group配置">修改book-order的Group配置</h3>
<p>打开 <code>book-order/src/main/resources/application.yml</code>，将 <code>group</code> 修改为 <code>ORDER_GROUP</code>：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
<span class="w">        </span><span class="nt">group</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">ORDER_GROUP</span><span class="w">    </span><span class="c1"># 订单业务线分组</span>
<span class="w">        </span><span class="nt">metadata</span><span class="p">:</span>
<span class="w">          </span><span class="nt">env</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
</code></pre></div>

<h3 id="验证Group隔离效果">验证Group隔离效果</h3>
<p>在 dev 命名空间中，book-order 默认只能发现 <code>ORDER_GROUP</code> 下的服务。如果 book-order 尝试通过 <code>DiscoveryClient</code> 查询 <code>book-product</code>，默认情况下会查询 <code>ORDER_GROUP</code> 下的 book-product，但 book-product 注册在 <code>DEFAULT_GROUP</code>，因此<strong>查询不到</strong>。</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// 在 book-order 中调用（默认 Group 为 ORDER_GROUP）</span>
<span class="n">List</span><span class="o">&lt;</span><span class="n">ServiceInstance</span><span class="o">&gt;</span><span class="w"> </span><span class="n">instances</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="n">discoveryClient</span><span class="p">.</span><span class="na">getInstances</span><span class="p">(</span><span class="s">"book-product"</span><span class="p">);</span>
<span class="c1">// 返回空列表，因为 book-product 注册在 DEFAULT_GROUP</span>
</code></pre></div>

<blockquote>
<p><strong>说明：</strong> Spring Cloud 的 <code>DiscoveryClient</code> 抽象不支持按 Group 查询，它使用的是全局配置的 Group。因此，在实际项目中，通常不会用 Group 来隔离同一环境内需要互相调用的服务。Group 更适合用于<strong>不需要互相调用</strong>的业务线隔离，或者配合灰度发布场景使用。</p>
</blockquote>
<h3 id="恢复配置">恢复配置</h3>
<p>为了后续课程中 book-order 能正常调用 book-product，建议将 book-order 的 Group 恢复为 <code>DEFAULT_GROUP</code>：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">group</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEFAULT_GROUP</span>
</code></pre></div>

<blockquote>
<p><strong>实践建议：</strong> 在图书管理系统中，三个服务需要互相调用，因此建议统一使用 <code>DEFAULT_GROUP</code>。Group 的隔离能力更适合用于多业务线共存的大型系统。</p>
</blockquote>
<h2 id="环境切换的三种方式">环境切换的三种方式</h2>
<h3 id="方式一直接修改配置文件">方式一：直接修改配置文件</h3>
<p>最简单的方式，直接修改 <code>application.yml</code> 中的 <code>namespace</code> 值：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span><span class="w">   </span><span class="c1"># 切换环境时改为 test</span>
</code></pre></div>

<p><strong>优点：</strong> 简单直接，无需额外配置。
<strong>缺点：</strong> 每次切换都要修改文件，容易出错，且无法同时运行多个环境。
<strong>适用场景：</strong> 本地开发调试，临时切换。</p>
<h3 id="方式二使用Spring-Profiles重点">方式二：使用Spring Profiles（重点）</h3>
<p>Spring Profiles 是 Spring Boot 提供的多环境配置机制。通过为不同环境创建独立的配置文件，可以在启动时动态选择激活哪个环境。</p>
<h4 id="步骤一创建多环境配置文件">步骤一：创建多环境配置文件</h4>
<p>在 <code>src/main/resources</code> 目录下，创建以下配置文件：</p>
<table>
<thead>
<tr>
<th>文件名</th>
<th>用途</th>
<th>关键配置</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>application.yml</code></td>
<td>主配置，存放公共配置，并设置默认激活的 Profile</td>
<td><code>spring.profiles.active: dev</code></td>
</tr>
<tr>
<td><code>application-dev.yml</code></td>
<td>开发环境专属配置</td>
<td><code>namespace: dev</code></td>
</tr>
<tr>
<td><code>application-test.yml</code></td>
<td>测试环境专属配置</td>
<td><code>namespace: test</code></td>
</tr>
</tbody>
</table>
<p><strong>主配置文件 <code>application.yml</code> 示例：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="c1"># 公共配置：所有环境共享</span>
<span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">application</span><span class="p">:</span>
<span class="w">    </span><span class="nt">name</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">book-product</span>
<span class="w">  </span><span class="nt">profiles</span><span class="p">:</span>
<span class="w">    </span><span class="nt">active</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span><span class="w">          </span><span class="c1"># 默认激活开发环境</span>

<span class="c1"># 其他公共配置...</span>
</code></pre></div>

<p><strong>开发环境配置 <code>application-dev.yml</code> 示例：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">server</span><span class="p">:</span>
<span class="w">  </span><span class="nt">port</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">8081</span>

<span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span><span class="w">          </span><span class="c1"># 关键：指定 dev 命名空间 ID</span>
<span class="w">        </span><span class="nt">group</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEFAULT_GROUP</span>
<span class="w">        </span><span class="nt">metadata</span><span class="p">:</span>
<span class="w">          </span><span class="nt">env</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
</code></pre></div>

<p><strong>测试环境配置 <code>application-test.yml</code> 示例：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">server</span><span class="p">:</span>
<span class="w">  </span><span class="nt">port</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">8084</span><span class="w">                    </span><span class="c1"># 同机运行需改端口避免冲突</span>

<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">test</span><span class="w">         </span><span class="c1"># 关键：指定 test 命名空间 ID</span>

<h4 id="步骤二在IDEA中切换Profile">步骤二：在IDEA中切换Profile</h4>
<p>IDEA 提供了两种设置方式，<strong>推荐使用第一种</strong>，操作更直观。</p>
<p><strong>方式1：使用 “Active profiles” 选项（推荐）</strong></p>
<ol>
<li>在左侧选中你的 Spring Boot 启动配置</li>
<li>在右侧面板找到 <strong><code>Active profiles</code></strong> 输入框</li>
<li>填入环境标识：<strong><code>dev</code></strong> 或 <strong><code>test</code></strong></li>
<li>点击 <code>Apply</code> → <code>OK</code> 保存</li>
</ol>
<p>这种方式会传递 <code>-Dspring.profiles.active=dev</code>，<strong>优先级最高</strong>，会覆盖 <code>application.yml</code> 中的默认值。</p>
<p><strong>方式2：使用 “Program arguments” 或 “VM options”</strong></p>
<table>
<thead>
<tr>
<th>方式</th>
<th>位置</th>
<th>填写内容</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>Program arguments</strong>（推荐）</td>
<td><code>Configuration</code> → <code>Program arguments</code></td>
<td><code>--spring.profiles.active=dev</code></td>
</tr>
<tr>
<td><strong>VM options</strong></td>
<td><code>Configuration</code> → <code>VM options</code></td>
<td><code>-Dspring.profiles.active=dev</code></td>
</tr>
</tbody>
</table>
<h4 id="步骤三创建多个运行配置一键切换">步骤三：创建多个运行配置，一键切换</h4>
<p>如果需要在 <code>dev</code> 和 <code>test</code> 之间频繁切换，可以为每个环境创建<strong>独立的运行配置</strong>：</p>
<ol>
<li>在 <code>Edit Configurations</code> 界面，点击左上角 <code>+</code> → 选择 <code>Spring Boot</code></li>
<li>命名为 <code>BookProduct-Dev</code>，Main class 选择启动类，<code>Active profiles</code> 填 <code>dev</code></li>
<li>再次点击 <code>+</code>，创建 <code>BookProduct-Test</code>，<code>Active profiles</code> 填 <code>test</code></li>
<li>以后只需在 IDEA 右上角的运行配置下拉框中切换即可</li>
</ol>
<h4 id="步骤四验证Profile是否生效">步骤四：验证Profile是否生效</h4>
<p>启动应用后，观察控制台日志，应该出现类似以下输出：</p>
<div class="codehilite"><pre><span></span><code>The following 1 profile is active: "dev"
</code></pre></div>

<p>同时，在 Nacos 控制台中：</p>
<ul>
<li>切换到 <strong><code>dev</code> 命名空间</strong>，应能看到 <code>book-product</code> 服务</li>
<li>切换到 <strong><code>test</code> 命名空间</strong>，应能看到另一个 <code>book-product</code> 实例（如果启动了测试环境）</li>
</ul>
<h3 id="方式三使用环境变量">方式三：使用环境变量</h3>
<p>通过环境变量注入命名空间，适用于容器化部署：</p>
<div class="codehilite lang-bash"><pre><span></span><code><span class="nb">export</span><span class="w"> </span><span class="nv">NACOS_NAMESPACE</span><span class="o">=</span>dev
java<span class="w"> </span>-jar<span class="w"> </span>book-product.jar
</code></pre></div>

<p><strong>application.yml 中引用环境变量：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">${NACOS_NAMESPACE:public}</span>
</code></pre></div>

<blockquote>
<p><strong>默认值说明：</strong> <code>${NACOS_NAMESPACE:public}</code> 表示如果环境变量 <code>NACOS_NAMESPACE</code> 未设置，则默认使用 <code>public</code>。</p>
</blockquote>

<h2 id="小结">小结</h2>
<p>本讲我们学习了：</p>
<ol>
<li><strong>Group 分组</strong>：在同一个 Namespace 内实现服务的逻辑分组，适合业务线隔离。</li>
<li><strong>Namespace 与 Group 的分工</strong>：Namespace 切环境，Group 切业务线，两者配合使用。</li>
<li><strong>Group 隔离效果</strong>：同一 Namespace 内，不同 Group 的服务默认互相不可见。</li>
<li><strong>环境切换三种方式</strong>：直接修改配置文件、Spring Profiles、环境变量。</li>
<li><strong>Spring Profiles 实战</strong>：创建 <code>application-dev.yml</code> 和 <code>application-test.yml</code>，通过 IDEA 的 Active profiles 一键切换。</li>
<li><strong>常见问题排查</strong>：Spring Profiles 未生效、Group 隔离导致服务无法发现等。</li>
</ol>
