回顾与导入

在前面的课程中，我们已经在多处使用过 Nacos API，这些 API 散落在各讲中，且大多通过 HTTP 方式调用。在实际项目中，我们往往需要通过 Java SDK 将这些能力集成到业务系统中——服务消费者需要动态感知提供者的实例变化，服务提供者需要上报元数据并动态调整自身状态。

本讲将系统梳理 Nacos 3.x 的 API 体系，并通过两个典型应用场景的 Java SDK 集成，将前面各讲的知识点串联起来。

Nacos 3.x API 分类与鉴权

API 四分类

Nacos 3.x 将 API 从原来的两大类细化为四类。Nacos Open API 根据调用方类型和使用场景，分为 Client Open API、Admin Open API 和 Console Open API。

API 类型 使用方 典型路径 协议 默认鉴权
Client Open API 普通应用、微服务应用 /v3/client/* gRPC 为主，部分 HTTP 1.1 默认不开启
Admin API 运维平台、自动化脚本、管理员 /v3/admin/* HTTP 1.1 默认开启
Console API Nacos 控制台、自定义控制台 UI /v3/console/* HTTP 1.1 默认开启
Inner API 引擎节点间通信 /v3/inner/* gRPC 默认开启

本讲重点： Client Open API（Java SDK） 。它是业务系统集成 Nacos 的主要方式。Admin API 和 Console API 已在前面各讲中通过 HTTP 方式使用过，本讲不再重复。

鉴权方式

Client Open API（Java SDK）通过 gRPC 与 Nacos 服务端通信，鉴权由客户端自动处理。如果启用了鉴权，需要在初始化 SDK 时配置用户名和密码：

Properties props = new Properties();
props.put("serverAddr", "127.0.0.1:8848");
props.put("namespace", "dev");
props.put("username", "nacos");
props.put("password", "your_password");

Java SDK 核心 API：NamingService

NamingService 接口概览

NamingService 是 Nacos Java SDK 中用于服务发现的核心接口。它提供了注册、注销、查询、订阅、加权选择等能力。

方法 说明
registerInstance(serviceName, instance) 注册实例
deregisterInstance(serviceName, instance) 注销实例
getAllInstances(serviceName) 获取所有实例
selectInstances(serviceName, healthy) 获取健康实例
selectOneHealthyInstance(serviceName) 加权随机选一个健康实例
subscribe(serviceName, listener) 订阅服务变更
unsubscribe(serviceName, listener) 取消订阅

初始化 NamingService

public class NacosClientFactory {

    public static NamingService createNamingService(String serverAddr, String namespace) throws Exception {
        Properties props = new Properties();
        props.put("serverAddr", serverAddr);
        props.put("namespace", namespace);
        // 如果启用了鉴权，需要配置用户名和密码
        props.put("username", "nacos");
        props.put("password", "your_password");
        return NacosFactory.createNamingService(props);
    }
}

注意： 一个 NamingService 实例对应一个命名空间。如果需要访问多个命名空间，需要创建多个实例。

场景一：服务消费者动态发现与客户端负载均衡

场景描述

在图书管理系统中，book-order 作为服务消费者，需要动态发现 book-product 的实例列表，并根据实例的健康状态和权重进行客户端负载均衡调用。当 book-product 的实例数量发生变化（扩容、缩容、宕机）时，book-order 应能实时感知并调整路由策略。

传统方式的局限

前面我们通过 DiscoveryClient + RestTemplate 实现了手动服务发现。这种方式存在以下局限：

局限 说明
无自动感知 每次调用都需要手动获取实例列表，无法感知实例的实时变化
无权重选择 instances.get(0) 始终取第一个实例，权重配置不生效
代码侵入性强 每次调用都需要手动构造 URL、处理异常

Java SDK 集成方案

使用 Nacos Java SDK 的 NamingService，可以实现服务订阅监听和加权实例选择。

步骤一：封装服务发现客户端

public class NacosServiceDiscoveryClient {

    private final NamingService namingService;
    private final String serviceName;
    private final String groupName;

    public NacosServiceDiscoveryClient(String serverAddr, String namespace,
           String serviceName, String groupName) throws NacosException {
        this.namingService = NacosClientFactory.creteNamingService(serverAddr, namespace);
        this.serviceName = serviceName;
        this.groupName = groupName;
    }

    /**
     * 订阅服务变更，当实例列表发生变化时触发回调
     */
    public void subscribe(EventListener listener) throws Exception {
        namingService.subscribe(serviceName, groupName, listener);
    }

    /**
     * 获取所有健康实例
     */
    public List<Instance> getAllHealthyInstances() throws Exception {
        return namingService.selectInstances(serviceName, groupName, true);
    }

    /**
     * 加权随机选择一个健康实例（Nacos 内置）
     */
    public Instance selectOneHealthyInstance() throws Exception {
        return namingService.selectOneHealthyInstance(serviceName, groupName);
    }
}

selectOneHealthyInstance 方法会基于实例权重进行加权随机选择。权重越高，被选中的概率越大。

步骤二：注册服务变更监听器并模拟调用

public class BookOrderService {

    public static void main(String[] args) throws Exception {
        NacosServiceDiscoveryClient client = new NacosServiceDiscoveryClient(
                "127.0.0.1:8848",
                "dev",
                "book-product",
                "DEFAULT_GROUP"
        );

        // 注册监听器：实例列表变化时自动触发
        client.subscribe(event -> {
            if (event instanceof NamingEvent namingEvent) {
                System.out.println("服务 " + namingEvent.getServiceName()
                        + " 实例列表已更新，当前实例数: " + namingEvent.getInstances().size());
                for (Instance instance : namingEvent.getInstances()) {
                    System.out.println("  实例: " + instance.getIp() + ":" + instance.getPort()
                            + " 健康=" + instance.isHealthy()
                            + " 权重=" + instance.getWeight()
                            + " 启用=" + instance.isEnabled());
                }
            }
        });

        // 模拟业务调用：每3秒选择一个实例
        while (true) {
            Instance instance = client.selectOneHealthyInstance();
            System.out.println("选中实例: " + instance.getIp() + ":" + instance.getPort()
                    + " 权重=" + instance.getWeight());

            // 使用选中的实例发起远程调用
            String url = "http://" + instance.getIp() + ":" + instance.getPort() + "/api/products/1";
            System.out.println("调用URL: " + url);

            Thread.sleep(3000);
        }
    }
}

场景二：服务提供者动态注册与元数据管理

场景描述

在图书管理系统中，book-product 作为服务提供者，需要在启动时自动注册到 Nacos，并上报元数据（版本、机房、环境等）。同时，book-product 需要根据自身负载情况动态调整权重，实现自适应负载均衡。

业务需求

需求 说明
启动注册 服务启动时自动注册到 Nacos，携带元数据
关闭注销 服务关闭时自动注销，避免流量路由到已停止的实例
元数据上报 上报版本号、机房、环境等信息，供消费者路由使用
动态权重 根据当前 CPU 负载动态调整权重，负载高时降低权重

Java SDK 集成方案

步骤一：封装服务注册客户端

public class NacosServiceRegistry {

    private final NamingService namingService;
    private final String serviceName;
    private final String groupName;
    private final String ip;
    private final int port;

    public NacosServiceRegistry(String serverAddr, String namespace,
                                 String serviceName, String groupName,
                                 String ip, int port) throws Exception {
        this.namingService = NacosClientFactory.creteNamingService(serverAddr, namespace);
        this.serviceName = serviceName;
        this.groupName = groupName;
        this.ip = ip;
        this.port = port;
    }

    /**
     * 注册实例，携带元数据
     */
    public void register(Map<String, String> metadata) throws Exception {
        Instance instance = new Instance();
        instance.setIp(ip);
        instance.setPort(port);
        instance.setWeight(1.0);
        instance.setMetadata(metadata);
        namingService.registerInstance(serviceName, groupName, instance);
        System.out.println("实例注册成功: " + ip + ":" + port + " 元数据: " + metadata);
    }

    /**
     * 注销实例
     */
    public void deregister() throws Exception {
        Instance instance = new Instance();
        instance.setIp(ip);
        instance.setPort(port);
        instance.setServiceName(serviceName);
        namingService.deregisterInstance(serviceName, groupName, instance);
        System.out.println("实例已注销: " + ip + ":" + port);
    }

    /**
     * 动态更新权重
     */
    public void updateWeight(double weight) throws NacosException {
        Instance instance = new Instance();
        instance.setIp(ip);
        instance.setPort(port);
        instance.setServiceName(serviceName);
        instance.setWeight(weight);
        instance.setEnabled(true);
        // 通过registerInstance方法实现更新操作
        namingService.registerInstance(serviceName, groupName, instance);
        System.out.println("权重已更新为: " + weight);
    }
}

步骤二：在服务启动和关闭时调用

public class BookProductApplication {

    private static NacosServiceRegistry registry;

    public static void main(String[] args) throws Exception {
        // 模拟服务启动
        registry = new NacosServiceRegistry(
                "127.0.0.1:8848",
                "dev",
                "book-product",
                "DEFAULT_GROUP",
                "127.0.0.1",
                8081
        );

        // 上报元数据
        Map<String, String> metadata = new HashMap<>();
        metadata.put("version", "1.0.0");
        metadata.put("region", "beijing");
        metadata.put("env", "dev");
        registry.register(metadata);

        // 模拟根据 CPU 负载动态调整权重
        new Thread(() -> {
            while (true) {
                try {
                    double cpuLoad = Math.random(); // 模拟 CPU 负载 0~1
                    double weight = cpuLoad > 0.6 ? 0.2 : 1.0;
                    registry.updateWeight(weight);
                    Thread.sleep(2000);
                } catch (Exception e) {
                    e.printStackTrace();
                }
            }
        }).start();

        // 模拟服务关闭时注销
        Runtime.getRuntime().addShutdownHook(new Thread(() -> {
            try {
                registry.deregister();
            } catch (Exception e) {
                e.printStackTrace();
            }
        }));

        // 保持服务运行
        Thread.sleep(Long.MAX_VALUE);
    }
}

场景对比

维度 场景一：服务消费者 场景二：服务提供者
SDK类 NamingService NamingService
核心方法 subscribe、selectOneHealthyInstance registerInstance、deregisterInstance
数据流向 从 Nacos 拉取实例列表 向 Nacos 推送实例信息
感知方式 事件推送 主动注册/更新
适用场景 服务间调用、灰度路由 服务启动注册、动态权重

注意事项

  1. 一个 SDK 实例对应一个命名空间：NamingService 初始化时指定的 namespace 固定，如需访问多个命名空间，需创建多个 SDK 实例。

  2. 服务订阅是长连接：subscribe 底层基于 gRPC 长连接，Nacos 会实时推送实例变更。确保 gRPC 端口（9848）可访问。

  3. 加权选择需要 Nacos 感知：selectOneHealthyInstance 方法内置了加权随机逻辑，直接使用即可。

  4. 注册与注销成对出现：服务启动时注册，关闭时注销。使用 Runtime.getRuntime().addShutdownHook 确保正常关闭时注销。

  5. 动态权重适合自适应场景：根据业务指标（如 CPU 负载、队列长度）动态调整权重，可以实现自适应负载均衡。
