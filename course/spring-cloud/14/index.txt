<h2 id="场景一服务消费者动态发现与客户端负载均衡">场景一：服务消费者动态发现与客户端负载均衡</h2>
<h3 id="场景描述">场景描述</h3>
<p>在图书管理系统中，book-order 作为服务消费者，需要动态发现 book-product 的实例列表，并根据实例的健康状态和权重进行客户端负载均衡调用。当 book-product 的实例数量发生变化（扩容、缩容、宕机）时，book-order 应能实时感知并调整路由策略。</p>
<h3 id="传统方式的局限">传统方式的局限</h3>
<p>前面我们通过 <code>DiscoveryClient</code> + <code>RestTemplate</code> 实现了手动服务发现。这种方式存在以下局限：</p>
<table>
<thead>
<tr>
<th>局限</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>无自动感知</strong></td>
<td>每次调用都需要手动获取实例列表，无法感知实例的实时变化</td>
</tr>
<tr>
<td><strong>无权重选择</strong></td>
<td><code>instances.get(0)</code> 始终取第一个实例，权重配置不生效</td>
</tr>
<tr>
<td><strong>代码侵入性强</strong></td>
<td>每次调用都需要手动构造 URL、处理异常</td>
</tr>
</tbody>
</table>

<h2 id="场景二服务提供者动态注册与元数据管理">场景二：服务提供者动态注册与元数据管理</h2>
<h3 id="场景描述_1">场景描述</h3>
<p>在图书管理系统中，book-product 作为服务提供者，需要在启动时自动注册到 Nacos，并上报元数据（版本、机房、环境等）。同时，book-product 需要根据自身负载情况动态调整权重，实现自适应负载均衡。</p>

<th>说明</th>

</tr>
<tr>
<td><strong>关闭注销</strong></td>
<td>服务关闭时自动注销，避免流量路由到已停止的实例</td>
</tr>

<td><strong>元数据上报</strong></td>

</tr>
<tr>

<h2 id="注意事项">注意事项</h2>
<ol>
<li>
<p><strong>一个 SDK 实例对应一个命名空间</strong>：<code>NamingService</code> 初始化时指定的 namespace 固定，如需访问多个命名空间，需创建多个 SDK 实例。</p>
</li>
<li>
<p><strong>服务订阅是长连接</strong>：<code>subscribe</code> 底层基于 gRPC 长连接，Nacos 会实时推送实例变更。确保 gRPC 端口（9848）可访问。</p>
</li>
<li>
<p><strong>加权选择需要 Nacos 感知</strong>：<code>selectOneHealthyInstance</code> 方法内置了加权随机逻辑，直接使用即可。</p>
</li>
<li>
<p><strong>注册与注销成对出现</strong>：服务启动时注册，关闭时注销。使用 <code>Runtime.getRuntime().addShutdownHook</code> 确保正常关闭时注销。</p>
</li>
<li>
<p><strong>动态权重适合自适应场景</strong>：根据业务指标（如 CPU 负载、队列长度）动态调整权重，可以实现自适应负载均衡。</p>
</li>
</ol>
<h2 id="小结">小结</h2>
<p>本讲将前面各讲散落的 Nacos API 调用集中整理，并聚焦于两个典型应用场景的 Java SDK 系统集成：</p>
<ol>
<li><strong>API 分类</strong>：Client Open API、Admin API、Console API、Inner API。</li>
<li><strong>场景一：服务消费者动态发现与负载均衡</strong>：使用 <code>NamingService</code> 的 <code>subscribe</code> 实现实例变更监听，<code>selectOneHealthyInstance</code> 实现加权随机选择。</li>
<li><strong>场景二：服务提供者动态注册与元数据管理</strong>：使用 <code>NamingService</code> 的 <code>registerInstance</code> 注册实例并上报元数据，<code>updateInstance</code> 动态调整权重，<code>deregisterInstance</code> 注销实例。</li>
<li><strong>Java SDK 核心 API</strong>：<code>NamingService</code> 的常用方法速查。</li>
</ol>
