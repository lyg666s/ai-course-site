<h2 id="回顾与导入">回顾与导入</h2>
<p>在上一节中，我们为<code>BookClient</code>配置了拦截器。但有一个问题一直没有被正面回答：<strong>当book-product有多个实例时，Feign的请求到底发给了哪一个？</strong></p>
<p>来看一个真实场景：</p>
<blockquote>
<p><strong>场景：</strong> book-product扩容到了两个实例（8081、8082），book-order通过<code>BookClient.getById()</code>调用。book-order的开发者以为“Feign会自动负载均衡”，但实际上，如果LoadBalancer没有正确参与，请求可能<strong>始终打到8081</strong>，8082完全闲置。扩容等于白扩。</p>
</blockquote>
<p>注意，Feign的底层组成：</p>
<table>
<thead>
<tr>
<th>组件</th>
<th>职责</th>
</tr>
</thead>
<tbody>
<tr>
<td>Feign Core</td>
<td>解析接口、生成动态代理、编码请求</td>
</tr>
<tr>
<td><strong>Spring Cloud LoadBalancer</strong></td>
<td><strong>根据服务名获取实例列表，并按策略挑一个</strong></td>
</tr>
<tr>
<td>Nacos Discovery</td>
<td>提供实例列表</td>
</tr>
</tbody>
</table>
<p><code>@FeignClient(name = "book-product")</code>中的<code>book-product</code>只是一个<strong>服务名</strong>，Feign自己并不知道8081和8082的存在。真正把服务名解析成具体实例地址的，是LoadBalancer。</p>
<p>本节的核心任务就是：<strong>让LoadBalancer的“挑实例”过程可见、可验证</strong>。</p>
<h2 id="核心原理Feign调用链中的LoadBalancer">核心原理：Feign调用链中的LoadBalancer</h2>
<h3 id="调用链全景">调用链全景</h3>
<p>一次<code>bookClient.getById(1L)</code>的完整调用链如下：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TD
    A[bookClient.getById] --&gt; B[Feign动态代理]
    B --&gt; C[编码为RequestTemplate]
    C --&gt; D{LoadBalancer&lt;br/&gt;选实例}
    D --&gt;|从Nacos获取实例列表| E[Nacos]
    E --&gt;|返回 8081, 8082| D
    D --&gt;|轮询/随机策略| F[选中 127.0.0.1:8081]
    F --&gt; G[HTTP客户端发出请求]
    G --&gt; H[book-product:8081]

    style D fill:#e8f5e9
    style F fill:#fff3e0
</code></pre></div>

<p>关键点：LoadBalancer在<strong>请求编码之后、HTTP客户端发出之前</strong>介入，将<code>http://book-product/api/products/1</code>中的<code>book-product</code>替换为具体的<code>127.0.0.1:8081</code>。</p>
<h3 id="默认负载均衡策略轮询">默认负载均衡策略：轮询</h3>
<p>Spring Cloud LoadBalancer官方提供了<code>ReactiveLoadBalancer</code>接口，并内置了<strong>轮询（Round-Robin）</strong> 和<strong>随机（Random）</strong> 两种实现。默认生效的是<strong>轮询策略（<code>RoundRobinLoadBalancer</code>）</strong> 。</p>
<p>轮询的行为是：按照固定顺序将请求依次分配给每个实例——1号、2号、3号、再回到1号。如果两个book-product实例的健康状态相同、权重相同（默认1.0），轮询会让请求在8081和8082之间交替。轮询算法：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="c1">// 伪代码，展示核心逻辑</span>
<span class="kd">private</span><span class="w"> </span><span class="n">Response</span><span class="o">&lt;</span><span class="n">ServiceInstance</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">getInstanceResponse</span><span class="p">(</span><span class="n">List</span><span class="o">&lt;</span><span class="n">ServiceInstance</span><span class="o">&gt;</span><span class="w"> </span><span class="n">instances</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">if</span><span class="w"> </span><span class="p">(</span><span class="n">instances</span><span class="p">.</span><span class="na">isEmpty</span><span class="p">())</span><span class="w"> </span><span class="p">{</span>
<span class="w">        </span><span class="c1">// 记录警告日志并返回空响应</span>
<span class="w">        </span><span class="k">return</span><span class="w"> </span><span class="k">new</span><span class="w"> </span><span class="n">EmptyResponse</span><span class="p">();</span>
<span class="w">    </span><span class="p">}</span>
<span class="w">    </span><span class="c1">// 对单实例列表进行优化，直接返回</span>

<span class="w">    </span><span class="p">}</span>

<span class="w">    </span><span class="kt">int</span><span class="w"> </span><span class="n">pos</span><span class="w"> </span><span class="o">=</span><span class="w"> </span><span class="k">this</span><span class="p">.</span><span class="na">position</span><span class="p">.</span><span class="na">incrementAndGet</span><span class="p">()</span><span class="w"> </span><span class="o">&amp;</span><span class="w"> </span><span class="n">Integer</span><span class="p">.</span><span class="na">MAX_VALUE</span><span class="p">;</span>

<p>普通轮询的取模算法非常直接：通过原子计数器记录当前请求的序列号，然后对实例节点总数取模，得到具体下标，再从列表取实例。</p>
<h2 id="实战实例可见和负载均衡">实战：实例可见和负载均衡</h2>
<p>现在启动两个book-product服务实例，端口分别为8081和8082.</p>
<h3 id="问题Feign默认日志不打印实例IP">问题：Feign默认日志不打印实例IP</h3>
<p>Feign的<code>BASIC</code>或<code>FULL</code>日志会打印<strong>服务名</strong>级别的URL（如<code>GET http://book-product/api/products/1</code>），但<strong>不会打印最终选中的实例IP和端口</strong>。当两个实例都可能被选中时，仅凭Feign日志无法判断请求到底打到了哪一台。</p>
<h3 id="解决方案自定义LoadBalancerLifecycle">解决方案：自定义LoadBalancerLifecycle</h3>
<p>Spring Cloud LoadBalancer提供了<code>LoadBalancerLifecycle</code>接口，允许在负载均衡的不同阶段插入回调：</p>
<table>
<thead>
<tr>
<th>回调方法</th>
<th>触发时机</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>onStart(Request&lt;RC&gt; request)</code></td>
<td>负载均衡开始前</td>
</tr>
<tr>
<td><code>onStartRequest(Request&lt;RC&gt; request, Response&lt;T&gt; lbResponse)</code></td>
<td>实例选择完成后</td>
</tr>
<tr>
<td><code>onComplete(CompletionContext&lt;RES, T, RC&gt; completionContext)</code></td>
<td>请求完成后</td>
</tr>
</tbody>
</table>
<p>在<code>onStartRequest</code>中，可以从<code>Response</code>中提取LoadBalancer选中的<code>ServiceInstance</code>，打印其IP和端口。</p>
<p><strong>在book-order中创建生命周期监听器：</strong></p>

<p>配置Feign日志（辅助观察），确保book-order的<code>application.yml</code>中Feign日志可用。</p>

<h3 id="如果两个实例的请求分布明显不均">如果两个实例的请求分布明显不均</h3>
<p>如果连续多次调用后，<code>[LB选中实例]</code>几乎总是同一个端口，检查以下原因：</p>

<h2 id="关键机制35秒实例缓存与Nacos场景的坑">关键机制：35秒实例缓存与Nacos场景的坑</h2>
<h3 id="默认缓存行为">默认缓存行为</h3>
<p>Spring Cloud LoadBalancer为了避免每次Feign调用都向注册中心拉取实例列表，内置了一层<strong>本地缓存</strong>。默认缓存TTL为<strong>35秒</strong>，默认初始容量为256。在这35秒内，LoadBalancer<strong>优先使用缓存中的实例列表</strong>，即使Nacos中实例已经发生了变化。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant Feign as Feign调用
    participant LB as LoadBalancer
    participant Cache as 本地缓存
    participant Nacos as Nacos

    Feign-&gt;&gt;LB: 选择book-product实例
    LB-&gt;&gt;Cache: 查缓存
    alt 缓存命中（35秒内）
        Cache--&gt;&gt;LB: 返回旧列表
    else 缓存过期
        LB-&gt;&gt;Nacos: 拉取最新列表
        Nacos--&gt;&gt;LB: 返回最新列表
        LB-&gt;&gt;Cache: 写入缓存
    end
    LB--&gt;&gt;Feign: 返回选中的实例
</code></pre></div>

<h3 id="Nacos场景下缓存带来的问题">Nacos场景下缓存带来的问题</h3>
<p>Nacos 2.x之后使用gRPC长连接<strong>实时推送</strong>实例变更，Nacos Client内存中已经维护了最新的实例列表。但LoadBalancer的这层缓存会<strong>屏蔽掉Nacos的实时推送</strong>：</p>
<table>
<thead>
<tr>
<th>场景</th>
<th>缓存开启时的表现</th>
<th>缓存关闭时的表现</th>
</tr>
</thead>
<tbody>
<tr>
<td>新实例启动</td>
<td>最长35秒内，流量不会路由到新实例</td>
<td>立即可见</td>
</tr>
<tr>
<td>实例优雅下线</td>
<td>最长35秒内，流量仍可能路由到已下线实例</td>
<td>立即停止路由</td>
</tr>
<tr>
<td>实例宕机</td>
<td>取决于Nacos心跳超时 + LoadBalancer缓存，感知延迟叠加</td>
<td>仅受Nacos心跳超时影响</td>
</tr>
</tbody>
</table>
<p><strong>推荐配置（Nacos场景）：</strong></p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">loadbalancer</span><span class="p">:</span>
<span class="w">      </span><span class="nt">cache</span><span class="p">:</span>
<span class="w">        </span><span class="nt">enabled</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">false</span>
</code></pre></div>

<p>关闭LoadBalancer缓存后，每次负载均衡直接读取Nacos Client内存中的实时实例列表，<strong>不会增加注册中心的网络压力</strong>，因为<code>getInstances</code>是纯内存操作。</p>
<p>如果生产环境 QPS 非常高、服务数量很多，也可以先评估性能影响；折中做法是把 TTL 缩短，例如：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">loadbalancer</span><span class="p">:</span>
<span class="w">      </span><span class="nt">cache</span><span class="p">:</span>
<span class="w">        </span><span class="nt">enabled</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">true</span>
<span class="w">        </span><span class="nt">ttl</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">5s</span>
</code></pre></div>

<blockquote>
<p><strong>注意：</strong> <code>cache.ttl</code>仅在<code>cache.enabled=true</code>时生效。</p>
</blockquote>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>Feign与LoadBalancer的协作关系</strong>：Feign负责编码和发送请求，LoadBalancer负责从服务名解析出具体实例。</li>
<li><strong>默认轮询策略</strong>：在健康状态和权重相同时，请求在两个实例间交替分布。Nacos权重、自定义策略等内容将在后续课程中展开。</li>
<li><strong><code>LoadBalancerLifecycle</code>监听器</strong>：通过<code>onStartRequest</code>回调打印最终选中的实例IP和端口，弥补Feign日志的不足。</li>
<li><strong>35秒实例缓存</strong>：LoadBalancer默认缓存实例列表35秒，会屏蔽Nacos的实时变更推送；Nacos场景推荐配置<code>cache.enabled: false</code>。</li>
<li><strong>多实例验证</strong>：启动两个book-product实例，观察<code>[LB选中实例]</code>输出是否交替出现，确认负载均衡生效。</li>
</ol>
