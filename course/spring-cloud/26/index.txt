<ul>

<h2 id="回顾与导入">回顾与导入</h2>
<p>到目前为止我们完成了配置中心的集成、分级与共享。配置已经从本地搬到了 Nacos，支持多环境隔离和动态刷新。但配置变更的风险一直没有被正面处理：</p>
<blockquote>
<p><strong>场景：</strong> book-product 有 2 个实例在运行。运维人员要开启一个新功能开关 <code>new-search-enabled: true</code>。直接全量发布，2 个实例几乎同时刷新。如果新逻辑有 bug，所有用户同时受影响。</p>
<p>更安全的做法：<strong>先让 1 个实例接收新配置</strong>，观察无异常后再全量。这就是配置灰度发布。</p>
</blockquote>
<p>配置灰度发布与前面介绍的代码灰度发布解决同一类问题——控制变更影响范围，但作用对象不同：</p>

</tr>

<td>变更对象</td>
<td>代码版本</td>
<td>配置内容</td>
</tr>
<tr>
<td>路由依据</td>
<td>请求 Header</td>

<h2 id="实验环境与-Actuator-准备">实验环境与 Actuator 准备</h2>
<p>本节验证配置是否生效时，会频繁使用 Spring Boot Actuator 的 <code>/actuator/env</code> 端点。该端点<strong>默认不会通过 HTTP 暴露</strong>，因此必须先完成以下准备。</p>
<h3 id="1-确认已集成-Nacos-Config">1. 确认已集成 Nacos Config</h3>
<p>本节默认项目已经完成 Nacos 配置中心集成。只有 Nacos Config 集成正确，后续才能在 Actuator 中看到配置属性的来源。</p>
<h3 id="2-添加-Actuator-依赖">2. 添加 Actuator 依赖</h3>
<p>在 <code>book-product</code> 的 <code>pom.xml</code> 中添加：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>org.springframework.boot<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-boot-starter-actuator<span class="nt">&lt;/artifactId&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<h3 id="3-暴露-Actuator-端点">3. 暴露 Actuator 端点</h3>
<p>在 <code>application.yml</code> 或 <code>bootstrap.yml</code> 中添加：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">management</span><span class="p">:</span>
<span class="w">  </span><span class="nt">endpoints</span><span class="p">:</span>
<span class="w">    </span><span class="nt">web</span><span class="p">:</span>
<span class="w">      </span><span class="nt">exposure</span><span class="p">:</span>
<span class="w">        </span><span class="nt">include</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">env,refresh,health</span>
</code></pre></div>

<h3 id="4-验证-Actuator-是否可用">4. 验证 Actuator 是否可用</h3>
<p>启动 book-product 后，先访问健康检查端点：</p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">GET http://127.0.0.1:8081/actuator/health</span>
</code></pre></div>

<p>预期响应类似：</p>
<div class="codehilite lang-json"><pre><span></span><code><span class="p">{</span>
<span class="w">  </span><span class="nt">"status"</span><span class="p">:</span><span class="w"> </span><span class="s2">"UP"</span>
<span class="p">}</span>
</code></pre></div>

<p>再访问配置端点：</p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">GET http://127.0.0.1:8081/actuator/env</span>
</code></pre></div>

<p>预期返回 JSON，并能看到 <code>propertySources</code>。</p>
<h3 id="5-单属性查询格式说明">5. 单属性查询格式说明</h3>
<p>查询单个配置项时，使用：</p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">GET http://127.0.0.1:8081/actuator/env/book.product.new-search-enabled</span>
</code></pre></div>

<p>该路径中的 <code>book.product.new-search-enabled</code> 是属性名。</p>
<h2 id="配置灰度发布的核心概念">配置灰度发布的核心概念</h2>
<p>配置灰度发布是指在发布配置变更时，<strong>先让一部分实例接收新配置</strong>，观察运行状态，确认无异常后再扩大到全部实例的发布方式。</p>

<h3 id="灰度配置的存储模型">灰度配置的存储模型</h3>
<p>灰度期间，同一个 DataId 存在多个版本：</p>
<table>
<thead>
<tr>
<th>版本</th>
<th>哪些实例读取</th>
</tr>
</thead>
<tbody>
<tr>
<td>正式配置</td>
<td>非灰度实例</td>
</tr>
<tr>
<td>Beta 配置</td>

<p><strong>关键：</strong> 灰度期间<strong>正式配置没有被修改</strong>。Beta 配置和标签配置是“叠加层”，只在匹配的实例上生效。撤销灰度时，只需删除叠加层，正式配置原样保留——这是灰度发布“可回滚”的基础。</p>
</blockquote>
<h2 id="Beta-发布实战">Beta 发布实战</h2>
<p>Beta 发布是最常用、最直观的灰度方式：直接指定要灰度的实例 IP。</p>
<h3 id="前提确认实例-IP">前提：确认实例 IP</h3>
<p>在 Nacos 控制台的 dev 命名空间，进入“服务管理”→“服务列表”→点击 <code>book-product</code>，确认实例的 IP 和端口。</p>
<blockquote>
<p><strong>本机模拟的注意点：</strong> 同一台机器上启动两个实例，IP 都是 <code>127.0.0.1</code>，Beta 发布按 IP 匹配无法区分端口，会同时命中两个实例。要演示“只灰度一个实例”，需用 Docker 分配不同 IP，或<strong>在实验时只启动一个实例做 Beta 验证</strong>。</p>
</blockquote>
<h3 id="创建-Beta-发布">创建 Beta 发布</h3>
<p><strong>步骤一：进入配置详情</strong></p>
<p>Nacos 控制台 → dev 命名空间 → “配置管理” → “配置列表” → 找到 <code>book-product.yml</code>，点击进入详情。</p>
<p><strong>步骤二：修改配置内容</strong></p>
<p>将用于验证的配置项改为新值：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">book</span><span class="p">:</span>
<span class="w">  </span><span class="nt">product</span><span class="p">:</span>
<span class="w">    </span><span class="nt">page-size</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">10</span>
<span class="w">    </span><span class="nt">cache-enabled</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">true</span>
<span class="w">    </span><span class="nt">new-search-enabled</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">true</span><span class="w">      </span><span class="c1"># 新增，灰度值</span>
</code></pre></div>

<p><strong>步骤三：勾选“Beta 发布”</strong></p>
<p>在编辑页面底部勾选“Beta 发布”（不是直接点击“发布”）。</p>
<p><strong>步骤四：指定灰度 IP</strong></p>
<p>在弹出的输入框中填写要灰度的实例 IP（如 <code>127.0.0.1</code>），点击“发布 Beta”。</p>
<p><strong>步骤五：观察状态</strong></p>
<p>发布成功后，配置列表中 <code>book-product.yml</code> 显示“Beta 发布中”，并标注灰度 IP。</p>
<blockquote>
<p><strong>重要：</strong> Beta 发布不会修改正式配置。新启动的实例（非 Beta IP）读到的仍是旧配置。</p>
</blockquote>
<h3 id="验证-Beta-发布生效">验证 Beta 发布生效</h3>
<p><strong>在灰度实例上验证：</strong></p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">GET http://127.0.0.1:8081/api/config/properties</span>
</code></pre></div>

<p><strong>预期：</strong> <code>newSearchEnabled: true</code>。</p>
<p><strong>用 Actuator 确认配置来源：</strong></p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">GET http://127.0.0.1:8081/actuator/env/book.product.new-search-enabled</span>
</code></pre></div>

<p><strong>预期响应：</strong></p>
<div class="codehilite lang-json"><pre><span></span><code><span class="p">{</span>
<span class="w">  </span><span class="nt">"property"</span><span class="p">:</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="nt">"source"</span><span class="p">:</span><span class="w"> </span><span class="s2">"DEFAULT_GROUP@book-product.yml"</span><span class="p">,</span>
<span class="w">    </span><span class="nt">"value"</span><span class="p">:</span><span class="w"> </span><span class="s2">"******"</span>
<span class="w">  </span><span class="p">}</span>
<span class="p">}</span>
</code></pre></div>

<blockquote>
<p><strong>说明：</strong> 灰度实例的配置来源仍是 <code>book-product.yml</code>，但值是 Beta 版本的内容。Nacos 推送时，Beta 配置覆盖正式配置推送给匹配的客户端。</p>
</blockquote>
<h3 id="全量发布或撤销">全量发布或撤销</h3>
<table>
<thead>
<tr>
<th>目标</th>
<th>操作</th>
</tr>
</thead>
<tbody>
<tr>
<td>灰度验证通过，正式采用新配置</td>
<td>点击“发布”，用 Beta 内容覆盖正式配置</td>
</tr>
<tr>
<td>灰度验证失败，回滚</td>
<td>点击“撤销 Beta”，灰度实例回到正式配置</td>

<blockquote>
<p><strong>回滚速度：</strong> 撤销 Beta 后，Nacos 通过 gRPC 推送正式配置，生效通常在秒级。这是配置灰度相对于代码回滚的最大优势——<strong>不需要重新部署</strong>。</p>
</blockquote>
<h2 id="标签发布原理拓展">标签发布原理（拓展）</h2>
<p>Beta 发布按 IP 精确指定，适合“小范围验证”。当需要按<strong>逻辑分组</strong>灰度时（如“机房 A 的实例先灰度”），使用标签发布。</p>
<blockquote>
<p><strong>⚠️ 版本限制提示：</strong> 在 开源Nacos 3.0.3 版本中，无法直接通过控制台操作标签。因此，本节内容主要为了解其设计理念，为日后升级版本或使用商业版（如阿里云 MSE）打下基础。</p>
</blockquote>
<h3 id="标签发布的原理">标签发布的原理</h3>
<p>标签发布基于 Nacos 客户端向配置中心发起请求时携带的<strong>专属标签（Labels）</strong>。</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>flowchart TD
    A[客户端启动时携带标签&lt;br/&gt;nacos.app.conn.labels=gray:true] --&gt; B[Nacos 匹配标签规则&lt;br/&gt;gray=true]
    B --&gt; C[Nacos 只推送标签配置&lt;br/&gt;给匹配标签的客户端]
    C --&gt; D[其他未携带标签的实例&lt;br/&gt;继续用正式配置]
</code></pre></div>

<h3 id="客户端打标签方式">客户端打标签方式</h3>
<p>如果未来升级了 Nacos 服务端，在 book-product 启动时，可以通过 JVM 参数注入配置中心标签（<strong>请注意，这不是注册中心的 metadata</strong>）：</p>
<div class="codehilite lang-bash"><pre><span></span><code>-Dnacos.app.conn.labels<span class="o">=</span><span class="s2">"gray=true"</span>
</code></pre></div>

<p><em>(如果是 IDEA 启动，请在 VM options 中填入上述参数)</em></p>
<p>启动后，该实例在请求 Nacos 配置中心时，就会带上 <code>gray=true</code> 的标签。服务端通过 API 接收到标签匹配规则后，即可实现精准的配置下发。</p>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>配置灰度发布的价值</strong>：把配置变更的风险从全量降到局部，避免“一处配置错误、全部实例异常”。</li>
<li><strong>Nacos 的两种灰度方式</strong>：Beta 发布（控制台按 IP 精确指定）和标签发布（按客户端连接标签匹配）。</li>
<li><strong>Beta 发布流程</strong>：修改配置 → 勾选 Beta 发布 → 指定灰度 IP → 验证 → 全量发布或撤销。</li>
<li><strong>版本限制认知</strong>：在开源 Nacos 中，Beta 发布是首选。标签发布需要 Nacos 的企业版支持。</li>
<li><strong>核心概念辨析</strong>：配置灰度标签（<code>nacos.app.conn.labels</code>）≠ 服务发现元数据（<code>discovery.metadata</code>）。</li>
<li><strong>灰度配置的存储模型</strong>：正式配置不变，Beta/标签配置是叠加层；撤销即删除叠加层，正式配置原样保留。</li>
<li><strong>回滚演练的重要性</strong>：灰度发布的价值在于“能快速回滚”，必须实际验证撤销操作。</li>
</ol>
