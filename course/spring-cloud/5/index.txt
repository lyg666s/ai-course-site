<h2 id="回顾与导入">回顾与导入</h2>
<p>在前三节中，我们完成了工程初始化和三个服务的 CRUD 实现。此时三个服务的 Controller 直接返回 VO 对象或 List、原生对象：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="nd">@PostMapping</span>
<span class="kd">public</span><span class="w"> </span><span class="n">ProductVO</span><span class="w"> </span><span class="nf">create</span><span class="p">(</span><span class="nd">@Valid</span><span class="w"> </span><span class="nd">@RequestBody</span><span class="w"> </span><span class="n">ProductCreateRequest</span><span class="w"> </span><span class="n">request</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">productService</span><span class="p">.</span><span class="na">create</span><span class="p">(</span><span class="n">request</span><span class="p">);</span>

<span class="nd">@GetMapping</span>
<span class="kd">public</span><span class="w"> </span><span class="n">List</span><span class="o">&lt;</span><span class="n">ProductVO</span><span class="o">&gt;</span><span class="w"> </span><span class="nf">list</span><span class="p">()</span><span class="w"> </span><span class="p">{</span>
<span class="w">    </span><span class="k">return</span><span class="w"> </span><span class="n">productService</span><span class="p">.</span><span class="na">listAll</span><span class="p">();</span>

<p>这种返回方式存在以下问题：</p>
<table>
<thead>
<tr>
<th>问题</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>响应格式不统一</strong></td>
<td>有的返回实体、有的返回 List、有的返回 Boolean</td>
</tr>
<tr>
<td><strong>缺少状态码</strong></td>
<td>前端无法区分业务成功与失败</td>
</tr>
<tr>
<td><strong>缺少错误信息</strong></td>
<td>异常时直接抛出 500，前端无法获取具体原因</td>
</tr>
<tr>
<td><strong>无法携带元数据</strong></td>
<td>无法返回分页信息、时间戳等</td>
</tr>
<tr>
<td><strong>代码重复</strong></td>
<td>每个 Controller 都要处理异常</td>
</tr>
</tbody>
</table>

<h2 id="公共模块的结构设计">公共模块的结构设计</h2>
<h3 id="book-common-的包结构">book-common 的包结构</h3>
<div class="codehilite"><pre><span></span><code>book-common/
└── src/main/java/com/example/common/
    ├── model/
    │   ├── Result.java            # 统一响应体
    │   └── PageResult.java        # 分页响应体
    ├── exception/
    │   ├── BusinessException.java        # 业务异常
    │   ├── ResourceNotFoundException.java # 资源不存在异常
    │   └── ParamException.java            # 参数异常
    ├── enums/
    │   └── ResultCode.java        # 状态码枚举
    └── handler/
        └── GlobalExceptionHandler.java # 全局异常处理器
</code></pre></div>

<blockquote>
<p><strong>设计原则：</strong> 公共模块只包含<strong>与业务无关</strong>的通用组件（统一响应、异常体系、工具类）。任何与具体业务相关的实体（如 Book、Order）都不能放入 book-common。</p>
</blockquote>
<h2 id="状态码枚举设计">状态码枚举设计</h2>
<h3 id="什么是状态码">什么是状态码</h3>
<p><strong>业务状态码</strong>是接口返回的用于表示业务处理结果的数字编码，不同于 HTTP 状态码。它让前端能够精确判断业务处理的具体情况。</p>
<table>
<thead>
<tr>
<th>对比</th>
<th>HTTP 状态码</th>
<th>业务状态码</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>负责范围</strong></td>
<td>HTTP 协议层面</td>
<td>业务层面</td>
</tr>
<tr>
<td><strong>示例</strong></td>
<td>200、404、500</td>
<td>200、1001、1004</td>
</tr>
<tr>
<td><strong>作用对象</strong></td>
<td>客户端和中间件</td>
<td>前端业务逻辑</td>
</tr>
</tbody>
</table>
<h3 id="设计原则">设计原则</h3>
<table>
<thead>
<tr>
<th>原则</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>分层分类</strong></td>
<td>按功能模块或错误类型分类，便于扩展</td>
</tr>
<tr>
<td><strong>语义清晰</strong></td>
<td>状态码本身能反映错误类型</td>
</tr>
<tr>
<td><strong>规范统一</strong></td>
<td>全系统使用同一套状态码规范</td>
</tr>
<tr>
<td><strong>可扩展</strong></td>
<td>预留状态码段供后续业务扩展</td>
</tr>
</tbody>
</table>

<h2 id="全局异常处理器">全局异常处理器</h2>
<p>如果不在 Controller 中显式捕获异常，异常会直接抛给 Spring 的默认处理机制，返回 500 错误页面或简单的错误 JSON，无法满足统一响应的要求。全局异常处理器可以集中捕获所有异常，转换为统一的 <code>Result</code> 格式。</p>

<h2 id="注意事项">注意事项</h2>
<ol>
<li><strong><code>scanBasePackages</code> 配置</strong>：<code>GlobalExceptionHandler</code> 位于 <code>book-common</code> 中，各服务主启动类必须添加 <code>@SpringBootApplication(scanBasePackages = "com.example")</code>，否则异常处理器不会被加载。</li>
<li><strong><code>@JsonInclude</code> 的作用</strong>：<code>Result</code> 类上的 <code>@JsonInclude(JsonInclude.Include.NON_NULL)</code> 确保 <code>data</code> 为 null 时不返回该字段。</li>
<li><strong>HTTP 状态码与业务状态码的映射</strong>：<code>@ResponseStatus</code> 指定 HTTP 状态码，<code>Result.code</code> 指定业务状态码，两者独立但协同工作。</li>
<li><strong>异常日志记录</strong>：<code>GlobalExceptionHandler</code> 中使用 <code>log.warn</code> 记录业务异常，<code>log.error</code> 记录系统异常，便于后续排查。</li>
<li><strong>公共模块的边界</strong>：<code>book-common</code> 中不能包含任何具体业务的实体（如 Product、Order），只能包含通用的响应封装和异常体系。</li>
<li><strong>向后兼容</strong>：改造 Controller 时，所有返回类型从 <code>ProductVO</code> / <code>List&lt;ProductVO&gt;</code> 改为 <code>Result&lt;ProductVO&gt;</code> / <code>Result&lt;List&lt;ProductVO&gt;&gt;</code>，需同步通知前端调整解析逻辑。</li>
</ol>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>公共模块的定位</strong>：<code>book-common</code> 存放与业务无关的通用组件，被三个服务共用。</li>
<li><strong>状态码枚举 ResultCode</strong>：定义分层分类的业务状态码。</li>
<li><strong>统一响应体 Result<T></strong>：包含 <code>code</code>、<code>message</code>、<code>data</code>、<code>timestamp</code> 四个字段，提供 <code>success</code> 和 <code>error</code> 静态方法。</li>
<li><strong>分页响应体 PageResult<T></strong>：从 MyBatis-Plus 的 <code>IPage</code> 一键转换，只保留分页必需字段。</li>
<li><strong>异常体系</strong>：<code>BusinessException</code>、<code>ResourceNotFoundException</code>、<code>ParamException</code> 三个层级。</li>
<li><strong>全局异常处理器 GlobalExceptionHandler</strong>：使用 <code>@RestControllerAdvice</code> 统一捕获异常，返回统一的 <code>Result</code> 格式。</li>
<li><strong>服务集成</strong>：在主启动类上添加 <code>scanBasePackages</code>，确保能扫描到 <code>book-common</code> 中的组件。</li>
</ol>
