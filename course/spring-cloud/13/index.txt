<h2 id="回顾与导入">回顾与导入</h2>
<p>到目前为止，我们通过Namespace实现了dev/test两套环境的隔离，三个服务都成功注册到了各自的命名空间。但此时同一服务下的多个实例，接收到的流量是<strong>完全均等</strong>的——因为默认的负载均衡策略会等概率地从健康实例列表中选择一个实例。</p>
<p>这在很多实际场景中并不合理。来看几个真实的需求：</p>
<table>
<thead>
<tr>
<th>场景</th>
<th>需求</th>
<th>传统方案的痛点</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>主备部署</strong></td>
<td>主服务器性能强，备服务器性能弱，希望主服务器承担更多流量</td>
<td>均等分配导致备服务器过载或主服务器资源浪费</td>

<tr>

<h2 id="权重路由核心原理">权重路由核心原理</h2>
<h3 id="权重的工作机制">权重的工作机制</h3>
<p>Nacos的权重路由功能基于服务实例的元数据实现。每个服务实例都可以配置一个权重值（weight），Nacos会根据权重值计算每个实例的流量分配比例。</p>
<p>权重的核心机制如下：</p>
<table>
<thead>
<tr>
<th>特性</th>
<th>说明</th>
</tr>
</thead>
<tbody>
<tr>
<td><strong>相对值</strong></td>
<td>权重是相对值，不是百分比。权重为3和1的两个实例，分别接收75%和25%的流量</td>
</tr>
<tr>
<td><strong>客户端执行</strong></td>
<td>Nacos服务端只负责存储和推送权重值，<strong>不强制执行流量分配</strong>。实际的路由决策由客户端（框架自动实现，或本课程中由我们手写实现）完成</td>
</tr>
<tr>
<td><strong>动态生效</strong></td>
<td>权重修改后无需重启服务，权重值会伴随实例信息被推送到Nacos客户端</td>
</tr>
</tbody>
</table>
<h3 id="流量分配的计算公式">流量分配的计算公式</h3>
<p>假设有N个健康实例，每个实例的权重为<code>w_i</code>，则实例<code>i</code>被选中的概率为：</p>
<div class="codehilite"><pre><span></span><code>P(实例i) = w_i / (w_1 + w_2 + ... + w_N)
</code></pre></div>

<p><strong>示例：</strong></p>
<table>
<thead>
<tr>
<th>实例</th>
<th>权重</th>
<th>流量占比</th>
</tr>
</thead>
<tbody>
<tr>
<td>实例A</td>
<td>9</td>
<td>9/(9+1) = 90%</td>
</tr>
<tr>
<td>实例B</td>
<td>1</td>
<td>1/(9+1) = 10%</td>
</tr>
</tbody>
</table>
<blockquote>
<p><strong>重要提示：</strong> Nacos的权重路由是<strong>概率性</strong>的，不是严格计数。请求次数少时比例波动较大，请求样本越大，实际比例越接近理论比例。</p>
</blockquote>

<h2 id="手动实现加权随机选择">手动实现加权随机选择</h2>
<h3 id="为什么需要自己写">为什么需要自己写</h3>
<p><code>DiscoveryClient.getInstances("book-product")</code>返回的是一份<strong>原始实例列表</strong>，每个实例都带着<code>weight</code>属性，但<strong>列表本身不按权重排序</strong>，也不提供"按权重挑选"的方法。所以我们必须自己实现选择逻辑。</p>
<p>好消息是：Nacos客户端内部的加权随机算法本身并不复杂，核心就是"按权重累加，命中随机数"——理解并实现一遍，就真正理解权重路由了。</p>
<h3 id="编写-WeightedInstanceSelector">编写 <code>WeightedInstanceSelector</code></h3>
<p>在book-order中新建一个工具类：</p>
<div class="codehilite lang-java"><pre><span></span><code><span class="kd">public</span><span class="w"> </span><span class="kd">class</span> <span class="nc">WeightedInstanceSelector</span><span class="w"> </span><span class="p">{</span>

<span class="w">    </span><span class="kd">public</span><span class="w"> </span><span class="kd">static</span><span class="w"> </span><span class="n">ServiceInstance</span><span class="w"> </span><span class="nf">choose</span><span class="p">(</span><span class="n">List</span><span class="o">&lt;</span><span class="n">ServiceInstance</span><span class="o">&gt;</span><span class="w"> </span><span class="n">instances</span><span class="p">)</span><span class="w"> </span><span class="p">{</span>

<h2 id="验证权重路由效果">验证权重路由效果</h2>
<h3 id="基线权重-10-10观察均等分配">基线：权重 1.0 : 1.0，观察均等分配</h3>
<p><strong>先确认</strong>：此时Nacos控制台两个book-product实例的权重都是默认的<code>1.0</code>。</p>
<p><strong>操作</strong>：连续调用50次接口：</p>
<div class="codehilite lang-http"><pre><span></span><code><span class="err">### 连续调用50次，每次返回被选中实例的端口</span>
<span class="err">GET {{order_url}}/api/discovery/book/instance-port</span>
</code></pre></div>

<p><strong>预期现象</strong>：返回的端口字符串中，<code>8081</code>和<code>8082</code>大致各占一半（各25次左右）。由于是概率性路由，20次中偶尔出现30:20或20:30都正常，但<strong>不会出现一边倒</strong>。</p>
<p>如果此时出现"全是8081"或"全是8082"，说明加权逻辑没有正确生效，请检查：</p>
<ul>
<li><code>WeightedInstanceSelector.choose</code>是否被调用（而不是<code>get(0)</code>）；</li>
<li>Nacos客户端是否已经拉到最新的实例列表（权重/实例变更后默认约10秒内生效，可稍等或重启book-order）。</li>
</ul>
<h3 id="统计方式">统计方式</h3>
<h4 id="方式一通过-book-order-日志统计">方式一：通过 book-order 日志统计</h4>
<p>book-order的<code>DiscoveryController</code>每次选择实例后都会打印：</p>
<div class="codehilite"><pre><span></span><code>选中图书服务实例：127.0.0.1:8081 (weight=1.0)
选中图书服务实例：127.0.0.1:8082 (weight=0.1)
</code></pre></div>

<p>直接在日志中统计<code>8081</code>与<code>8082</code>出现的行数，即可得到实际流量分布。</p>
<h4 id="方式二通过-book-product-端日志统计">方式二：通过 book-product 端日志统计</h4>
<p>book-product的<code>ProductController</code>中也有：</p>
<div class="codehilite"><pre><span></span><code>book-product 实例 8081 被调用（instance-port）
</code></pre></div>

<p>同样能在两个book-product实例的日志里分别统计被调用次数，双重验证。</p>
<blockquote>
<p><strong>注意</strong>：由于权重路由是概率性的，请求样本越大，实际比例越接近理论比例。建议至少调用<strong>50次</strong>再下结论。</p>
</blockquote>

<h3 id="配置主备权重">配置主备权重</h3>
<p>在Nacos控制台中，将两个实例的权重设置为9和1。</p>
<blockquote>
<p><strong>为什么备实例不设为0？</strong> 备实例保持10%的流量有以下几个好处：
1. <strong>热备验证</strong>：备实例持续处理少量请求，确保其代码和配置始终可用
2. <strong>快速切换</strong>：当主实例故障时，备实例已处于运行状态，可立即承接全部流量
3. <strong>性能监控</strong>：备实例的监控指标持续更新，便于对比分析</p>
</blockquote>
<p><strong>验证</strong>：等待约10秒后连续调用50次<code>/api/discovery/book/instance-port</code>，预期8081约45次、8082约5次。</p>

<h2 id="注意事项">注意事项</h2>
<ol>
<li>
<p><strong>权重路由是概率性的</strong>：调用次数少时比例波动大，建议至少观察50次以上的调用结果。</p>
</li>
<li>
<p><strong>备实例建议保持非零权重</strong>：备实例保持少量流量（如10%）可以验证其可用性，并在主实例故障时快速承接全部流量。</p>
</li>
<li>
<p><strong>权重为0即"下线流量"</strong>：<code>WeightedInstanceSelector</code>会过滤掉权重为0的实例，效果等同于"保留实例但不下发流量"。</p>
</li>
<li>
<p><strong>客户端缓存延迟</strong>：Nacos客户端默认每10秒拉取一次实例列表，权重修改后最多10秒才生效。修改权重后建议先等待再验证。</p>
</li>
</ol>

<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li>
<p><strong>权重路由的核心原理</strong>：Nacos根据权重值计算流量分配比例，服务端只负责存储和推送权重，客户端（手动或框架）负责执行路由决策。</p>
</li>
<li>
<p><strong>控制台操作</strong>：在Nacos服务详情页中编辑实例权重，权重为浮点数，常见范围 <code>0 ~ 10000</code>。</p>
</li>
<li>
<p><strong>手动加权随机实现</strong>：核心是<code>P(i) = w_i / Σw</code>，配合过滤权重为0实例、累加比较的算法，代码与公式一一对应。</p>
</li>
<li>
<p><strong>主备实例配置</strong>：主实例权重9、备实例权重1，实现90%/10%的流量倾斜，备实例保持热备状态。</p>
</li>
<li>
<p><strong>权重为0的特殊用法</strong>：临时摘除实例、模拟故障、对比测试等场景。</p>
</li>
<li>
<p><strong>流量验证方法</strong>：通过book-order日志或book-product日志统计各实例被调用次数。</p>
</li>
</ol>
