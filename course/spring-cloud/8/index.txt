<h2 id="服务注册与发现机制回顾">服务注册与发现机制回顾</h2>
<p>在动手配置之前，先理解Nacos客户端的工作机制。</p>
<h3 id="注册流程">注册流程</h3>
<p>当Spring Boot应用启动时，如果引入了Nacos Discovery依赖并配置了Nacos服务器地址，Nacos客户端会自动完成以下动作：</p>
<div class="codehilite lang-mermaid"><pre><span></span><code>sequenceDiagram
    participant App as book-product应用
    participant NacosClient as Nacos客户端
    participant NacosServer as Nacos服务器

    App-&gt;&gt;NacosClient: 启动完成，触发注册事件
    NacosClient-&gt;&gt;NacosServer: 发送注册请求（服务名、IP、端口、元数据）
    NacosServer--&gt;&gt;NacosClient: 返回注册成功
    NacosClient-&gt;&gt;NacosServer: 启动心跳（每5秒一次）
    NacosServer--&gt;&gt;NacosClient: 心跳续约确认

    Note over NacosClient,NacosServer: 服务持续运行期间，心跳保持
    Note over App: 应用关闭时，Nacos客户端自动发送注销请求
</code></pre></div>

<h3 id="自动装配原理">自动装配原理</h3>
<p>Spring Cloud Alibaba Nacos Discovery通过Spring Boot的自动装配机制实现“零代码”注册。核心类是<code>NacosServiceRegistry</code>和<code>NacosDiscoveryAutoConfiguration</code>，它们在应用启动时自动注册<code>AutoServiceRegistration</code>，监听Web服务器的启动事件，随后向Nacos发起注册。</p>
<p>这意味着：<strong>不需要手写任何注册代码</strong>，只需引入依赖、添加配置，服务就会自动注册到Nacos。</p>
<h3 id="服务名的作用">服务名的作用</h3>
<p><code>spring.application.name</code>是服务在注册中心的唯一标识。当一个服务有多个实例时（如启动两个book-product实例），它们注册在同一个服务名下，Nacos会将它们作为同一个服务的不同实例进行管理。消费者通过服务名（而非IP:端口）来调用服务，由负载均衡器选择一个实例。</p>

<h3 id="关于server-addr的集群配置">关于server-addr的集群配置</h3>
<p>当配置了多个Nacos节点地址后，Nacos客户端的寻址机制如下：</p>
<ol>
<li><strong>随机选择</strong>：客户端从地址列表中随机选择一个节点建立连接</li>
<li><strong>故障转移</strong>：如果当前节点不可用，客户端以轮询方式依次尝试其他地址</li>
<li><strong>持续重试</strong>：尝试完所有地址后，回到第一个地址继续轮询，直到找到可用节点或客户端停止</li>
</ol>
<p>这意味着即使集群中某个节点宕机，客户端也能自动切换到其他健康节点，注册功能不受影响。</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="c1"># 单机模式</span>
<span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>

<span class="c1"># 集群模式</span>
<span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848,127.0.0.1:8858,127.0.0.1:8868</span>
</code></pre></div>

<h3 id="是否需要EnableDiscoveryClient">是否需要@EnableDiscoveryClient</h3>
<p>在我们使用的Spring Cloud Alibaba版本中，<strong><code>@EnableDiscoveryClient</code>注解已不再必需</strong>。只要满足以下两个条件，服务就会自动注册：</p>
<ol>
<li>引入了<code>spring-cloud-starter-alibaba-nacos-discovery</code>依赖</li>
<li>配置了<code>spring.cloud.nacos.discovery.server-addr</code></li>
</ol>
<p>Nacos Discovery的自动装配机制会检测到这些条件，并自动完成注册。</p>
<p>不过，为了代码的<strong>显式性和可读性</strong>，建议在启动类上保留<code>@EnableDiscoveryClient</code>注解，明确表明该服务启用了服务发现功能。这不是强制要求，但有助于团队协作时快速理解服务定位。</p>

<h2 id="常见问题排查">常见问题排查</h2>
<h3 id="服务未出现在Nacos控制台">服务未出现在Nacos控制台</h3>
<p>这是最常见的问题。按以下顺序逐步排查：</p>
<p><strong>第一步：检查Nacos是否正常运行</strong></p>
<p>访问Nacos控制台，确认节点状态均为UP。如果Nacos服务器本身不可用，服务自然无法注册。</p>
<p><strong>第二步：检查网络连通性</strong></p>
<div class="codehilite lang-bash"><pre><span></span><code><span class="c1"># 测试能否访问Nacos节点</span>
telnet<span class="w"> </span><span class="m">127</span>.0.0.1<span class="w"> </span><span class="m">8848</span>
</code></pre></div>

<p>如果telnet不通，说明网络或防火墙存在问题。Nacos 3.x需要开放的端口包括：8848（HTTP）、9848（gRPC）、8080（控制台）。</p>
<p><strong>第三步：检查配置是否正确</strong></p>
<p>确认<code>application.yml</code>中的配置项：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
</code></pre></div>

<ul>
<li>确认<code>server-addr</code>的IP和端口与Nacos实际监听一致</li>
<li>确认<code>spring.application.name</code>已配置（这是服务名）</li>
<li>确认<code>namespace</code>填的是命名空间ID而非名称</li>
</ul>
<p><strong>第四步：查看应用启动日志</strong></p>
<p>在应用日志中搜索<code>REGISTER-SERVICE</code>关键字，确认注册请求是否已发出。如果日志中没有该关键字，说明注册请求根本没有发出，可能是依赖缺失或配置未生效。</p>
<p><strong>第五步：查看Nacos服务端日志</strong></p>
<p>查看Nacos的日志文件，确认包含注册请求信息中的服务名称："book-product"。</p>

<h3 id="版本冲突导致NoSuchMethodError">版本冲突导致NoSuchMethodError</h3>
<p>如果启动时出现<code>NoSuchMethodError</code>或<code>ClassNotFoundException</code>，通常是BOM未生效或版本冲突：</p>
<div class="codehilite lang-bash"><pre><span></span><code><span class="c1"># 查看实际生效的nacos-client版本</span>
mvn<span class="w"> </span>dependency:tree<span class="w"> </span>-pl<span class="w"> </span>book-product<span class="w"> </span><span class="p">|</span><span class="w"> </span>grep<span class="w"> </span>nacos
</code></pre></div>

<p>确认<code>nacos-client</code>版本为3.0.3，与Nacos Server版本一致。如果版本不一致，检查父POM中的BOM配置。</p>
<h2 id="小结">小结</h2>
<p>本节课我们学习了：</p>
<ol>
<li><strong>服务注册与发现机制</strong>：Nacos客户端在应用启动时自动向Nacos注册服务，并通过心跳维持注册状态。</li>
<li><strong>依赖确认</strong>：<code>spring-cloud-starter-alibaba-nacos-discovery</code>依赖版本由BOM统一管理。</li>
<li><strong>application.yml配置</strong>：核心配置项包括<code>server-addr</code>、<code>namespace</code>、<code>group</code>、<code>metadata</code>等。</li>
<li><strong>集群地址配置</strong>：多个Nacos节点用逗号分隔，客户端自动实现故障转移。</li>
<li><strong>启动类配置</strong>：<code>@EnableDiscoveryClient</code>为可选注解，但建议保留以提升可读性。</li>
<li><strong>验证注册成功</strong>：通过控制台、API、日志三种方式验证服务已注册。</li>
<li><strong>多实例注册</strong>：相同服务名的多个实例会注册在同一个服务下，为负载均衡做准备。</li>
<li><strong>常见问题排查</strong>：服务未出现、实例不健康、连接超时、版本冲突等问题的排查方法。</li>
</ol>
