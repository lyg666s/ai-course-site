<h2 id="进阶配置抽取与共享">进阶：配置抽取与共享</h2>
<h3 id="问题分析">问题分析</h3>
<p>三个服务的Nacos配置完全相同，分散在三个文件中。如果Nacos集群地址发生变化（如从3节点扩展到5节点），需要修改三个文件。虽然目前只有三个服务，但如果未来服务数量增加，维护成本会显著上升。</p>
<h3 id="方案一使用springconfigimport导入共享配置">方案一：使用spring.config.import导入共享配置</h3>
<p>Spring Boot 2.4+支持通过<code>spring.config.import</code>导入外部配置文件。我们可以在项目根目录创建一个共享的<code>nacos-shared.yml</code>：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="c1"># 项目根目录/nacos-shared.yml</span>
<span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">server-addr</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">127.0.0.1:8848</span>
<span class="w">        </span><span class="nt">namespace</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">public</span>
<span class="w">        </span><span class="nt">group</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEFAULT_GROUP</span>
</code></pre></div>

<p>然后在每个服务的<code>application.yml</code>中导入：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">config</span><span class="p">:</span>
<span class="w">    </span><span class="nt">import</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">optional:file:../nacos-shared.yml</span>
<span class="w">  </span><span class="nt">application</span><span class="p">:</span>
<span class="w">    </span><span class="nt">name</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">book-product</span>
</code></pre></div>

<blockquote>
<p><strong>注意：</strong> <code>optional:</code>前缀表示文件不存在时不报错。路径<code>../nacos-shared.yml</code>是相对于服务目录的路径，实际使用时需要根据项目结构调整。</p>
</blockquote>
<h3 id="方案二使用Nacos配置中心推荐后续课程">方案二：使用Nacos配置中心（推荐，后续课程）</h3>
<p>后续内容将引入Nacos Config配置中心，届时所有服务的配置都可以集中管理到Nacos，支持动态刷新和灰度发布。这是最优雅的方案，也是生产环境的标准做法。</p>
<blockquote>
<p><strong>本节建议：</strong> 现阶段保持方式一（分别配置）即可，重点是理解服务注册的机制。配置共享的优雅方案将在配置中心课程中讲解。</p>
</blockquote>
<h2 id="进阶注册开关元数据与权重">进阶：注册开关、元数据与权重</h2>
<h3 id="register-enabled开关">register-enabled开关</h3>
<p>如果某个服务是纯消费者（只调用其他服务，不会被其他服务调用，如book-order服务），可以关闭注册：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">register-enabled</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">false</span>
</code></pre></div>

<p>关闭后，服务仍然可以从Nacos发现其他服务，但自身不会出现在服务列表中。</p>
<h3 id="元数据的使用">元数据的使用</h3>
<p>元数据（metadata）是附加在服务实例上的键值对，可用于灰度发布、版本路由等场景：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">metadata</span><span class="p">:</span>
<span class="w">          </span><span class="nt">version</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">1.0.0</span>
<span class="w">          </span><span class="nt">env</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">dev</span>
<span class="w">          </span><span class="nt">region</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">beijing</span>
</code></pre></div>

<p>注册后，在Nacos控制台的实例详情中可以看到这些元数据。后续课程中将利用元数据实现基于请求Header的灰度流量路由。</p>
<h3 id="权重配置">权重配置</h3>
<p>实例权重影响负载均衡时的流量分配。默认权重为1.0，权重越高的实例被选中的概率越大：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">spring</span><span class="p">:</span>
<span class="w">  </span><span class="nt">cloud</span><span class="p">:</span>
<span class="w">    </span><span class="nt">nacos</span><span class="p">:</span>
<span class="w">      </span><span class="nt">discovery</span><span class="p">:</span>
<span class="w">        </span><span class="nt">weight</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">2.0</span><span class="w">  </span><span class="c1"># 该实例权重为2，是默认实例的2倍</span>
</code></pre></div>

<p>权重也可以在Nacos控制台中动态修改（“服务详情” → 实例列表 → 编辑权重），无需重启应用。后续内容将详细讲解权重的使用。</p>
<h2 id="服务注册后的运维操作">服务注册后的运维操作</h2>
<h3 id="手动下线实例">手动下线实例</h3>
<p>在Nacos控制台中，进入服务详情页，可以手动将实例<strong>下线</strong>。下线后的实例不会参与服务发现，但进程仍在运行。</p>
<p><strong>操作步骤：</strong></p>
<ol>
<li>进入<code>book-product</code>服务详情页</li>
<li>找到目标实例，点击“下线”</li>
<li>实例状态变为“已下线”</li>
<li>其他服务无法发现该实例</li>
</ol>
<p><strong>适用场景：</strong> 灰度发布前将旧版本实例下线、临时摘除问题实例。</p>
<h3 id="手动上线实例">手动上线实例</h3>
<p>将已下线的实例重新<strong>上线</strong>，恢复其参与服务发现的能力。</p>
<h3 id="编辑实例权重">编辑实例权重</h3>
<p>在服务详情页点击“编辑”，可以修改实例权重。权重越高，被负载均衡选中的概率越大。</p>
<table>
<thead>
<tr>
<th>权重</th>
<th>流量分配</th>
</tr>
</thead>
<tbody>
<tr>
<td>1.0</td>
<td>默认权重</td>
</tr>
<tr>
<td>2.0</td>
<td>约两倍流量</td>
</tr>
<tr>
<td>0.0</td>
<td>不接收流量（等价于下线）</td>
</tr>
</tbody>
</table>
<blockquote>
<p><strong>注意：</strong> 权重调整仅对<strong>临时实例</strong>有效。持久化实例的权重调整需要通过API或控制台的特殊操作。</p>
</blockquote>
<h3 id="实例元数据查看">实例元数据查看</h3>
<p>在服务详情页可以看到实例的元数据（metadata），如<code>version=1.0.0</code>、<code>region=local</code>。这些元数据可用于灰度路由、监控分组等场景。</p>
<h3 id="配置debug日志">配置debug日志</h3>
<p>配置 debug 日志方式：</p>
<div class="codehilite lang-yaml"><pre><span></span><code><span class="nt">logging</span><span class="p">:</span>
<span class="w">  </span><span class="nt">level</span><span class="p">:</span>
<span class="w">    </span><span class="nt">com.alibaba.cloud.nacos</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEBUG</span>
<span class="w">    </span><span class="nt">com.alibaba.nacos</span><span class="p">:</span><span class="w"> </span><span class="l l-Scalar l-Scalar-Plain">DEBUG</span>
</code></pre></div>

<p>注意：需要同时更新 <code>spring-cloud-starter-alibaba-nacos-discovery</code>的依赖：</p>
<div class="codehilite lang-xml"><pre><span></span><code><span class="nt">&lt;dependency&gt;</span>
<span class="w">    </span><span class="nt">&lt;groupId&gt;</span>com.alibaba.cloud<span class="nt">&lt;/groupId&gt;</span>
<span class="w">    </span><span class="nt">&lt;artifactId&gt;</span>spring-cloud-starter-alibaba-nacos-discovery<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">    </span><span class="nt">&lt;exclusions&gt;</span>
<span class="w">        </span><span class="nt">&lt;exclusion&gt;</span>
<span class="w">            </span><span class="nt">&lt;groupId&gt;</span>com.alibaba.nacos<span class="nt">&lt;/groupId&gt;</span>
<span class="w">            </span><span class="nt">&lt;artifactId&gt;</span>logback-adapter<span class="nt">&lt;/artifactId&gt;</span>
<span class="w">        </span><span class="nt">&lt;/exclusion&gt;</span>
<span class="w">    </span><span class="nt">&lt;/exclusions&gt;</span>
<span class="nt">&lt;/dependency&gt;</span>
</code></pre></div>

<p>为什么要这样配置？简单来说，<code>logback-adapter</code> 是旧版 Nacos 为了在 Spring Boot 3.x 下“抢回”日志控制权而引入的一个<strong>过渡性补丁</strong>。但在 Spring Boot 3.5 和 Nacos 3.x 的新组合下，这个补丁本身会引发初始化错误，并且与 Nacos 内部新的日志管理机制相冲突。因此，通过 <code>&lt;exclusions&gt;</code> 将其移除，是为了<strong>让日志系统的控制权平滑地交还给 Spring Boot</strong>，同时<strong>让 Nacos 3.x 使用它自带的、更稳定的日志集成机制</strong>。这是恢复日志正常输出（包括你需要的 DEBUG 级别）的必要步骤。</p>
